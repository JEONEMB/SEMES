# SEMES 전달 폴더 명세 (초안, 2026-11-14)

SEMES 에 보낼 독립 폴더(`2026-10_SEMES/semes`)의 내용과 근거를 정리한다.

- 숫자는 모두 SEMES 사진 702장, 정지 사진 평가다. 우리 장비 사진은 따로 표시했다.
- 통과 기준: |eY| ≤ 0.045 mm 그리고 |eT| ≤ 0.01°
- **아직 없는 것**은 표에 "없음"으로 표시하고 맨 끝 [빠진 것](#빠진-것)에 모았다.

---

## 1. 알고리즘 소개

사진 한 장(3840×2160)에서 **기준 사진(센터 사진) 대비 가로 이동량** 몇 개를 재고, 선형식으로 Y(mm)·T(°)를 낸다.

| 단계 | 하는 일 |
|---|---|
| 1. QR 이동 | QR 3개가 기준 사진에서 가로로 몇 px 움직였는지 잰다. 기본은 흐림 NCC(σ2), 선택은 536점 추적. 3개 평균 = **QR 값** |
| 2. 나사 이동 | 나사 4개마다 핀 NCC 로 대략 위치를 찾고, 기울기 영상 ECC 로 소수 px 가로 이동을 잰다 = **나사 값 4개** |
| 3. 바 기울기 (선택) | 위·아래 바의 세로 위치를 48칸에서 재서 기울기를 낸다 = **바 값 2개**. 기본은 쓰지 않는다 |
| 4. Y·T 계산 | 값들을 정규화해 미리 학습한 계수로 더한다(Huber 강건 선형식) |
| 5. 영점 | 출력 = 계산값 − 영점. 기본은 절대 영점(기준 사진과 같은 화면 = 0, 0) |
| 6. 일치 점검 | 값들이 Y·T 두 개로 함께 설명되는지 보고, 아니면 경고한다 |

왜 이렇게 읽히나:

- QR 과 나사는 높이가 달라서, Y 이동에서 둘이 다르게 움직인다(시차, SEMES 1 mm 에 약 3.1 px 차이).
- T 회전은 화면 전체를 가로로 민다(1° 에 약 80 px).
- **세로 이동은 쓰지 않는다.** 세로 값은 날마다 화면이 밀리며 바뀌어서, 처음 보는 날 성적이 64% 로 떨어졌다. 빼니 98.8% 가 됐다.

## 2. 정확도 (기본 구성: 흐림 NCC + 나사 4 + 바 없음)

| 시험 | 결과 |
|---|---|
| 주 검증 (560장, 80/20 × 10회) | 탈락 평균 0.2장, rms Y 0.0133 mm, T 0.0029° |
| 보조 50/50 (10회) | 탈락 평균 0.5장 |
| 처음 보는 회차 (회차 하나를 빼고 학습) | 98.2% (1·2·3차 99 ~ 100%, 4차 93.0%) |
| 마지막 확인 (142장, 한 번만 봄) | 탈락 0 |
| 학습 범위 밖 (안쪽만 학습 → 바깥쪽 299장) | Y 탈락 0 (비례 오차 0.3%), T 14장 탈락 (가장자리에서 1 ~ 1.5% 크게 읽음) |

탈락한 사진은 모두 학습 범위 가장자리(|T| ≈ 0.96, |Y| ≥ 1.2)였고, 기준을 조금 넘었다(T 0.0001 ~ 0.0017, Y 0.3 ~ 2 µm).

## 4. 오류

**값을 못 낼 때는 예외를 던진다.** (0, 0) 으로 숨기지 않는다.

| 메시지 | 뜻 |
|---|---|
| `QR n NCC 가 낮다` | QR 이 가려졌거나 반사됐거나 많이 흐림 |
| `QR n 이 탐색 창 끝에 걸렸다` | QR 이 탐색 창(가로 ±250 px, 세로 ±22 px) 밖으로 움직임 |
| `QR 고정 536점 중 유효하지 않은 점이 있다` | (536점 방식) 밝기·흐림·가림 |
| `Pin NCC below 0.6` / `Pin refinement did not converge` | 나사를 못 찾음(가림, 반사, 이물) |
| `나사 기울기 영상 맞춤에 실패했다` | 나사 소수 이동 계산 실패 |
| `Line normal-profile match failed` | (바 사용 시) 바를 못 찾음, 주로 화면 세로 밀림 |

값은 내지만 의심스러울 때는 **경고**를 남긴다.

- 표시: `alignment_diagnostics()` 의 `normalized_cost_margin > 1`, `message` 가 `WARNING 측정값이 서로 맞지 않는다(…)`
- 기본은 경고만 남긴다. 설정으로 멈추게 할 수 있다.

## 6. [측정] QR

| 방식 | 하는 일 | 정확도 (주 검증 / 처음 보는 회차) | 속도 (노트북, SEMES, 4스레드) | 안정성 |
|---|---|---|---|---|
| **흐림 NCC (기본)** | QR 3개를 통째로 σ2 흐린 뒤 NCC, 정수 봉우리 + 3점 포물선 | 0.2 / 98.2% | 약 15 ms | 밝기 변화에 강함. 흐림 σ2 이상에서 일부 틀림 |
| 536점 추적 | QR 안 536점을 하나씩 따라가 평균 | 0.0 / 98.2% | 약 45 ms, 초기화 약 1 초 | 가장 정밀. 밝기 변화·흐림 σ2 에서 멈춤(틀리지는 않음) |

- QR 상자(SEMES 센터 사진 기준): (1552, 969, 184×198), (1809, 971, 184×198), (2067, 973, 185×198). QR 사이 간격은 약 257 px 다.
- 흐림을 넣은 이유:
  - 선명한 SEMES 사진에서는 3점 포물선이 소수 위치에 따라 ±0.03 px 치우쳤다.
  - σ2 로 흐리니 0.003 px 가 됐다(주 검증 탈락 2.6 → 0.2).

추천:

| 환경 | 고를 것 |
|---|---|
| 기본, 속도가 중요, 조명이 바뀔 수 있음 | 흐림 NCC |
| 조명·초점이 늘 같고 가장 정밀해야 함, 속도 여유 있음 | 536점 |
| 영상이 많이 흐리거나 노이즈가 큼 | 536점 (틀리지 않고 멈춤) |
| 바·나사가 없거나 가려짐 | QR 방식으로는 해결 안 됨. 나사 조합을 바꾼다(9장) |

## 7. [측정] 영점

| 방식 | 하는 일 | 언제 |
|---|---|---|
| **절대 영점 (기본)** | QR·나사가 기준 사진과 같은 상태가 (0, 0). 숫자로 정해져 있다 | 아무 설정도 안 하면 |
| 영점 업데이트 | 그날 센터 사진(여러 장 평균)의 지금 출력을 영점으로 삼아 뺀다. 돌려주는 값 = 그날 센터의 절대 자세 | 날마다, 카메라·조명·판을 건드린 뒤 |
| 영점 값 넣기 / 지우기 / 읽기 | 저장해 둔 영점 값을 다시 넣거나 절대 영점으로 되돌린다 | 재시작 뒤 복원 |
| 측정 기준 다시 잡기 | 센터 사진으로 QR 상자·나사 중심·바 칸을 다시 찾는다. 절대 영점은 이어진다 | 화면이 크게 밀려 측정이 실패할 때 |

| 변화 | 영점 업데이트 전 | 영점 업데이트 뒤 |
|---|---|---|
| 카메라 0.05° 회전 | Y 0.27 mm 틀림 | 탈락 0 |
| 화면 가로 2 px 밀림 | T 0.025° 틀림 | 탈락 0 |

## 8. [측정] 바

| 선택 | 정확도 (주 검증 / 처음 보는 회차 / 범위 밖 탈락) | 비고 |
|---|---|---|
| **안 씀 (기본)** | 0.2 / 98.2% / 14 | 화면 세로 밀림에 강함 |
| 위 바 기울기 | 0.2 / 98.4% / 15 | |
| 아래 바 기울기 | 0.2 / 98.2% / 13 | |
| 둘 다 | 0.2 / 98.4% / 14 | |
| 바 위치(세로) | 쓰지 않음 | 세로 값이 날마다 바뀌어 처음 보는 날 64% |

**찾는 방법**:

- 기준 사진의 바 칸 48개에서 세로 단면을 맞춰 위치를 잰다(세로 약 ±11 px 안).
- 화면이 밀려 바가 이 범위를 벗어나면 측정 기준 다시 잡기로 바 칸을 다시 찾는다(기준 위치 ± 20 px).

**바가 없거나 학습 때와 많이 다를 때**:

- 바를 안 쓰는 기본 구성이면 영향이 없다.
- 바를 쓰는 구성에서 바를 못 찾으면 예외(`Line normal-profile match failed`)가 난다. 이때는 바 없는 구성으로 바꾸거나 측정 기준을 다시 잡는다.

**쓸 때와 안 쓸 때**:

| | 바 씀 | 바 안 씀 |
|---|---|---|
| 정확도 | 같음 (차이 1장 수준) | 같음 |
| 속도 | 바 48칸 측정 시간이 더 든다 (따로 재지 않음) | 빠름 |
| 화면 세로 10 px 밀림 | 702장 중 404장 멈춤 | 20 px 까지 그대로 (21 px 부터 QR 을 못 찾음) |
| 장비 사진, 카메라 처짐(세로 14 px) | 1698장 전부 실패 | 42/42 측정 |

**분석 방법과 선택**: 바 위·아래, 위치·기울기, 측정 영역과 방식을 비교했다(실험 A19, A21, 20261112 바 측정 대조, 20261113_1830, 20261114_0330). 기울기만 남기고 위치는 뺐다. 기울기도 정확도 이득이 없어 기본에서 뺐다.

## 9. [측정] 나사

| 선택 | 정확도 (주 검증 / 처음 보는 회차 / 범위 밖 탈락) | 쓸 수 있나 |
|---|---|---|
| **4개 (기본)** | 0.2 / 98.2% / 14 | 예 |
| 3개 (1 또는 2 빼기) | 0.2 / 97.5 ~ 98.4% / 14 | 예 |
| 3개 (3 또는 4 빼기) | 1.1 ~ 2.0 / 97.3 ~ 98.4% / 16 | 예 (조금 나쁨) |
| 2개 아래 (3, 4) / 대각 (1, 4), (2, 3) | 0.0 ~ 0.6 / 97.0 ~ 98.6% / 14 ~ 16 | 예 |
| 2개 위 (1, 2) | 2.8 / 98.2% / 22 | 가능하나 나쁨 |
| 2개 한쪽 (왼쪽 1, 3 / 오른쪽 2, 4) | 128 ~ 136 / 52 ~ 57% | **아니오** |
| 1개 | 145 ~ 170 / 45 ~ 56% | **아니오** |
| 0개 (QR 만, 또는 QR + 바) | 78 ~ 181 | **아니오** |

나사 번호: 1 왼쪽 위 (974, 1352), 2 오른쪽 위 (2864, 1358), 3 왼쪽 아래 (1010, 1677), 4 오른쪽 아래 (2817, 1681).

**규칙**: 나사가 **왼쪽에 하나, 오른쪽에 하나 이상** 있어야 한다. Y 와 T 를 가르려면 좌우 나사가 다 필요하다.

**찾는 방법**:

1. QR 이동으로 대략 위치를 짐작한다.
2. 그 주변 ±60 px 에서 핀 NCC 로 찾는다. 못 찾으면 ±260 px 에서 다시 찾는다.
3. 기울기 영상(흐림 1.5, Sobel 크기) ECC 로 반지름 45 px 안을 맞춰 소수 px 가로 이동을 낸다.
4. 나사 위치가 바뀌면 측정 기준 다시 잡기로 나사 중심을 다시 찾는다.

**나사가 없거나 학습 때와 많이 다를 때**:

| 상황 | 어떻게 되나 | 대처 |
|---|---|---|
| 나사를 못 찾음 | `Pin NCC below 0.6` 등 예외. SEMES 사진에서는 가림·반사가 대부분 여기서 걸린다 | 그 나사를 뺀 조합으로 초기화 |
| 찾았는데 엉뚱한 곳에 맞춤 (장비 사진 가림·반사) | 일치 점검이 경고 (Y 0.1 mm 넘게 틀린 것은 모두) | 경고가 계속되면 그 나사를 뺀 조합 |
| 나사 전체가 QR 대비 같이 밀림 (판 재조립) | 사진으로는 알 수 없음 (0.1 px ≈ Y 28 µm) | 판을 손대면 영점 다시 잡기 (운영 규칙) |

**나사 기울기**: 지금은 나사의 가로 이동만 잰다. 기울기는 재지 않는다([빠진 것](#빠진-것)).

**분석 방법과 선택**:

| 방법 | 주 검증 탈락 | 판단 |
|---|---:|---|
| 핀 NCC + 기울기 영상 ECC (지금) | 0.1 | 선택 |
| 위상 상관 (밝기) | 12.2 | |
| 위상 상관 (기울기) | 28.8 | |
| 위상 상관, 초기값 없이 | 8.8 ~ 28.5 | |

그 밖에 나사 관측 Y·T 동시 추정 후보(20261104 나사관측 실험), 나사 측정 방식 대조를 비교했다.

## 10. [안정성] Y 또는 T 가 크게 이동할 때

성현 님 평가 범위는 Y −6 ~ +7 mm, T −1.6 ~ +2° 다. 우리 학습 범위는 Y ±2 mm, T ±1° 다.

| 항목 | 결과 | 근거 |
|---|---|---|
| 측정이 되나 | 탐색 창 ±110 이면 평가 자세 35개 중 10개 멈춤. **±250 이면 모두 측정**(최대 약 184 px) | 실험 20261114_0230 (사진을 옮긴 합성 시험) |
| 엉뚱한 QR 을 잡나 | ±250 에서도 0장 | 같은 시험 |
| 시간 | 창 ±250 이 약 8% 더 걸림 | 같은 시험 |
| 범위 밖 정확도 | Y 비례 오차 0.3%(성현 님 약 2%). T 는 가장자리에서 1 ~ 1.5% 크게 | 실험 20261114_0130 (안쪽 학습 → 바깥쪽 예측) |
| 조합 차이 | QR 방식·바 사용과 무관하게 거의 같음 | 같은 시험, 실험 20261114_0330 |
| 큰 회전에서 QR 놓칠 위험 | T 1° 까지 상관 0.98 이상, 늘려 보면 2° 에서도 0.99 (추정) | 실험 20261114_0130 |

정렬은 반복해서 센터로 가므로, 먼 자세의 작은 비례 오차는 센터 근처에서 다시 재며 줄어든다.

## 11. [안정성] 다른 환경

### 예전에 새 데이터마다 정확도가 떨어진 이유와 지금

| 원인 | 예전 | 지금 | 근거 |
|---|---|---|---|
| 날마다 명령 0 의 자리가 다름 | 정답이 날마다 달라짐 | 절대 영점으로 해결 | 회차마다 0점이 Y 0.04 ~ 0.10 mm 달랐음 |

| 자료 | 결과 |
|---|---|
| SEMES (회차 빼기) | 1·2·3차 99 ~ 100%, 4차 93% (4차는 나사 위치가 다른 회차와 0.1 ~ 0.3 px 다름) |

### 앞으로 달라질 수 있는 것과 반응 (교란 시험 결과 반영)

| 바뀌는 것 | 반응 | 대처 |
|---|---|---|
| 화면 세로 밀림 (카메라 처짐) | 20 px 까지 영향 없음, 넘으면 QR 을 못 찾음 | 측정 기준 다시 잡기 |
| 화면 가로 밀림, 카메라 회전 | T·Y 가 일정하게 치우침 | 영점 업데이트로 없어짐 |

- 정답이 영상 값·스테이지 명령에서 나와 독립된 정답이 아니다.
- 실제 정렬 복귀는 아직 시험하지 않았다.

## 12. [오류해결]

| 증상 | 원인 | 해결 |
|---|---|---|
| 초기화 때 `자료 해시가 다르다` | assets 파일이 바뀜(줄바꿈 변환 등) | 받은 파일 그대로 복사. 텍스트 변환 금지 |
| `QR … 탐색 창 끝에 걸렸다` | 이동이 너무 큼, 화면이 크게 밀림 | 이동을 줄이거나 측정 기준 다시 잡기 |
| `QR n NCC 가 낮다` | QR 가림·반사·초점 | 가림 제거, 조명 확인 |
| 나사 관련 예외 | 나사 가림·반사·이물 | 원인 제거, 안 되면 그 나사 뺀 조합 |
| 경고(`WARNING 측정값이 서로 맞지 않는다`)가 가끔 | 나사 하나가 이상함 | 원인 확인. 값은 쓸 수 있으나 의심 |
| 경고가 모든 사진에서 남 | 화면이 학습 때와 달라짐(카메라 처짐·배율) | 영점 업데이트, 그래도 나면 측정 기준 다시 잡기 |
| 결과가 날마다 일정하게 어긋남 | 카메라·조명 변화 | 날마다 영점 업데이트 |
| 판 재조립 뒤 Y 가 일정하게 어긋남 | 판–나사 상대 위치 변화 | 영점 다시 잡기(필수) |
| 느림 | 536점 방식, 바 사용, 1스레드 | 흐림 NCC, 바 안 씀, OpenCV 스레드 켜기 |
