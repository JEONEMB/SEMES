# [11] 검증 단계 조사방법론

작성 2026-11-04. 브랜치 `feature/hye/pipeline-v2`. 지침은 [문헌연구/AGENTS.md](../../../문헌연구/AGENTS.md), [ALGORITHM_RULES.md](../../../../../ALGORITHM_RULES.md)를 따른다.

## 1. 목적

최종 위치가 진짜 맞는지 확인한다.

캔버스 노드 `s11`의 목적을 그대로 쓴다. 지금 성적은 모두 파일명 명령값을 정답으로 쓴 것이다. 명령한 자리에 멈춰 찍은 정지 사진뿐이고, 실제 작업 후 도착 사진은 없다. 341/575장은 이미 개발에 노출됐다. 그래서 이 단계는 다음을 문헌으로 정한다.

- 명령값과 다른 기준으로 위치를 재는 방법
- 반복성, 재현성, 다른 개체로의 전이를 나눠 재는 시험 설계
- 기준기 자체의 불확도를 넣은 통과 판정
- 개발에 쓴 자료의 성적을 독립 성능으로 부풀리지 않는 평가 절차

### 근거 수치

- 허용오차: |eY| ≤ 0.045, |eT| ≤ 0.045. Y 0.045는 영상에서 약 0.65px이다(Y 1mm 약 14.36px).
- 독립 기준기 요구 정밀도: 허용오차의 1/3인 0.015 이하(ALGORITHM_RULES 2026-11-02).
- 점 측정 잡음 0.009~0.015px. 536점의 유효 독립 정보는 약 19개다.
- 영점 변동: 하루 안 가로 최대 0.84px(백래시 β −0.34px, 드리프트), 날짜 간 세로 +0.44px(카메라 이동).
- 날짜 묶음: 1014, 1020, 1029. 다른 로봇 자료는 없다.

## 2. 해결할 질문

캔버스의 질문 1~3을 유지하고 4~7을 보강했다.

1. 명령값이 아닌 다른 기준으로 최종 위치를 확인할 수 있는가? 그 기준기는 얼마나 정밀해야 하는가(0.015 이하, 허용오차의 1/3)?
2. 같은 결과가 반복되는가? 같은 자리, 같은 접근 방향으로 여러 번 오면 추정값과 실제 위치가 얼마나 흩어지는가? 접근 방향이 다르면 얼마나 커지는가?
3. 다른 날에도 되는가? 날짜, 세션, 카메라 재장착에 따른 재현성을 반복성과 나눠 잴 수 있는가?
4. 다른 로봇, 다른 설치 위치(QR 내용이 다름)에서도 되는가? 개체 간 전이를 어떤 분할과 지표로 보여야 하는가?
5. 기준기의 불확도와 추정 불확도를 합쳐서, 한 번의 측정으로 "0.045 안"이라고 판정하려면 판정 기준을 어떻게 잡아야 하는가(보호대, 오판 위험)?
6. 개발에 이미 노출된 자료로 낸 성적의 선택 편향을 어떻게 막고, 새 자료는 어떻게 한 번만 써야 하는가? 자료 누출을 어떤 항목으로 점검하는가?
7. 시험 설계: 반복 횟수, 날짜 수, 자세 수, 20턴 순차 복귀 시험 횟수를 시험 전에 어떻게 정하고, 어떤 변동원을 분리하도록 짜는가?

## 3. 검색어

블록 안은 OR, 블록 사이는 AND로 묶는다.

| 블록 | 검색어 |
|---|---|
| A 기준 측정 | independent reference, ground truth, laser tracker, interferometer, substrate-like sensor, wafer-like sensor, teaching sensor, verification wafer |
| B 반복성과 재현성 | repeatability, reproducibility, gauge R&R, measurement system analysis, MSA, ISO 9283, pose repeatability |
| C 불확도와 판정 | measurement uncertainty, GUM, conformity assessment, decision rule, guard band, risk of false acceptance |
| D 전이 검증 | external validation, internal-external validation, transportability, leave-one-site-out, blocked cross-validation, domain shift |
| E 선택 편향 | selection bias, model selection, nested cross-validation, data leakage, holdout reuse, adaptive data analysis |
| F 대상 | wafer, substrate, transfer robot, vision, camera, robot |

조합 예시

- (A) AND (F): 독립 기준으로 웨이퍼 로봇 위치를 재는 장치
- (B) AND (C): 측정 시스템 능력과 판정 규칙
- (C) AND 판정: 적합성 판정 보호대
- (D) OR (E): 다른 장소 검증, 누출, 홀드아웃 재사용

## 4. 검색 기록

검색 경로 상태

- OpenAlex API: 2026-11-04 이 네트워크의 무료 일일 한도가 소진되어 "Rate limit exceeded"가 났다. API 키를 만들려면 사용자 이메일을 보내야 해서 쓰지 않았다. 대신 Crossref API로 서지를 찾았다.
- arXiv API(export.arxiv.org): HTTP 429. 대신 arXiv 초록 페이지(arxiv.org/abs/ID)로 서지와 PDF 주소를 확인했다.
- Google Patents: 검색과 특허 페이지 모두 자동 요청 차단(검색 "Sorry" 페이지, 특허 페이지 HTTP 503). 차단을 우회하지 않았다. 대신 USPTO Patent Public Search(ppubs.uspto.gov) 화면 검색을 썼고, 공보는 USPTO 공보 PDF로 받아 표지를 확인했다. Justia, FreePatentsOnline은 HTTP 403이라 쓰지 않았다.
- PPUBS는 AND를 여러 개 넣은 일부 검색에서 결과가 0건으로 돌아왔다(화면 내부 호출 오류로 보임). 0건은 "해당 문헌 없음"이 아니라 검색 실패일 수 있다.
- Crossref 건수는 관련도 정렬 전체 일치 수라서 매우 크다. 후보 판단에는 상위 8건만 봤다.
