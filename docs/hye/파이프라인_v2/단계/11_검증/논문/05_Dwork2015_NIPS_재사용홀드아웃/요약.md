# Dwork 외 2015, 적응적 자료 분석에서의 일반화와 홀드아웃 재사용 (NIPS 28)

- 원제: Generalization in Adaptive Data Analysis and Holdout Reuse
- 원문 파일: 같은 폴더의 `Dwork2015_NIPS_holdout_reuse.pdf` (arXiv:1506.02629v2, 29쪽)
- 번역: [번역.md](번역.md)
- 저자: Cynthia Dwork, Vitaly Feldman, Moritz Hardt, Toniann Pitassi, Omer Reingold, Aaron Roth
- 서지: Advances in Neural Information Processing Systems 28 (NIPS 2015). arXiv:1506.02629, 2015-09-28

## 핵심 (원문 확인)

1. **시험 집합을 여러 번 보고 고치면 시험 성적이 거짓이 된다.** 홀드아웃은 한 번만 쓰면 타당한 추정이다. 그러나 홀드아웃 결과를 보고 다음에 무엇을 할지 고르면(적응적 재사용), 모형이 홀드아웃과 독립이 아니게 되어 홀드아웃 자체에 과적합한다. 어떤 가설을 시험할지 미리 정해 두었다면 다중 검정 보정으로 해결되지만, 적응적으로 고르면 그 보정이 안 통한다.
2. **교차검증과 부트스트랩은 이 문제를 풀지 못한다.** 논문 5절의 명시적 결론이다. 같은 자료로 학습과 검증을 함께 하기 때문이다.
3. **Thresholdout.** 홀드아웃을 "문턱을 넘을 때만 말해 주는 창구"로 바꾼다. 질의 φ에 대해 |ESh[φ] − ESt[φ]|가 문턱 T + 잡음 아래면 훈련 집합 값 ESt[φ]만 돌려준다(홀드아웃에 대해 사실상 1비트만 흘린다). 문턱을 넘으면(즉 과적합 신호) 그때만 홀드아웃 값에 잡음을 더해 돌려주고 **과적합 예산 B를 1 깎는다.** B가 다 떨어지면 더 답하지 않는다.
4. **왜 되는가.** Thresholdout은 희소 벡터 알고리즘과 라플라스 기법의 조합이라 차분 프라이버시를 만족하고, 차분 프라이버시는 사후 처리와 적응적 합성에서 보존되므로 분석가가 무엇을 하든 일반화 보장이 유지된다.
5. **두 번째 알고리즘 SparseValidate.** 임의의 불리언 검증 질의를 허용하되, 1(검증 실패)을 돌려준 횟수를 B로 제한한다. 보장은 기술 길이(상호작용 기록이 짧다)에서 나온다. 단점은 과적합일 때 보정값을 주지 않는다는 것이다. 보정이 필요하면 추정 전용 자료를 따로 두는 쪽이 경제적이라고 저자들이 권한다.
6. **통합 개념 근사 최대정보량.** 차분 프라이버시 보장과 기술 길이 보장을 하나의 척도로 묶는다. 두 종류 알고리즘을 섞어 적응적으로 합성해도 일반화 보장이 더해진다.

## 우리와의 관계

- 관련도: ◎
- 답하는 질문: **6** (개발에 노출된 자료의 선택 편향을 어떻게 막고, 새 자료를 어떻게 한 번만 쓰는가), **7** (시험 설계를 시험 전에 어떻게 정하는가. 특히 재측정 횟수와 예산)
- 우리 상황과 바로 겹치는 점
  - 575장 중 341장이 이미 개발에 노출됐다. 남은 234장이 사실상의 홀드아웃인데, 이 234장을 보고 다시 고치면 논문이 말하는 그 과적합이 그대로 일어난다.
  - 지금까지의 개발은 전형적인 적응적 분석이다. 고정 536점 선택, 6절편 후보, P12, 48블록 같은 선택이 모두 성적을 보고 고른 것이다. 논문 5절의 모의실험 구조(상관으로 변수를 고르고 같은 자료에서 검증)와 같다.
  - 허용 ±0.045 통과율은 값이 0 또는 1인 질의다. Thresholdout이 다루는 φ: X → [0, 1]에 그대로 들어맞는다.
- 겹치지 않는 점
  - 논문의 보장은 i.i.d. 표본을 전제한다. 우리 사진은 날짜(1014, 1020, 1029)와 명령 격자로 묶여 있어 i.i.d.가 아니다. 그래서 이론 한계를 그대로 쓸 수 없다.
  - 논문의 홀드아웃은 n = 10,000이다. 우리는 234장이다. 아래 계산을 보라.

## 리뷰 카드

- **어떻게 해결했나**: 홀드아웃을 직접 읽지 못하게 막고, "훈련 값과 많이 다른가"라는 1비트 판정만 통과시키는 창구를 두었다. 다르다고 판정될 때만 잡음 섞인 홀드아웃 값을 주고 과적합 예산을 1 깎는다. 예산이 떨어지면 창구를 닫는다. 보장은 차분 프라이버시의 사후 처리 보존과 적응적 합성에서 나온다.
- **같은 점**: 우리도 같은 시험 자료를 보면서 방법을 계속 고쳐 왔다. 341장이 노출됐고, 남은 234장을 몇 번이고 다시 보면 그 234장의 통과율도 거짓이 된다. 논문이 "교차검증으로도 안 된다"고 못 박은 것은, 우리가 만든 날짜 묶음 교차검증이나 무작위 80/20 5겹으로도 이 편향이 안 풀린다는 뜻이다. 통과 여부라는 0/1 질의와 20턴 수렴 성공률도 모두 이 틀의 질의다.
- **다른 점**: 논문 보장은 i.i.d. 표본 10,000장을 전제한다. 우리 홀드아웃은 234장이고, 같은 날짜와 같은 명령 격자로 묶여 있어 독립 표본 수가 장수보다 훨씬 적다. 또 논문의 질의는 한 번 던지면 끝이지만, 우리 시험은 한 장이 아니라 20턴 복귀 한 벌이 한 번의 관측이다. 그래서 홀드아웃의 유효 크기는 장수가 아니라 복귀 시험 벌 수로 세야 한다.
- **가져올 해결책**: (1) 234장을 두 몫으로 쪼갠다. 개발 중에는 **문턱 창구**만 열어 둔다. 질의는 "통과율이 훈련에서 본 값과 T = 0.05 넘게 다른가" 하나로 고정하고, 아니라고 나오면 개발 자료 값을 그대로 쓴다. 넘었다고 나오는 횟수를 예산 B로 세고 **B = 3**으로 묶는다. (2) 나머지 몫은 손대지 않고 끝에 **딱 한 번** 읽어 최종 성적으로 보고한다. (3) 홀드아웃을 읽은 횟수와 그때 본 값을 날짜와 함께 기록으로 남긴다(논문의 과적합 계수기 Zi에 해당). (4) 홀드아웃을 보고 고친 횟수가 예산을 넘으면, 그 시점 이후의 성적은 독립 성능이 아니라고 보고서에 적는다.

## 이 단계 후보 방법으로서

- **방법 이름**: 재사용 홀드아웃(Thresholdout 방식 문턱 창구) + 과적합 예산 계수기
- **전제 조건**
  - 홀드아웃이 i.i.d. 표본이어야 이론 보장이 성립한다. 우리 자료는 날짜와 명령 격자로 묶여 있으므로 보장은 근사로만 쓴다.
  - 질의는 값이 [0, 1]인 함수여야 한다. 통과율(0/1 지시 함수)과 20턴 성공률은 조건을 만족한다. 평균 |eY|(mm 단위)는 유계로 잘라야 한다.
  - 예산 B와 문턱 T를 **시험 시작 전에** 정하고 바꾸지 않아야 한다.
- **장점**
  - 특별한 절차 없이, 이미 가진 자료로 "개발 중에도 성적을 몇 번 들여다볼 수 있게" 해 준다. 매번 새 자료를 모으는 것이 종래의 유일한 안전책이었다.
  - 예산 계수기가 그대로 감사 기록이 된다. 보고서에 "홀드아웃을 몇 번 읽었다"를 숫자로 쓸 수 있다.
  - 논문 모의실험에서 표준 홀드아웃이 50%를 63%로 부풀릴 때 Thresholdout은 50%를 유지했다. 우리의 통과율 부풀림 위험과 크기가 비슷한 수준의 사례다.
- **단점**
  - **우리 자료 크기에서는 이론 보장이 사실상 나오지 않는다.** 보조정리 24에 우리 숫자를 넣으면, 홀드아웃 n = 234, 실패 확률 β = 0.05일 때 ln(6/0.05)/τ² ≤ 234에서 τ ≥ 0.143이다. 즉 통과율을 ±14%p보다 좁게는 보장할 수 없다. 두 번째 조건 2B/(στ) ≤ 234에 σ = 0.01, τ = 0.143을 넣으면 B < 1이 되어 예산이 1회도 안 된다. 234장을 20턴 복귀 시험 벌 수로 세면 유효 크기는 더 작다.
  - 그러므로 **이론 보장이 아니라 실무 규율로만** 쓸 수 있다. 저자들도 5절 모의실험에서 이론값보다 훨씬 작은 T = 0.04, 잡음 0.01을 썼다고 밝혔다.
  - 과적합일 때 돌려주는 값에 잡음이 섞여 있어, 그 값을 다시 튜닝 근거로 쓰면 안 된다.
  - 보장이 i.i.d.를 전제하므로, 날짜 하나씩 빼기 같은 묶음 분할과 함께 쓸 때는 보장이 아니라 관행으로만 다룬다.
- **우리 적용 조건**
  1. 234장(개발 미노출분)을 **검증 몫**과 **최종 몫**으로 나눈다. 날짜가 치우치지 않게 나누고, 분할을 기록하고 이후 바꾸지 않는다.
  2. 검증 몫은 Thresholdout 창구로만 접근한다. 질의는 "|eY| ≤ 0.045 이면서 |eT| ≤ 0.045인 비율"과 "20턴 안 수렴 비율" 둘로 고정한다. 문턱 T = 0.05, 예산 **B = 3**으로 시작 전에 정한다. 문턱을 안 넘으면 개발 자료에서 잰 값을 그대로 보고한다.
  3. 최종 몫은 모든 조정이 끝난 뒤 **한 번만** 읽는다. 그 값만 독립 성능으로 보고한다. 다시 읽으면 더는 독립이 아니라고 적는다.
  4. 노출된 341장에서 낸 성적은 어떤 경우에도 독립 성능으로 쓰지 않는다. 보고서에 "개발 노출분"으로 따로 표기한다.
  5. 홀드아웃 접근 기록(날짜, 질의, 문턱 초과 여부, 남은 예산)을 실험 폴더에 남긴다. 이것이 질문 6의 누출 점검표에 들어간다.
  6. 질문 7의 시험 설계에 예산 B와 문턱 T를 **사전 등록** 항목으로 넣는다. 반복 횟수, 날짜 수, 자세 수, 20턴 복귀 시험 벌 수와 같은 줄에 적는다.
