# 파이프라인 v2 계획

작성 2026-11-04 · 브랜치 `feature/hye/pipeline-v2` · 지침 [문헌연구/AGENTS.md](../문헌연구/AGENTS.md), [ALGORITHM_RULES.md](../../../ALGORITHM_RULES.md)

## 목표

지금의 `00000_final_Y_T control`, `00000_final_Y_T_joint`보다 **더 강건하고, 효과가 크고, 논리적으로 설명 가능한** `final_v2` 두 모듈(control, joint)을 만든다. 모든 설계 선택은 (1) 단계별 해결할 질문 → (2) 논문·특허 조사 → (3) 문헌 기반 후보 재작성 → (4) 같은 자료·같은 분할 비교 실험 → (5) 선택의 순서로 근거를 남긴다.

성공 기준 (ALGORITHM_RULES 2026-11-04 기준. 에이전트 프롬프트에 적힌 0.045 공통 기준보다 이 절이 우선)
- **joint_v2 (1차 T): 한 장 `|eT| ≤ 0.01` (1틱).** 주 지표는 날짜를 나눈 평가의 통과율과 최대오차. 기존 joint는 20261020 OOF에서 85.4%(41/48), 최대 0.043. 0.01 초과 사진을 사진별로 분석한다.
  - 튀는 값 분석(A10 per_shot.csv, 20261020 OOF): 0.01 초과 7장 모두 T는 +0.01~+0.043, 같은 사진의 Y는 −0.04~−0.19로 **Y 오차 ≈ −5~−6 × T 오차**. 감도비 5.6과 일치하므로 실제 Y 이동 일부를 T로 읽는 Y↔T 누출이다. 튀는 사진은 대부분 Y·T가 함께 큰 혼합 자세(T=1.00)이며, 혼합 자세 학습 자료는 1020 한 사분면뿐이다. joint_v2는 이 누출을 줄이는 것(가로선 활용, 날짜 간 카메라 이동 제거, 혼합 자세 외삽 대책)을 주 목표로 삼는다.
  - 메인이 직접 한 선행 실험: [A17](../../../experiments/hye/20261104_091825_A17_날짜층화5fold_joint재평가/결과/보고서.md)(날짜별 80/20 5-fold, 1020 85.4%→91.7%), [A18](../../../experiments/hye/20261104_092326_A18_joint_T001_개선탐색/결과/보고서.md)(최선 1장 98.4%, 같은 자세 3장 평균 99.4%; 남은 꼬리는 사진 단위 실제 자세 차이로 추정, 서로 다른 관측이 일치). joint_v2 설계는 이 결과를 출발점으로 쓰고, 날짜별 80/20 5-fold(10분할 반복)를 평가 분할에 포함한다.
  - [A19](../../../experiments/hye/20261104_093558_A19_QR선측정_안정성점검/결과/보고서.md): QR 측정은 강건(교란 오차 ≤0.017 px), **가로선 블록은 잡음·조명에 0.1~0.7 px 흔들림**, 카메라 세로 0.25 px 이동에 frozen joint T가 최대 0.017 변함. [A20](../../../experiments/hye/20261104_093913_A20_실제joint측정_세션재영점/결과/보고서.md): 1014만 학습→1029에서 지금 joint 측정 102d는 0%, **QR 평균 가로 이동 + 위·아래 선 기울기 차 2특징은 재영점 없이 233/234**. joint_v2는 (1) 가로선 측정 강건화(강건 직선 적합으로 기울기), (2) 카메라 이동 불변 특징, (3) "1014만 학습→다른 날짜" 분할을 주 평가로 삼는다. 세션 재영점 방식은 비교 기준으로 둔다.
- **control_v2 (2차 Y): 한 장 `|eY| ≤ 0.045`** (주 기준, 사용자 확인).
- **control_v2 보조 기준 (b) 준비:** 같은 자세 반복의 Y 전폭 ≤ 0.045. 반복 묶음(1020·1029의 3장 묶음)으로 전폭·3σ와 통과 여부를 보고하고, 만족에 필요한 턴당 평균 장수와 구동계 반복 오차 예산을 계산한다.
- 축별 평균·최대오차, 처리 시간(ms)을 기존 final과 **같은 사진·같은 분할**에서 비교
- 날짜를 통째로 나눈 평가(1014 ↔ 1020 ↔ 1029)에서 기존보다 나빠지지 않을 것
- 실패를 (0,0)으로 숨기지 않고, 판정(신뢰/재촬영) 진단을 함께 낼 것
- 개발에 이미 노출된 자료의 성적임을 명시하고, 독립 검증·실기 검증을 주장하지 않을 것

## 진행 순서

1. **조사** (단계 단위 병렬): 질문 → 기존 문헌 매핑 → 새 논문·특허 검색 → 문헌별 폴더(원문·번역·요약) → `00_단계.md` 리뷰
2. **캔버스 1** 조립
3. **실험 계획** (단계 단위): 문헌 기반 후보로 실험 설계. 오프라인 자료로 가능한 것과 실기 필요한 것을 구분
4. **캔버스 2** 조립
5. **실험 실행** (오프라인 가능 단계): 같은 자료·분할, 정확도+시간
6. **캔버스 3** 조립
7. **알고리즘 재설계**: 실험 결과로 control_v2, joint_v2 구성 → 구현 → 기존 final과 비교 검증 → 적대적 검토
8. **알고리즘 캔버스**와 결과보고

## 환경 메모

- 기존 실험은 Windows MSVC v141 + OpenCV 3.4.15로 빌드됐다. 이 맥에는 Homebrew OpenCV(5.x)를 설치해 실험을 돌린다. 버전 차이로 수치가 미세하게 다를 수 있으며, 결과 문서에 빌드 환경을 적는다. final_v2 코드는 OpenCV 3.4.15 API 안에서 작성해 팀 환경 호환을 유지한다.
- `data/clean/`(13 GB)과 기존 캐시 `20261102_124309_A0_.../결과/cache`를 입력으로 쓴다. 원본·기존 결과는 덮어쓰지 않는다.
- 대용량 데이터는 커밋하지 않는다. `git add .`를 쓰지 않는다.
