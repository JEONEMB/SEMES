# 0. 전체 안내

이 패키지로 할 수 있는 네 가지를 차례로 설명한다.

1. 사진을 넣는다 (데이터)
2. 계수를 다시 만든다 (학습)
3. 성능을 잰다 (평가)
4. 장비에서 쓴다 (실사용, 포팅)

무슨 문제를 풀고 어디까지 풀었는지는 [0. 문제 정의와 목표](0_문제정의와_목표.md)에 있다.

## 1. 전체 폴더 구조

```
semes/
  include/alignment.hpp      쓰는 사람이 부르는 함수 7개 (이것만 보면 쓸 수 있다)
  src/                       측정 코드 (실사용, 학습, 평가가 모두 이 코드 하나를 쓴다)
  config/settings.json       설정 (쓸 나사, 실패 기준, 로그 파일)

  data/
    model/                     실사용이 읽는 파일 (기준 사진, 위치, 계수, 점검식). 장비에는 이것만 보낸다
    new_photos/                학습과 평가에 쓸 사진을 넣는 곳
      20261014/ …                ← 사람이 사진을 넣는다 (촬영한 날마다 폴더 하나)
      tables/                    ← 프로그램이 자동으로 만든다 (손대지 않는다)
    sample/                    확인용 예제 사진 5장과 기대값
    results/                   도구가 만든 결과: train/ (새로 학습한 계수), eval/ (평가 결과)

  tools/
    try/                       써 보기와 확인: measure_one, show_steps, check_photos, check_setup, make_figures
    train/                     계수를 다시 만들 때: train (물어보며 한 번에) 과 그 안에서 차례로 도는 두 프로그램
      prepare_dataset            사진 → 목록, 정답, 시험 나누기, 측정값
      fit_coefficients           측정값 + 정답 → 새 계수와 점검식
    evaluate/                  성능을 잴 때
      evaluate_accuracy          정확도 시험 네 가지
      measure_speed              속도
      score_photos               명령값 기준 채점 (엑셀용 표, 손으로 확인)
    environment/               다른 설치 환경의 화면을 만들어 반응 보기
    common/                    도구가 같이 쓰는 코드

  docs/                      문서
    0_문제정의와_목표, 0_전체안내, 0_코드구조, 1_한눈에보기, 2_포팅안내서
    구현_방법/                 어떻게 만들었고 왜 이 방법인가 (step 0 ~ 4)
    평가_방법/                 어떻게 재고 얼마나 나왔나 (정확도, 속도, 강건성, 부품별 정밀도, 직접 평가하는 법)
    추가_논의/                 더 이야기할 주제
```

### 한눈에 보는 흐름

```
[사진] → data/new_photos/
           │ prepare_dataset
           ▼
        data/new_photos/tables  (목록, 정답, 시험 나누기, 측정값)
           │ fit_coefficients              │ evaluate_accuracy, measure_speed
           ▼                               ▼
        새 model 폴더 → 확인 후 data/model/ 로 복사   성능 보고서
           │
           ▼
        실사용: initialize → set_zero_from_photos → measure_alignment
```

### 지키는 원칙 네 가지

| 원칙 | 뜻 | 어떻게 지키나 |
|---|---|---|
| 진짜 정확도 | 답을 외운 시험이 아니라 처음 보는 사진으로 잰 정확도 | 시험 사진은 학습에 쓰지 않는다. 같은 자세는 같은 묶음. 마지막 확인 사진은 다 정한 뒤 한 번만 본다 |
| 진짜 속도 | 무엇을 쟀는지 분명한 속도 | 사진 읽기 포함 여부, 스레드 수, 첫 호출 제외, 중앙값과 최대값, 컴퓨터 사양을 같이 적는다 |
| 강건함 | 조명, 가림, 카메라 변화에도 버티는가 | 교란 시험에서 "상태는 정상인데 틀린 값"(조용히 틀림)의 비율을 잰다 |
| 못 풀면 알린다 | 잴 수 없거나 믿기 어려우면 숨기지 않는다 | 경고(값과 함께 안내, 다음 할 일)와 실패(멈춤)로 알린다. README 5절 |

## 2. 데이터 넣는 방법

### 2-1. 넣는 법 (이것만 하면 된다)

1. `data/new_photos/` 안에 **촬영한 날(회차)마다 폴더를 하나** 만든다. 폴더 이름이 회차 이름이 된다. 예: `20261014`
2. 그 폴더에 **SEMES 에서 찍은 사진을 이름 그대로** 넣는다. 하위 폴더가 있어도 된다.
3. 그날 **로봇을 명령 0 으로 보내 찍은 사진**이 있으면 이름을 명령값 그대로 넣는다. 예: `Y+0.00 T+0.00 (1).bmp`. 영점을 잡는 데 쓴다
4. 아래 한 줄을 실행한다.

```bash
build/Release/prepare_dataset data/new_photos
```

### 2-2. 파일 이름 규칙

파일 이름에서 명령값을 읽는다. 없는 축은 0 으로 본다.

| 파일 이름 | 읽는 값 |
|---|---|
| `Y+0.05.bmp` | Y 0.05 mm, T 0 |
| `T-0.30.bmp` | Y 0, T −0.30도 |
| `Y+0.05 T+0.01.bmp` | Y 0.05, T 0.01 |
| `Y+0.05 T+0.01 (2).bmp` | 같은 자세를 여러 번 찍은 것. `(2)` 는 무시하고 같은 자세로 묶는다 |
| `Y+0.00 T+0.00 (1).bmp` | 명령 0 사진. 평가할 때 영점을 잡는 데 쓴다 |
| `center.bmp` 처럼 명령값이 없는 이름 | 명령값을 알 수 없어 정답, 영점에 쓰지 않는다. 건너뛰고 보고서에 적는다 |
| 그 밖의 이름 | 건너뛰고 보고서에 적는다 (멈추지 않는다) |

사진은 3840×2160, 8비트 (`.bmp` 또는 `.png`).

### 2-3. 자동으로 만들어지는 것 (`data/new_photos/tables`)

| 파일 | 내용 |
|---|---|
| `photos.tsv` | 사진 번호, 회차, 경로, 명령 Y, 명령 T |
| `labels.tsv` | 학습용 정답 (아래 2-4) |
| `splits.tsv` | 시험 나누기: 마지막 확인 사진 여부, 반복 10번 각각의 묶음 번호 |
| `features.tsv` | 사진마다 측정값: QR 가로 이동, 나사 1~4 가로 이동 |
| `prepare_report.txt` | 읽은 사진 수, 건너뛴 파일, 회차별 영점 차이 |

### 2-4. 왜 이렇게 하나

| 결정 | 이유 |
|---|---|
| 회차마다 폴더 | 로봇의 "명령 0" 자리가 날마다 조금씩 다르다 (Y 0.04~0.10 mm). 날을 구분해야 이 차이를 다룰 수 있다 |
| 이름 그대로 넣기 | SEMES 가 원래 쓰는 이름 규칙이라 고칠 일이 없다. 사람이 손으로 표를 만들 필요가 없다 |
| 학습용 정답은 "명령값 − 그날 영점 차이" | 날마다 다른 영점을 그대로 두면 다른 날 사진에서 성적이 크게 떨어졌다 (71%). 그날 사진 전체로 그날 영점 차이를 구해 빼서 모든 날을 같은 0 에 맞춘다. **이 보정은 학습에만 쓴다. SEMES 의 정답(파일 이름)은 바꾸지 않는다** |
| 같은 자세는 같은 묶음 | 거의 같은 사진이 학습과 시험에 동시에 들어가면 답을 미리 본 셈이 된다 |
| 나누기는 고정 씨앗 | 누가 돌려도 같은 나누기, 같은 숫자가 나온다 |
| 사진은 Git 에 안 올림 | 장당 24 MB. 사진은 원래 SEMES 것이라 SEMES 가 가지고 있다 |

## 3. 학습과 평가

### 3-1. 학습 (계수 다시 만들기)

**가장 쉬운 방법: 물어보며 진행.** 인자 없이 실행하면 사진 재기, 계수 만들기, 정확도 확인을 차례로 알아서 한다.

```bash
build/Release/train
```

| 순서 | 화면에 나오는 것 | 할 일 |
|---|---|---|
| 1 | 사진 넣는 규칙 설명, 사진 폴더 경로 묻기 | `data/new_photos` 에 넣었으면 Enter |
| 2 | 회차마다 사진 수, 걸릴 시간, 새 계수를 저장할 곳을 보여 주고 시작할지 묻기. 전에 잰 표가 있으면 다시 잴지도 묻는다 | Enter 또는 y |
| 3 | 사진 재기 (진행 줄: 몇 장째, 퍼센트, 남은 시간. 715장에 약 2분) → 계수 만들기 → 정확도 확인 | 기다린다 |
| 4 | "학습이 완료되었습니다", 새 계수와 정확도 보고서를 저장한 곳, 새 계수를 쓰는 방법 | 정확도를 보고 쓸지 정한다 |

새 계수는 `data/results/train/<날짜_시각>/model/` 에 생긴다. **지금 쓰는 `data/model/` 은 바뀌지 않는다.** 쓰기로 했으면 `data/model` 을 다른 이름으로 보관한 뒤 새 `model` 안의 파일을 복사한다.

**한 단계씩 따로 실행** (`train` 이 차례로 부르는 프로그램들이다. 한 단계만 다시 돌릴 때 쓴다):

```bash
build/Release/fit_coefficients data/new_photos/tables data/results/train/new_model
```

| 하는 일 | 내용 |
|---|---|
| 계수 | 나사 조합 16가지마다 Y, T 선형식 (값을 표준화한 뒤 Huber 강건 회귀 6번, 아주 작은 ridge) |
| 점검식 | 나사 2개 이상 조합 11가지마다, 값마다 "이 Y, T 라면 이 값이어야 한다" 2차식과 기준값 |
| 학습 범위 | 학습에 쓴 사진의 Y, T 범위를 `reference.json` 에 적는다 |
| 결과 위치 | `data/results/train/new_model/` (**`data/model/` 을 바로 덮어쓰지 않는다**). 평가로 확인한 뒤 사람이 `data/model/` 에 복사한다 |

**왜 이렇게 하나**

| 결정 | 이유 |
|---|---|
| 선형식 | 2차, 3차식, 릿지, GLS 도 시험했지만 이기지 못했거나 과적합됐다. 범위 밖에서도 덜 휜다 |
| Huber 강건 회귀 | 가끔 섞이는 이상한 사진에 계수가 끌려가지 않게 |
| 조합마다 계수 | 나사가 가려져도 남은 나사로 정밀하게 계산하려고 |
| 새 폴더에 쓰기 | 실수로 운영 계수를 바꾸지 않게 |

### 3-2. 평가

평가는 세 가지 프로그램으로 한다. 재는 방법, 그렇게 재는 이유, 자세한 결과는 [평가_방법/](평가_방법/) 폴더에 있다.

| 재는 것 | 프로그램 | 결과 요약 | 자세한 문서 |
|---|---|---|---|
| 받은 사진 채점 (엑셀로 확인) | `score_photos` | 사진마다 정답, 측정값, 오차, 통과 여부 | [5. 직접 평가하는 법](평가_방법/5_직접_평가하는_법.md) |
| 정확도 | `evaluate_accuracy` | 처음 보는 사진 100%, 마지막 확인 99.2%, 처음 보는 날(그날 영점 5장) 95.5% | [1. 정확도](평가_방법/1_정확도.md) |
| 속도 | `measure_speed` | 측정만: 스레드 1개 19.2 ms, 4개 9.6 ms (가운뎃값) | [2. 속도](평가_방법/2_속도.md) |
| 상황이 나빠질 때 | (합성 사진 시험) | 상황마다 생기는 일과 대처 | [3. 강건성](평가_방법/3_강건성.md) |
| QR, 나사, 바 각각 | | 찾는 비율, 흔들림, 치우침 | [4. 부품별 정밀도](평가_방법/4_부품별_정밀도.md) |

통과 = Y 오차 0.045 mm 이하이고 T 오차 0.01도 이하. 시험에 쓴 사진은 그 시험의 학습에 쓰지 않았다.

**받은 사진을 채점하는 가장 쉬운 방법**

```bash
build/Release/score_photos
```

인자 없이 실행하면 영점 사진, 평가할 폴더를 차례로 묻는다. 끝나면 `data/results/eval/` 아래에 `results.csv`(엑셀로 연다)와 `summary.txt` 가 생긴다.

**꼭 지킬 것 하나**: 평가할 사진과 **같은 날, 로봇을 명령 0 으로 보내 찍은 사진 5 ~ 10장**을 같이 준다. 없으면 그날 로봇 0 의 차이(Y 0.04 ~ 0.13 mm)가 그대로 오차가 된다.

| | 처음 보는 날 통과율 |
|---|---|
| 영점 사진 없이 | 31.5% |
| 영점 사진 5장으로 | 95.5% |

## 4. 실사용 방법

### 4-1. 순서

```cpp
#include "alignment.hpp"

alignment::initialize("data/model");                                 // 1. 프로그램 시작할 때 한 번
alignment::set_zero_from_photos(zero_photos);                  // 2. 매일, 장비를 손댄 뒤 (명령 0 에서 찍은 사진 5~10장)
alignment::Result r = alignment::measure_alignment(photo);     // 3. 사진마다
// 보정 이동 = (−r.y_mm, −r.t_deg)
// r.status 가 Warning 이면 r.message 의 안내대로, Failed 이면 멈춘다
```

### 4-2. 영점 (가장 중요)

- **로봇을 명령 0 으로 보내 찍은 사진으로 매일 영점을 잡는다.** 그래야 출력이 그날 명령값과 맞는다.
- 영점을 안 잡으면 그날 로봇 0 의 어긋남(Y 0.04 ~ 0.13 mm)이 그대로 오차로 보인다. 허용오차(0.045 mm)보다 클 수 있다.
- 명령값을 모르는 "센터 사진"으로 잡으면 안 된다. 그 사진이 그날 명령 0 과 다른 만큼 치우친다.
- 1장보다 **5 ~ 10장**이 좋다.

| 사진 수 | 영점의 흔들림 (Y) | 정확도 (10/14, 가장 나쁜 경우) |
|---|---|---|
| 1장 | 0.003 ~ 0.016 mm | 89.6% (61.3%) |
| 3장 | 0.001 ~ 0.008 mm | 95.6% (85.6%) |
| 5장 | 0.0005 ~ 0.006 mm | 96.4% (87.3%) |
| 10장 | 0.001 ~ 0.003 mm | 97.9% (91.5%) |

자세한 내용(명령 0 이 아닌 자세로 잡는 법, 영점과 기준의 차이)은 [구현 방법 step 0](구현_방법/step0_준비와_영점.md).

- 영점은 메모리에만 있다. 프로그램을 다시 켜면 다시 잡거나 `set_zero_value` 로 적어 둔 값을 넣는다.
- 카메라가 많이 밀려 QR 을 못 찾으면 `set_reference_from_photos` 로 기준을 다시 잡는다(영점은 이어진다).

### 4-3. 상태별 대응

README 5절 표를 따른다. 요약:

| 상태 | 로봇 |
|---|---|
| 정상 | 그 값으로 보정 |
| 경고 | 안내대로 옮기고 다시 잰다 (QR 3개, 좌우 나사가 보일 때까지, 학습 범위 안에 들어올 때까지) |
| 실패 | 멈춘다 |

### 4-4. 포팅할 때 주의할 점 (자세한 것은 README 9절)

| 주의 | 내용 |
|---|---|
| 컬러 순서 | 3채널 사진은 BGR 로 본다. RGB 로 주면 값이 조용히 틀린다. 회색으로 넣는 것이 가장 안전 |
| 사진 크기, 카메라 조건 | 3840×2160 만 받는다. 렌즈, 거리, 카메라를 바꾸면 계수를 다시 학습해야 한다 (3-1) |
| 재시작 | 영점, 기준을 다시 잡은 결과는 메모리에만 있다 |
| 동시 사용 | 상태가 하나라서 카메라 여러 대는 프로세스를 나눈다 |
| 숫자 형식 | `double` 을 유지한다. `float` 으로 바꾸면 확인 값이 소수 4자리에서 어긋날 수 있다 |
| OpenCV | 3.4.15 에서 확인했다. 다른 버전은 `tools/try/check_photos` 로 확인 |
| 소스 인코딩 | UTF-8, 한글 주석. Visual Studio 는 `/utf-8` 옵션 |
| 경로 | 설정, 위치 파일은 영문 경로에 둔다 |
