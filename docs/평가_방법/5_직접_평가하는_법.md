# 5. 직접 평가하는 법

설비에서 찍은 사진을 가져와 **프로그램 하나로 채점하고 엑셀로 결과를 보는** 순서다. 코드를 고치지 않는다.

도구: `tools/evaluate/score_photos`

---

## 1. 준비할 사진

### 1-1. 평가할 사진

- 하루에 찍은 사진을 폴더 하나에 넣는다. 하위 폴더가 있어도 된다.
- **파일 이름에 로봇 명령값이 들어 있어야 한다.** 이 값을 정답으로 쓴다.

| 파일 이름 | 읽는 정답 |
|---|---|
| `Y+0.05.bmp` | Y 0.05 mm, T 0도 |
| `T-0.30.bmp` | Y 0 mm, T −0.30도 |
| `Y+0.05 T+0.01.bmp` | Y 0.05 mm, T 0.01도 |
| `Y+0.05 T+0.01 (2).bmp` | 위와 같음 (같은 자세를 두 번째 찍은 사진) |
| `center.bmp` 처럼 명령값이 없는 이름 | 정답을 알 수 없어 건너뛴다 |

- 사진은 3840×2160, 8비트 (`.bmp` 또는 `.png`).
- 파일 이름을 바꿀 수 없으면 정답표를 따로 줄 수 있다 (3절).

### 1-2. 영점 사진 (꼭 같이 찍는다)

- **평가할 사진과 같은 날, 로봇을 명령 0 (Y 0, T 0) 으로 보내고 5 ~ 10장** 찍는다.
- 이름은 `Y+0.00 T+0.00 (1).bmp`, `(2)`, … 로 해서 평가할 폴더에 같이 넣거나, 다른 폴더에 따로 둔다.

**왜 필요한가**: 로봇의 "명령 0" 자리는 날마다 조금씩 다르다 (우리가 받은 사진에서 Y 로 0.04 ~ 0.13 mm). 이 차이는 사진만으로는 알 수 없다. 영점 사진이 없으면 이 차이가 그대로 오차로 들어가서 통과율이 크게 낮게 나온다.

| | 처음 보는 날 통과율 (우리가 받은 4번의 촬영) |
|---|---|
| 영점 사진 없이 | 31.5% |
| 영점 사진 5장으로 | 95.5% |

**지킬 것**

| | 이유 |
|---|---|
| 평가할 사진과 같은 날 찍는다 | 날이 바뀌면 로봇 0 도 바뀐다 |
| 카메라, 조명, 판을 건드렸으면 다시 찍는다 | 화면이 조금만 움직여도 영점이 바뀐다 |
| 로봇 명령값을 아는 사진이어야 한다 | 명령값 없이 "센터"라고만 찍은 사진은 명령 0 과 다를 수 있다 (우리가 받은 센터 사진은 0.03 ~ 0.04 mm 달랐다) |
| 1장보다 5 ~ 10장 | 1장은 운이 나쁘면 그날 전체가 치우친다 |
| 여러 날 사진은 날마다 따로 평가한다 | 영점은 하루치에만 맞다 |

## 2. 평가하기

### 2-1. 물어보는 대로 답하기 (쉬운 방법)

```
build\Release\score_photos.exe
```

인자 없이 실행하면 차례로 묻는다.

| 순서 | 묻는 것 | 답 |
|---|---|---|
| 1 / 3 | 영점 사진 | 영점 사진이 든 폴더나 파일 경로. 평가할 폴더 안에 `Y+0.00 T+0.00` 사진이 있으면 Enter |
| 2 / 3 | 평가할 사진 | 평가할 사진이 든 폴더 경로 |
| 3 / 3 | 확인 | 찾은 사진 수, 영점 사진 수, 통과 기준을 보여 준다. Enter 로 시작 |

끝나면 결과를 저장한 곳을 알려 준다 (`data/results/eval/<날짜_시각>/`).

### 2-2. 한 줄로 실행하기

```
build\Release\score_photos.exe <사진 폴더> <출력 폴더> [--zero <영점 사진 폴더>] [--tolerance-y 0.045] [--tolerance-t 0.01] [--answers 정답표.tsv]
```

| 옵션 | 뜻 |
|---|---|
| `--zero` | 영점 사진이 든 폴더나 파일. 안 주면 사진 폴더 안의 명령 (0, 0) 사진을 쓴다 |
| `--tolerance-y`, `--tolerance-t` | 통과 기준 (기본 0.045 mm, 0.01도) |
| `--answers` | 파일 이름 대신 쓸 정답표 (3절) |
| `--data` | 모델 폴더 (기본 `data/model`) |

## 3. 파일 이름을 바꿀 수 없을 때: 정답표

탭으로 나눈 표를 만든다. 첫 줄은 머리줄이다.

```
file	y_mm	t_deg
IMG_0001.bmp	0.05	0.01
IMG_0002.bmp	-1.00	0
```

`--answers 정답표.tsv` 로 넘긴다. 엑셀에서 "텍스트(탭으로 분리)"로 저장하면 된다.

---

## 4. 결과 읽기

### 4-1. `summary.txt`

전체 통과율, 폴더별 통과율, 가장 큰 오차, 상태별 개수, 한 장에 걸린 시간이 나온다. 통과율은 두 가지가 같이 나온다.

| 점수 | 뜻 |
|---|---|
| 영점 잡음 | 영점 사진으로 그날 0 을 맞춘 뒤의 통과율. **실제로 쓸 때의 정확도** |
| 영점 없음 | 영점을 잡지 않았을 때의 통과율. 그날 로봇 0 이 얼마나 다른지 보여 준다 |

영점 사진이 없으면 맨 위에 경고가 나오고 "영점 없음" 점수만 나온다.

### 4-2. `results.csv` (엑셀로 연다)

한 줄이 사진 한 장이다.

| 열 | 뜻 |
|---|---|
| 사진, 폴더 | 파일 이름과 폴더 |
| 정답 Y, 정답 T | 파일 이름(또는 정답표)의 명령값 |
| 측정 Y, 측정 T | 알고리즘이 잰 값 (영점을 잡은 뒤) |
| 오차 Y, 오차 T | 측정 − 정답 |
| 통과 | 1 이면 통과, 0 이면 허용오차 밖 |
| 영점 없이 측정 Y, T, 통과 | 영점을 잡지 않았을 때의 값과 통과 여부 |
| 상태 | 정상, 경고, 실패 |
| 코드, 메시지 | 경고나 실패의 이유. 다음에 할 일은 [README 5절](../../README.md)의 표에 있다 |
| 시간 ms | 그 사진을 재는 데 걸린 시간 |

### 4-3. 엑셀에서 확인하는 순서

1. "통과" 열에 필터를 걸어 `0` 만 본다. 허용오차 밖인 사진만 남는다.
2. 그 사진들의 "상태", "코드" 열을 본다.
   - 경고가 붙어 있으면: 알고리즘이 "이 값은 믿기 어렵다"고 알린 것이다. 메시지대로 조치한다.
   - 정상인데 틀렸으면: "오차 Y", "오차 T" 중 어느 쪽이 넘었는지, 얼마나 넘었는지 본다.
3. "오차 Y" 열 전체의 평균을 본다.
   - 평균이 0 근처면 사진마다의 흔들림이다.
   - **평균이 0 에서 멀면 영점이 맞지 않은 것이다.** 영점 사진을 다시 확인한다.
4. 다른 기준으로 보고 싶으면 "오차 Y", "오차 T" 열로 엑셀에서 직접 계산한다.

## 5. 자주 생기는 일

| 증상 | 원인 | 할 일 |
|---|---|---|
| 통과율이 0 ~ 30% | 영점 사진이 없거나 다른 날 사진이다 | 같은 날 명령 0 사진 5 ~ 10장을 넣고 다시 한다 |
| 모든 사진의 오차 Y 가 비슷한 값으로 치우침 | 영점 사진을 찍은 뒤 카메라나 판이 움직였다 | 영점 사진을 다시 찍는다 |
| 모든 사진에 `W_VALUES_DISAGREE` | 일치 점검값이 해당 나사 조합의 한계를 넘었다 | 영점 사진을 다시 찍는다 |
| 모든 사진이 `E_QR_NOT_FOUND` | QR 검출 결과 또는 나사 조합 계수에 문제가 있다 | 기준을 다시 잡는다 ([구현 방법 step 0](../구현_방법/step0_준비와_영점.md) A-3) |
| 모든 사진이 `E_PHOTO` | 사진 크기나 형식이 다르다 | 3840×2160, 8비트인지 확인한다 |
| "이름에 명령값이 없어 건너뛰는 사진"이 많음 | 파일 이름 규칙이 다르다 | 정답표를 쓴다 (3절) |
| `W_OUT_OF_RANGE` 가 많음 | 영점 차감 전 판정값이 모델의 학습 범위 밖이다 | 메시지의 초과 축, 판정값, 학습 범위를 확인한다 |

---

## 6. 계수까지 다시 만들고 싶을 때

카메라, 렌즈, 거리, 판이 바뀌었거나, 영점을 잡아도 정확도가 낮으면 새 사진으로 계수를 다시 만든다.

1. 사진을 `data/new_photos/<촬영 날짜>/` 에 넣는다 (`data/new_photos/README.md`).
2. 실행한다.

```
build\Release\train.exe
```

3. 물어보는 대로 답하면 사진 재기, 계수 만들기, 정확도 확인을 차례로 한다.
4. 새 계수는 `data/results/train/<날짜_시각>/model/` 에 생긴다. **지금 쓰는 `data/model` 은 바뀌지 않는다.** 정확도 보고서를 확인한 뒤 직접 바꿔 넣는다.
