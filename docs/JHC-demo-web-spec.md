## 1. 목적과 확정 요구

Raspberry Pi에서 카메라 영상과 시연 웹을 제공하고, STM32가 Y·T(Theta)축을 제어한다.
관리자가 미리 저장한 시작 위치와 단계별 보정 명령으로 실제 장치를 움직이는 시연이다.
이번 범위의 보정값 생성 방식은 저장된 시나리오 재생이며, 실시간 영상 기반 보정량 계산은 별도 기능이다.

- 왼쪽: 실제 카메라 영상, 영상 정중앙에 고정된 빨간 십자선.
- 오른쪽: Trial, Y 보정 명령값, T 보정 명령값, 실행 상태.
- 아래쪽: `Random`, `자동보정` 버튼.
- Trial은 보정 시도 횟수이며 최대 20회다. Random 이동은 Trial에 포함하지 않는다.
- Random은 사전 지정한 시작 위치로 이동한다. 시작 위치와 이후 보정값은 시연 화면에 표시하지 않는다.
- Random 실행 시 Trial과 Y·T 표시를 0으로 초기화한다.
- 자동보정은 최대 20단계 안에서 여러 번 보정하여 중앙에 도달할 수 있다.
- Y·T는 실제 위치나 오차 추정치가 아니라 장치에 보낸 보정 명령값을 표시한다.
- 관리자 전용 화면에서 시연 시나리오를 작성·저장하고 시연은 저장된 값만 사용한다.

## 2. 구현 기본안

다음은 아직 사용자 확정값이 없는 부분에 대한 기본 설계다.

| 항목 | 기본안 |
| --- | --- |
| 시나리오 선택 | 관리자가 지정한 재생 목록을 순서대로 순환. 버튼 이름은 Random 유지 |
| Random 이동 | STM32 원점 좌표계의 절대 시작 위치로 MOVE_ABS 실행 |
| 보정 단계 | Y·T 상대 이동량을 한 쌍으로 저장하고 MOVE_REL 실행 |
| Trial 증가 | 새로운 보정 단계가 ACK로 수락될 때 1 증가. 재전송은 증가하지 않음 |
| Y·T 갱신 | ACK 시 해당 단계에 실제 전송한 보정 명령값으로 갱신 |
| 수치 의미 | 이번 Trial의 명령값. 누적값이 아님 |
| 표시 단위 | Y: mm, T: °. 내부 및 통신 저장 단위는 µm, 0.001° 정수 |
| 자동보정 실행 | 버튼 한 번으로 단계 전체 실행. 각 단계 DONE(OK) 이후 다음 단계 진행 |
| 완료 후 수치 | 마지막 보정 명령값 유지. 완료를 표현하려고 임의로 0으로 변경하지 않음 |
| 단계 간 대기 | 진동 안정화를 위한 설정값. 실제 장비에서 결정 |
| 접근 방식 | 파이 로컬 서버에 파이 또는 같은 네트워크의 발표용 노트북으로 접속 |

명령 전송부터 ACK까지는 내부적으로 '수락 대기'로 관리한다. NAK는 보정 Trial에 포함하지 않는다.
ACK 유실 등으로 실제 수락 여부가 불명확하면 실행을 중단 상태로 두고 확인한다. 임의로 카운트를 올리거나 다음 단계로 넘어가지 않는다.
한 단계에서 Y와 T 명령이 함께 수락되면 Trial 1회다. 두 축으로 나누어 2회로 세지 않는다.

## 3. 시연 화면 `/`

### 화면

- 프로젝트 제목/로고 영역은 제공된 스케치를 기준으로 배치한다.
- 카메라 원본 종횡비를 유지한다. 십자선은 여백을 제외한 실제 영상 영역의 정중앙에 둔다.
- `Trial 0 / 20`, `Y 0.000 mm`, `T 0.000°`에서 시작한다.
- 상태: 준비 필요 / 시작 위치로 이동 중 / 보정 대기 / 보정 중 / 보정 완료 / 최대 시도 도달 / 중단 / 오류.
- 카메라 및 제어기 연결 상태를 표시한다. 영상 연결 단절 시 이전 프레임이 실시간인 것처럼 남지 않게 표시한다.
- 시나리오 이름, 시작 좌표, 전체 보정표, 다음 명령값, 전체 단계 수는 화면과 시연용 API 응답에서 제외한다.
- 현재 보정 명령은 실제 수락 시점에만 표시하며, 사전 숫자 애니메이션은 사용하지 않는다.
- 실행 중 정지할 수 있는 별도 `정지` 동작을 제공한다.

### Random

1. 카메라/STM32 준비 상태, 원점 설정, 사용 가능한 검증 시나리오를 확인한다.
2. 서버가 실행을 잠그고 시나리오 버전을 고정한다.
3. Trial=0, Y=0, T=0으로 초기화한다.
4. 저장된 시작 절대 좌표로 이동 명령을 전송한다.
5. ACK 이후 DONE(OK) 및 시작 좌표 도달을 확인하면 '보정 대기'로 전환한다.
6. 시작 위치 이동 중에도 보정값 표시는 0을 유지한다.
7. 실패하면 오류 상태로 전환하고 자동보정 시작을 막는다.

### 자동보정

1. '보정 대기'에서만 실행할 수 있다.
2. 현재 단계의 상대 Y·T 이동량을 보낸다.
3. ACK 시 Trial을 1 증가시키고 해당 명령값을 표시한다.
4. DONE의 SEQ, 명령 종류, 결과를 확인한다.
5. DONE(OK) 이후 중앙 도달 조건을 검사한다.
6. 중앙 도달 조건 충족 시 이후 단계를 보내지 않고 종료한다.
7. 미도달이면 설정된 안정화 대기 후 다음 단계를 실행한다.
8. Trial 20 이후에는 추가 이동을 보내지 않는다. 20번째에서 중앙 도달하면 성공, 그렇지 않으면 '최대 시도 도달'이다.
9. 20회 이전에 시나리오가 끝났지만 중앙 좌표 조건을 충족하지 못하면 '시나리오 종료·미도달'로 처리한다.

실행 중 Random/자동보정 중복 클릭, 여러 브라우저의 동시 요청은 서버에서도 거부한다.
페이지 새로고침은 진행 중인 상태를 다시 구독하며 새로운 이동을 발생시키지 않는다.

## 4. 중앙 도달과 완료 조건

장치의 원점과 카메라 영상의 중앙 정렬 위치는 서로 다를 수 있다.
관리자가 실제 영상으로 중앙 정렬을 확인한 Y·T 절대 좌표를 별도로 저장한다.

시나리오에는 중앙 좌표, 각 축 허용 오차, 기준 설정 버전, 실제 장비 검증 기록을 연결한다.
실행 시 완료 조건은 다음과 같다.

1. 실제 장비로 사전 검증된 시나리오다.
2. 해당 보정 명령의 DONE 결과가 OK다.
3. STM32가 보고한 완료 좌표가 저장된 중앙 좌표의 Y·T 허용 오차 안에 있다.
4. 중단, 통신 오류, 리밋 또는 장치 재부팅이 발생하지 않았다.

이 조건은 사전 검증된 중앙 좌표 도달을 뜻한다. STM32 보고 좌표가 스텝 기반이면 실측 위치를 보장하지 않으며,
카메라에서 현재 타깃의 중앙 정렬을 매번 자동 검출하는 기능은 이번 범위에 포함하지 않는다.
영상으로 매번 성공을 보장해야 한다면 타깃 검출 및 영상 오차 판정 기능을 추가해야 한다.
카메라 위치·크롭·배율·기구 배치·원점 기준이 바뀌면 기존 검증을 무효화하고 다시 검증한다.

## 5. 관리자 화면 `/admin`

별도 사이트를 중복 운영하지 않고 같은 서버의 로그인 전용 페이지로 구성한다.
URL을 숨기는 것만으로 접근을 제한하지 않으며, 관리자 API도 서버에서 인증한다.

### 시나리오 관리

- 목록, 생성, 수정, 복제, 삭제, 활성화/비활성화.
- 시나리오 이름, 설명, 재생 순서.
- 시작 절대 좌표 Y·T.
- 단계별 상대 보정량 Y·T, 안정화 대기시간. 최소 1단계, 최대 20단계.
- 중앙 기준 좌표와 허용 오차, 기준 설정 버전.
- 검증 상태: 초안 / 검증 완료 / 재검증 필요.
- 작성·수정 시간, 버전, 검증 기록.
- JSON 내보내기/가져오기로 백업 및 재사용. 가져온 값도 동일한 검증을 통과해야 한다.

### 사전 등록·검증 흐름

1. 실제 장비의 원점 설정과 중앙 정렬 위치를 확인한다.
2. 관리자가 시나리오 시작 좌표와 단계별 보정값을 입력한다.
3. 입력값과 예상 이동 경로를 검증하고 초안으로 저장한다. 저장 자체는 장치를 움직이지 않는다.
4. 명시적인 관리자 시험 실행으로 시작 위치 이동과 각 보정 단계를 검증한다.
5. 시험 실행에서는 카메라, 현재 명령, 응답, 단계 이력을 보여준다. 한 단계씩 실행할 수도 있다.
6. 관리자가 최종 영상의 중앙 정렬을 확인하고 검증 완료로 등록한다.
7. 검증된 시나리오를 재생 목록에 활성화한다.
8. 실행 중에는 고정된 시나리오 버전을 사용한다. 수정본은 다음 실행부터 적용한다.

기본 입력 검증: 유한한 숫자, 정수 통신 단위로 표현 가능한 정밀도, 1~20단계,
각 단계의 예상 절대 위치가 GET_CONFIG의 허용 범위 내인지, 마지막 예상 좌표가 중앙 허용 오차 내인지 확인한다.
0·0 이동으로 Trial만 늘리는 단계는 허용하지 않는다.
시작 좌표 또는 보정값·기준 설정이 바뀌면 검증 완료 상태를 해제한다.

## 6. 시스템 구성

```text
발표용 브라우저 / 관리자 브라우저
          │ HTTP + 상태 이벤트 + 카메라 스트림
          ▼
Raspberry Pi 로컬 웹 서버
  ├─ 시연 상태 및 단일 실행 관리자
  ├─ 시나리오 저장소 (SQLite 제안)
  ├─ 카메라 스트림 (기존 Picamera2/MJPEG 코드 활용)
  └─ STM32 통신 어댑터
          │ 기존 robot_stage 통신 규약
          ▼
        STM32 → Y·T 모터 제어
```

- UI: HTML/CSS/JavaScript 기반의 가벼운 화면을 우선한다.
- 서버: Python 기반 웹 서버를 제안한다. 구현 시 설치 환경을 확인해 프레임워크를 확정한다.
- 상태 전송: SSE를 기본안으로 사용하고 조작 요청은 HTTP POST로 분리한다.
- SQLite에는 시나리오·버전·실행 이력을 저장한다. DB 및 관리자 비밀정보는 Git에서 제외한다.
- 영상 녹화는 기본적으로 하지 않는다. 카메라는 한 프로세스에서 열어 여러 브라우저에 공유한다.
- 초기 카메라 설정 후보는 기존 스트리밍 코드의 640×480, 10fps다. 실제 발표 화면에서 선명도·지연을 보고 조정한다.
- 관리자 인증은 비밀번호 해시, 서버 세션, 변경 요청 CSRF 방어를 적용한다.
- 시나리오 전체 자료는 관리자 API에서만 반환한다. 정적 JS에 시나리오 값을 포함하지 않는다.
- 시연 조작도 운영자 세션/접근 제어를 적용하여 단순 시청자가 장치를 움직이지 못하도록 한다.
- 발표 장소의 인터넷 연결 없이 로컬 자산으로 동작하도록 구성한다.

## 7. STM32 통신 연동

기준 문서: `STM32/robot_stage_protocol.md`, 공용 헤더: `STM32/robot_stage_protocol.h`.

현재 저장소 문서상 규약:

- USB ST-LINK 가상 COM, `/dev/ttyACM0`, 115200bps, 8N1.
- Y는 µm 정수, T는 0.001° 정수.
- MOVE_ABS/MOVE_REL은 Y·T 두 축 값을 함께 전송한다.
- ACK는 명령 수락이며 DONE은 이동 종료다. ACK만 받고 다음 이동을 보내지 않는다.
- DONE 결과 OK/STOPPED/LIMIT/FAULT를 구분한다.
- CRC16, SEQ 대응, 응답 제한시간 및 중복 실행 방지 규칙을 준수한다.
- 초기 응답 유실 시 규약의 같은 SEQ 재전송을 적용하되, 재전송 책임은 한 통신 계층에만 둔다.
- DONE 제한시간 초과 시 이동 명령을 새로 보내지 않고 상태를 조회한다. IDLE만으로 성공을 추정하지 않는다.
- 중복 명령 재전송 확인 중에는 다른 조회가 펌웨어의 최근 명령 캐시를 덮어쓰지 않도록 통신을 직렬화한다.
- STOP/리밋/고장/BOOT 발생 시 다음 단계를 중단한다. 재접속이나 서버 재시작 후 자동으로 이동을 재개하지 않는다.
- 연결 단절 상태에서는 웹에서 정지 명령을 전달할 수 없으므로 장치 정지 여부를 확인 필요 상태로 표시한다.

커널 드라이버 또는 기존 사용자 공간 API를 우선 조사해 재사용한다.
드라이버가 점유한 동일 시리얼 포트를 웹 서버가 동시에 직접 열지 않는다.
현재 브랜치에는 드라이버 빌드 산출물이 남아 있으나 소스 연동 경로는 구현 전에 확인해야 한다.
펌웨어 교체나 모터 제어 방식 변경은 웹 개발과 분리한다.

| API | 역할 |
| --- | --- |
| GET /api/state | 현재 상태, Trial, 현재 표시 명령값, 연결 상태 |

| POST /api/admin/login, /logout | 관리자 로그인/로그아웃 |
| GET/POST /api/admin/scenarios | 시나리오 목록/생성 |
| GET/PUT/DELETE /api/admin/scenarios/{id} | 상세/수정/삭제 |
| POST /api/admin/scenarios/{id}/test | 관리자 시험 실행 |
| POST /api/admin/scenarios/{id}/verify | 시험 결과 및 관리자 확인 기록 |
| GET/PUT /api/admin/settings | 중앙 기준 및 재생 목록 설정 |

명령 요청에는 중복 방지 키를 사용한다. 같은 HTTP 요청 재시도로 실제 이동이 반복되지 않게 한다.
실행 상태는 브라우저가 아니라 서버가 보유한다. 실행 ID와 이벤트 순번으로 재접속 시 상태를 동기화한다.

## 9. 구현 순서와 완료 기준

1. 기존 카메라/드라이버/펌웨어 연결 경로 확인, 데이터 및 실행 상태 모델 작성.
2. 모의 통신 어댑터로 시연 UI, 관리자 CRUD, 20단계 실행기 구현.
3. 실제 카메라 연결 및 해상도별 십자선 위치 확인.
4. STM32 어댑터 연결, ACK/DONE/오류/재전송/정지 검증.
5. 실제 시나리오 등록, 관리자 사전 검증, 발표 화면에서 반복 시연.

검증 기준:

- Random 이동 중/후 Trial=0, Y=T=0이며 다음 보정값이 시연용 응답에 포함되지 않는다.
- Trial은 수락된 보정 단계마다 한 번 증가하고, 재전송/중복 클릭에는 증가하지 않는다.
- Y·T는 해당 Trial의 실제 전송 명령값과 일치한다.
- DONE 전에 다음 단계가 실행되지 않는다.
- 1회/여러 회/20회 성공 및 20회 미도달을 구분한다. 21번째 명령은 전송되지 않는다.
- 중앙 미도달, NAK, DONE 오류, 연결 단절을 성공으로 표시하지 않는다.
- 관리자 미인증 요청은 시나리오를 조회·변경할 수 없다.
- 페이지 새로고침과 다중 브라우저 접속으로 이동이 중복되지 않는다.
- 실행 중 시나리오 수정이 현재 실행 명령을 바꾸지 않는다.
- 브라우저를 닫아도 실행 상태는 서버에서 일관되게 관리하고, 서버 재시작 후 자동 재개하지 않는다.
- 실제 영상과 STM32 연결이 없는 모의 실행은 개발/관리자 환경에서 명확히 구별한다.

## 11. 1차 구현 반영 (2026-11-09)

- 사용자 확인: T축 모터 미입고로 비활성 상태가 맞다. 실물 모드는 T=0인 Y축 시나리오만 허용한다.
- `demo_web/`에 Flask/Waitress + SQLite + HTML/CSS/JavaScript 기반 로컬 웹을 구현했다.
- 시연 화면, 인증된 관리자 CRUD, 단계별 시험, 자동 실행, 검증/활성화, JSON 백업 및 실행 이력을 구현했다.
- 모의 모드에서 T 명령 흐름은 시험할 수 있으나 화면에 모의 통신을 표시하고 실물 검증과 구분한다.
- 실물 통신은 기존 `/dev/robot_stage` ioctl 규약을 사용한다. 시리얼 포트를 직접 열거나 드라이버·펌웨어를 변경하지 않는다.
- 카메라 설정은 발표 화면용 960×720, 10fps로 구현했다. 실제 연결 후 화질과 지연을 확인해야 한다.
- 서버 재시작은 실행을 중단 상태로 기록한다. 실물 원점 복귀는 기존 도구에서 수행하며 웹에서 자동 실행하지 않는다.
- 중앙 기준 변경은 전체 검증을 해제한다. 백업 가져오기는 현재 중앙 기준에서 초안으로만 등록한다.
- 실행 안내와 실물 연동 조건은 [demo_web/README.md](../demo_web/README.md)에 정리했다.
- 디자인 수정: 시연·관리자 화면은 흰색 배경과 `#0A3D91` 강조색을 사용한다. 시연 화면 왼쪽 상단 문구는 `SSAFY X SEMES = A507`로 표시한다. 중앙 십자선은 빨간색으로 유지한다.
- 후속 점검: 명령 직전 및 안정화 대기 이후에 카메라·제어기·원점 상태를 재확인한다. 정지 전송 실패를 실행 이력에 남기고 후속 취소 처리에서도 오류 표시를 유지한다. 관련 회귀 테스트 4개를 추가했다.

## 12. 카메라 해상도·Y축 수동 시험 반영 (2026-11-09)

기존 11절의 카메라 및 통신 제약을 다음 내용으로 대체한다.

- IMX477 원본 4056×3040 12bit 센서 모드를 사용한다. 웹 JPEG 기본값은 4056×3040 5fps다.
- 관리자에서 카메라 사용 여부와 원본/2028×1520 10fps/960×720 10fps를 설정하고 DB에 저장한다.
- SEMES용 왜곡 보정·크롭·3840×2160 변환은 웹 스트림에 포함하지 않는다.
- 해상도 변경은 시나리오 검증·활성화를 해제하고 기준 버전을 올린다.
- 관리자에서 모의/실물 모드와 USB 직접 연결/기존 커널 드라이버를 선택한다. 연결 적용은 상태·리밋 조회만 수행한다.
- Y 원점 복귀(HOME mask=1), ±수동 이동(MOVE_REL, T=0), STOP을 제공한다.
- 수동 이동 기본 0.100mm, 1회 최대 1.000mm. 원점·IDLE·STM32 리밋·비활성 T좌표를 검사한다.
- 수동 시험은 카메라 없이 허용하며 Trial에는 포함하지 않는다. 수동 이력으로 시나리오 검증은 불가하다.
- 시나리오 준비/실행 중 설정 변경과 수동 시험을 금지한다. 서버 재시작 시 장치 모드는 기본 mock이며 자동 HOME은 없다.
- 직접 USB 어댑터는 115200/8N1, CRC16, SEQ, ACK 재전송 최대 3회, DONE 원명령 대응, 동시 STOP을 구현한다.
- BOOT 및 통신 오류는 실행을 중단한다. DONE 타임아웃 시 조회만 하고 이동을 재전송하지 않는다.
- 기존 커널 드라이버 연결은 유지하며 직접 UART 연결과 동시에 사용하지 않는다.
- 실제 카메라 세 해상도와 STM32 상태/리밋 조회 확인 완료. 실제 원점 복귀·Y 모터 이동은 실행하지 않았다.

## 13. 웹 영상 렌즈 왜곡 보정 (2026-11-09)

12절의 미보정 스트림을 다음 내용으로 갱신한다.

- `demo_web/calibration/camera_calib.yml`에 팀의 IMX477 4056×3040 캘리브레이션 원본을 포함한다.
- 기본은 왜곡 보정 켜짐이다. 관리자에서 보정 켜기/끄기를 선택하여 원본과 비교할 수 있다.
- 카메라 프레임을 JPEG로 인코딩하기 전에 OpenCV remap으로 보정한다. 여러 시청자가 같은 프레임을 공유한다.
- 실제 ScalerCrop(캘리브레이션 기준 8,16,4056,3040)과 출력 크기로 내부 행렬을 조정한다.
- 변환표는 영상 기하별로 재사용하며 원본 해상도·출력 내부 행렬·중앙 십자선 위치는 유지한다.
- SEMES용 크롭·광학 중심 재배치·3840×2160 변환은 별도 기능이며 이번 변경에 포함하지 않는다.
- 카메라 API GET/PUT에 boolean `undistort`를 추가한다. 생략 시 현재 설정을 유지한다.
- 설정은 DB에 보존한다. 해상도·보정 여부·보정 파일 해시 변경은 기존 검증과 활성화를 해제한다.
- 이전 미보정 버전의 시나리오도 최초 시작 시 검증을 해제한다. 저장된 시나리오 수치는 보존한다.
- 보정 처리 실패는 영상 오류로 표시하며 미보정 프레임을 보정 영상으로 노출하지 않는다.
- 자동 테스트 61개 통과. 기존 보정 예시와 픽셀 차이 0, 실제 카메라의 세 해상도에서 보정 프레임 수신 확인.
- 파라미터는 RMS 1.68px의 잠정값이다. 렌즈·초점 변경 및 정밀 시연 전에는 재캘리브레이션/기준 검증이 필요하다.

## 14. 실물 Y 원점 복귀·STM32 명령 패널·영상 지연 (2026-11-09)

- **Y 원점 복귀(HOME mask=1)는 서버 모드와 관계없이 실제 STM32에서 실행한다.** `rsctl home 1`과 같다.
  시연 화면(운영자 로그인)과 관리자 화면에 버튼이 있다. 모의 모드에서는 원점 복귀 동안만 `/dev/robot_stage`를 열고 닫는다.
- 관리자에 **STM32 명령 · rsctl과 동일** 패널을 추가했다. ping / status / config / home 1 / move-rel / move-abs / speed / stop을
  rsctl 단위 그대로 실제 장치에 보낸다. ACK/NAK는 요청 안에서 즉시 응답하고 DONE은 백그라운드에서 기다린다.
  원점·범위 검사는 STM32가 하며 T 값도 그대로 전달한다(현재 펌웨어는 T≠0이면 BAD_PARAM).
- 실물 원점 복귀나 이동 중 정지는 그 동작을 수행하는 실제 장치로 STOP을 보낸다.
- 기본 연결 방식은 커널 드라이버(`--transport driver`)다. USB 직접 연결은 ldattach를 쓰지 않을 때만 사용하며,
  `/dev/serial/by-id/` ST-LINK 경로를 쓰므로 ttyACM 번호가 바뀌어도 동작한다.
- 웹 서버 사용자 권한: `/dev/robot_stage`(root 0600)에 pi 사용자 ACL만 추가하는 udev 규칙을 사용한다. 소유자와 모드는 바꾸지 않는다.
- 영상 지연 원인은 waitress 연결당 16MB 출력 버퍼와 카메라 버퍼 6개였다. 송신 버퍼를 256KB로 줄여 최신 프레임만 보내고,
  카메라 버퍼는 3개로 줄였다. 10Mbit/s 측정 결과 원본은 10~14초에서 약 1.5초로, 축소 2028×1520은 0~0.4초로 줄었다.
  발표 화면에는 축소 해상도를 권장한다.
- 자동 테스트 71개 통과. 실제 장치에는 ping/status/config 조회만 수행했다. 웹을 통한 실물 HOME·이동은 시험 전이다.
