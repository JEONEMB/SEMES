# 03. 상태와 알림

현재 공개 API와 실제 구현을 기준으로 작성한다. 알림의 문구보다 status, correction_allowed, action과 notices를 우선 사용한다.

## 1. 결과 처리

| 필드 | 의미 |
|---|---|
| status | Ok, Warning, Failed |
| correction_allowed | 운영 측정에서 영점이 유효하고 보정 금지 조건이 없을 때만 true |
| action | Correct: 보정 가능, Review: 운영자 확인, Recapture: 원인 확인 후 재촬영, Stop: 정지 |
| notices | 발생한 모든 알림의 상태, 코드, 문구, 조치 |
| code | 가장 제한적인 조치의 대표 코드. 같은 조치이면 먼저 추가된 코드 |
| message | 모든 알림을 / 로 연결한 설명 |

조치 우선순위는 Stop > Recapture > Review > Correct이다. W_SCREW_MISSING이 함께 있어도 불일치나 범위 초과가 있으면 보정하지 않는다. Failed 결과의 Y와 T는 NaN이다. 값을 0으로 대신하지 않는다.

measure_diagnostic은 영점 없이도 측정하며, 기존 영점이 있으면 그 영점을 반영한다. 진단 결과의 correction_allowed는 항상 false다. 진단 결과를 로봇 이동에 쓰지 않는다. initialize와 영점 설정 함수의 성공 반환도 이동 명령이 아니다.

## 2. 실패 코드와 출력

{...}는 실행 중 채워지는 세부 정보다. 로더와 검출기의 상세 원인은 원문을 보존한다. 모든 실패는 보정 금지와 Stop이다.

| 코드 | 출력 문구 또는 형식 | 조치 |
|---|---|---|
| E_NOT_INITIALIZED | 초기화 완료 전 호출 | initialize 성공 후 다시 시작 |
| E_ZERO_REQUIRED | 유효한 영점이 없습니다. 명령 0에서 촬영한 사진으로 영점을 설정하세요. | 당일 영점 설정 |
| E_ZERO_VALUE | 영점 값이 유효하지 않습니다. Y와 T는 유한한 숫자여야 합니다. 영점을 다시 설정하세요. | 숫자와 기준 확인 후 영점 재설정 |
| E_NUMERIC | 유효하지 않은 계산값입니다. 보정을 중단하세요: {계산 단계} | 모델과 입력 확인, 로그 보존 |
| E_SETTINGS | {설정 파일 경로와 형식 오류} | 설정 수정 후 초기화 |
| E_DATA | {모델 경로와 필수 파일, 행, 숫자 또는 범위 오류} / 초기화 중 오류: {내용} | 모델 전체 확인 후 초기화 |
| E_PHOTO | 사진이 비어 있습니다 / 사진이 한 장도 없습니다 / 입력 해상도 {크기} (요구 3840×2160) / 입력 화소 형식 불일치 (요구 8비트 부호 없는 정수) / 입력 채널 수 {개수} (허용 1, 3, 4) | 입력과 카메라 설정 확인 |
| E_QR_NOT_FOUND | {봉우리 개수, 간격 또는 정밀 검출 실패 원인} | QR 가림과 반사 확인 후 재촬영 |
| E_SCREW_PARTIAL | 나사 {번호}: {일부 가림 또는 오염 의심 원인} | 나사 확인 후 재촬영 |
| E_ZERO | {영점 사진의 검출 실패 원인}, 운영용 영점 무효화 / 영점 사진 점검에 실패했습니다. 가림과 촬영 자세를 확인하세요. | 명령 0에서 다시 촬영 |
| E_REFERENCE | {기준 재등록 실패 원인} | 기준 사진 확인 후 재등록, 영점 재설정 |
| E_INTERNAL | 측정 중 오류: {내용} / 영점 잡는 중 오류: {내용} / 기준 다시 잡는 중 오류: {내용} | 운영 중단, 사진과 로그 보존 |

E_DATA는 점검식 11개와 계수 16개를 필수로 검사한다. 빈 파일, 중복 행, 필수 행 누락, 조합 불일치, 비정상 숫자, 0 이하 scale이나 threshold를 거부한다. reference.json은 영상 좌표와 학습 범위를 검사한다. 오류가 있는 모델로 측정을 시작하지 않는다.

## 3. 경고 코드와 출력

| 코드 | 출력 문구 | 조치 |
|---|---|---|
| W_COARSE | 좌우 나사 조합 미확보, 대략값 반환 ({사용 나사}) | Review, 자동 보정 금지 |
| W_VALUES_DISAGREE | 일치 점검값 {값}, 한계 {한계} 초과 (최대 편차 항목 {항목}) | Recapture, 보정 금지 |
| W_SCREW_MISSING | 나사 {번호 목록} 미검출, {사용 나사} | 다른 금지 조건이 없고 영점이 유효한 운영 측정이면 Correct |
| W_OUT_OF_RANGE | 영점 차감 전 학습 범위 초과 ({축, 값, 단위, 범위}) | Review, 자동 보정 금지 |
| W_ZERO_RESET | 기준이 변경되었습니다. 명령 0에서 영점을 다시 설정하세요. / 기존 기준에서 측정값 또는 좌우 나사 조합 미확보, 새 기준 사진을 영점으로 설정 | Review, 영점 재설정 전 운영 측정 차단 |

fail_on_disagreement가 1이면 W_VALUES_DISAGREE의 상태는 Failed, 조치는 Stop이며 Y와 T도 NaN이다. 이 설정이 0이어도 불일치 결과로 보정할 수 없다.

W_ZERO_RESET의 두 번째 문구는 좌표 연결용 내부 기준값을 뜻한다. 이 값으로 운영용 영점이 유효해지는 것은 아니다. 기준 등록 성공과 실패 모두 영점을 다시 설정해야 한다.

## 4. 영점과 초기화

initialize 성공 직후 영점은 미설정이다. initialize 실패 후에는 기존 모델로도 측정하지 않는다. set_zero_from_photos 실패, 잘못된 set_zero_value, clear_zero, 기준 재등록 시도는 영점을 무효화한다. 숫자가 메모리에 남아 있어도 운영 측정은 E_ZERO_REQUIRED로 차단한다. 기준 재등록 중 계산 오류나 예외가 발생하면 초기화 상태도 무효화하므로 initialize부터 다시 수행한다.

set_zero_value는 Result를 반환한다. 같은 모델과 기준 좌표의 유한한 영점만 지정해야 한다. 사진 기반 점검 기준은 삭제되므로 새 기준의 영점을 복원하는 용도로 임의 사용하지 않는다. 실제 명령 0에서 촬영한 사진으로 설정하는 방법을 권장한다.

매일 작업 시작 시 clear_zero를 호출하고 당일 사진으로 설정한다. 라이브러리는 달력 날짜나 교대 시간을 자동으로 판단하지 않는다. 장비 프로그램이 작업 시작 절차를 관리해야 한다.

## 5. 연동 예제

```cpp
auto ready = alignment::initialize("data/model");
if (ready.status == alignment::Status::Failed) return;
auto zero = alignment::set_zero_from_photos(zero_photos);
if (zero.status == alignment::Status::Failed) return;
auto result = alignment::measure_alignment(photo);
if (!result.correction_allowed) {
    // action과 notices를 기록하고 해당 조치를 수행한다.
    return;
}
// 검증된 장비 좌표 변환과 이동 제한을 적용한 뒤 보정한다.
```

실제 로봇 이동 부호, 이동량 제한, 반복 횟수와 비상정지는 장비에서 별도 검증해야 한다. 허용오차 이내인지 여부는 정답이 있는 평가에서만 확인할 수 있다.

## 6. 회귀 검증

```powershell
cmake --build build --config Release
ctest --test-dir build -C Release --output-on-failure
```

safety_contract는 미설정 영점, 영점 실패 뒤 차단, NaN과 무한대, 모델 파일 누락과 손상, 복합 경고, 엄격 실패 설정, 계산 오버플로, UTF-8 모델 경로를 검사한다. 테스트 변형 모델은 build 아래 고유한 safety_cases 폴더에 보존된다.

이전 N_WIDE_SEARCH, W_QR_PARTIAL, W_FAR 코드는 더 이상 사용하지 않는다.
