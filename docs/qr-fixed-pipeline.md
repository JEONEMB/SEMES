# 고정 파이프라인 리팩토링 검증

기존 재시도 기반 구현을 고정된 처리 순서로 변경했다. 이 변경은 포매팅만이 아니라 검출 알고리즘의 변경도 포함한다.

## 변경

- 플레이트: 가로선 180px→100px 재시도를 삭제했다. 허프 조각을 방향·직선 거리·구간 간격 조건으로 병합한 후, 병합 가로선 길이 300px 및 기존 사각형 크기·에지 지지도·명암 조건으로 한 번 탐색한다.
- QR decode: 원본/확대/라벨/가우시안을 바꿔가며 시도하던 분기를 삭제했다. 고정 전처리 후 detectAndDecode 한 번만 실행한다.
- Gaussian은 디코딩 복사본에만 적용한다. 특징점은 원본 영상에서 정밀화한다.
- BSD/Allman 스타일 및 4칸 들여쓰기를 .clang-format으로 고정했다. 외부 qrcodegen 소스의 원문 스타일·라이선스는 유지했다.
- 플레이트·ROI·디코딩·모델·정밀화·시각화를 파일과 함수로 분리했다. 기존 공개 인터페이스와 실행 인자를 유지했다.

## 고정 전처리 선택 근거

기존 알고리즘에서 추출한 843개 ROI에 18개 조합을 비교했다. 여기서의 조합 비교는 오프라인 개발 검증이며, 실행 시 후보들을 순회하지 않는다. 아래 값은 올바른 payload가 나온 QR 수다.

| Gaussian sigma | 확대 | 라벨 재크롭 | 성공 |
|---|---:|---|---:|
| 없음 | 2배 | 없음 | 843/843 |
| 0.6 | 2배 | 없음 | 843/843 |
| 0.9 | 2배 | 없음 | 843/843 |
| 0.6 | 2배 | 있음 | 841/843 |
| 0.9 | 2배 | 있음 | 841/843 |

선택한 방식은 Gaussian 3×3, sigma 0.6 → 2배 선형 확대 → 흰 테두리 32px이다. Gaussian 없는 경우도 이 ROI 세트에서는 모두 성공했으므로, 개선을 Gaussian 단독 효과로 해석하지 않는다. 확대율과 여백을 포함한 고정 조합의 결과다.

## 전체 파이프라인 검증

새로운 직선 병합으로 ROI가 달라질 수 있으므로 ROI 단독 비교에 그치지 않고 원본 281장 전체를 다시 처리했다. 플레이트 281/281, QR 3개 디코딩·모델 대응·특징점 검증 281/281, 슬롯 843/843이었다. 파일명은 메타데이터로만 사용했으며 절대 실측 정답으로 취급하지 않았다. source의 픽셀/mm 보정이나 Y/θ 최종 추정은 추가하지 않았다.

기존 성공률을 유지했지만 이전 파이프라인과 측정 좌표가 완전히 동일한 리팩토링은 아니다. 디코딩 입력과 초기 외곽이 달라져 정밀화 초기값도 바뀐다. 이 검증은 검출 누락/오류 코드/모델 일치 검사이며, 0.05mm·0.01도 정확도 인증은 아니다. GUI 시각화 파일은 확인했으나 실제 키 입력 흐름은 별도 확인이 필요하다.

추가 검사: 기존 center와 두 과거 플레이트 실패 이미지의 실행 성공, 입력 누락/없는 파일/잘못된 옵션의 종료 코드 1, 흰 빈 영상의 플레이트 실패 종료 코드 2, PNG 확장자·저장 검사, clang-format dry-run 검사.
