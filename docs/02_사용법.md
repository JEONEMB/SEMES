# 02. 사용법

> 정확도 수치를 읽기 전에 [평가 조건과 재실행 결과](06_평가_방법/6-1_정확도.md)를 확인한다. 내부 계수 실험의 전처리 라벨, 근처 자세로 추정한 영점, 실제 center 사진을 사용하는 평가는 서로 다르다. 정상 상태도 허용오차 통과를 보장하지 않는다.


담당자가 처음 패키지를 받았을 때, 동봉 예시 사진으로 실행하고 결과를 확인하는 순서입니다. 먼저 10월 14일 예시를 완료한 다음 10월 20일 예시를 실행합니다.

[1] PowerShell에서 패키지 폴더로 이동합니다.

현재 개발 PC에서는 아래 명령을 그대로 입력합니다. 다른 PC에서는 내려받은 semes 폴더 경로로 바꿉니다.

```powershell
cd "C:\Users\SSAFY\Desktop\hwlee\projects\2026-10_SEMES\semes"
Test-Path ".\build\Release\score_photos.exe"
```

True가 나오면 [2]로 진행합니다. False라면 아래 '1. 빌드와 확인' 절차를 완료하고 여기로 돌아옵니다.

예시 사진은 이미 들어 있습니다. 따로 복사하거나 정답표를 만들 필요가 없습니다.

```text
data/examples/
  20261014/
    center/   기준 사진 1장 (center.png)
    photos/   평가 사진 6장 (Y 이동과 T 이동 사진)
  20261020/
    center/   기준 사진 1장 (center1.png)
    photos/   평가 사진 3장
```

폴더 내용을 먼저 보고 싶으면 다음 명령을 입력합니다.

```powershell
explorer.exe "$PWD\data\examples"
```

[2] 평가 프로그램을 실행합니다.

```powershell
./build/Release/score_photos.exe
```

이후 경로를 콘솔에 타이핑하지 않습니다. 뜨는 창에서 기준 사진, 평가 사진, 정답 방식을 차례로 선택합니다.

[3] 10월 14일 기준 사진을 선택합니다.

1. '[1] 기준 사진(center)을 선택하세요' 창에서 '사진 선택'을 클릭합니다.
2. 파일 선택 창은 data/examples에서 시작합니다. `20261014` 폴더를 열고 그 안의 `center` 폴더를 엽니다.
3. `center.png` 한 장을 클릭한 뒤 '선택 완료'를 누릅니다.

선택할 파일은 `data/examples/20261014/center/center.png`입니다. 이 예시에서 Y 0, T 0의 기준으로 사용할 사진입니다.

[4] 같은 날짜의 평가 사진 6장을 선택합니다.

1. '[2] 평가 사진을 선택하세요' 창에서 '사진 선택'을 클릭합니다.
2. 파일 선택 창이 `data/examples/20261014/photos`에서 열리는지 확인합니다.
3. 사진 목록을 클릭하고 Ctrl+A를 눌러 아래 6장을 모두 선택합니다.
4. '선택 완료'를 누릅니다.

```text
T-0.01.png
T-0.02.png
T-0.03.png
Y-0.05.png
Y-0.10.png
Y-0.20.png
```

폴더째 선택하고 싶으면 각 선택 단계에서 '폴더 선택'을 누릅니다. 기준은 `20261014/center`, 평가는 `20261014/photos` 폴더를 선택합니다. 날짜 폴더 전체나 data/examples 전체를 고르지 않습니다. 기준은 center, 평가는 photos입니다.

[5] 정답 방식을 선택합니다.

'[3] 정답을 어떻게 읽을까요?' 창에서 '사진 파일명 사용'을 클릭합니다. 동봉 예시에는 이름에 Y 또는 T 값이 있으므로 TSV를 선택하지 않습니다. Y만 있는 이름은 T 0도, T만 있는 이름은 Y 0 mm로 읽습니다.

[6] 콘솔에서 입력 내용을 확인하고 시작합니다.

선택 창이 닫히면 콘솔로 돌아옵니다. '평가할 사진: 6장', '영점 사진: 1장'인지 확인합니다. 프로그램에서 말하는 영점 사진이 앞에서 선택한 center입니다. '시작할까요?'에서 Enter를 누릅니다. 장수가 다르면 n을 입력해 취소하고 [2]부터 다시 선택합니다.

[7] 평가 결과를 확인합니다.

동봉 모델과 위 예시를 그대로 사용한 확인 결과입니다. 속도와 결과 폴더의 날짜, 시간은 실행할 때마다 달라집니다.

```text
기준 1: Y +/-0.045 mm, T +/-0.01 도
  전체 통과율: 100.0% (6/6) / IN 6 / OUT 0 / 실패 0
기준 2: Y +/-0.09 mm, T +/-0.01 도
  전체 통과율: 100.0% (6/6) / IN 6 / OUT 0 / 실패 0
영점: 적용
```

두 기준은 동일한 예측값을 서로 다른 허용오차로 판정합니다. 경고 없는 통과율과 경고 없이 OUT인 건수도 함께 표시됩니다. 전체 통과율은 실패를 포함한 평가 대상 전체를 분모로 삼습니다. 실패는 IN/OUT 판정에서 제외하고 별도 표시합니다.

[8] 실행을 마치고 결과 폴더를 엽니다.

1. 마지막 'Enter를 누르면 끝납니다'에서 Enter를 누릅니다.
2. PowerShell 입력 표시가 다시 나오면 방금 출력된 `explorer.exe "전체 결과 폴더 경로"` 명령을 복사해서 실행합니다. 설명의 경로를 그대로 치는 것이 아니라 실제 출력된 명령을 사용합니다.
3. 열린 폴더에서 results.csv를 Excel로 엽니다.

```text
data/results/eval/실행날짜_시간/
  inputs/
    center/     선택한 기준 사진 사본
    photos/     선택한 평가 사진 사본
  inputs.txt    선택한 원본과 사본 경로
  results.csv   사진별 정답, 예측값, 오차, 두 기준 판정
  summary.txt   전체 평가 조건과 통과율
  logs/         사진별 단계와 추출값, 경고, 실패를 기록한 TXT
```

CSV의 `판정 Y0.045 T0.01`과 `판정 Y0.09 T0.01`에서 각각 IN인지 확인합니다. 사진의 상세 과정을 보려면 같은 행의 `상세 로그`에 적힌 TXT를 엽니다. 새 실행은 새 날짜와 시간 폴더에 저장하며 같은 초에는 번호를 붙입니다. 원본 예시 사진은 바뀌지 않습니다.

[9] 10월 20일 예시를 실행합니다.

```powershell
./build/Release/score_photos.exe
```

이번에는 기준 사진으로 `data/examples/20261020/center/center1.png`를 고릅니다. 다음 창에서 `data/examples/20261020/photos`의 사진 3장을 모두 선택합니다. 정답 방식은 다시 '사진 파일명 사용'을 선택합니다. 콘솔의 평가 사진 3장, 영점 사진 1장을 확인한 뒤 Enter를 누릅니다.

두 기준 모두 3/3 IN으로 확인한 예시입니다. 3장 중 1장은 학습 범위 경고가 있습니다. 경고는 학습 범위 등의 상태를 뜻하고 IN/OUT은 실제 정답 대비 오차 판정이므로 경고와 IN이 함께 나올 수 있습니다.

[10] 본인 사진으로 바꿔 평가할 때

같은 날짜와 같은 설치 조건에서 촬영한 center와 평가 사진을 선택합니다. center는 평가 원점 (Y 0, T 0)의 자세이며 이름만으로 원점임을 보장하지 않습니다. 장비 명령과 평가 좌표의 원점이 다르면 담당자가 확인한 평가 원점을 사용합니다. 실제 평가용 center는 같은 자세의 사진 5~10장을 권장합니다. 매 실행마다 선택한 center로 영점을 설정합니다.

사진은 3840x2160, 8비트 BMP 또는 PNG를 사용합니다. 파일명에 정답이 없으면 '정답표 선택'으로 UTF-8 탭 구분 TSV를 지정합니다. 열 이름은 file, y_mm, t_deg이며 data/sample/answers.tsv를 형식 참고용으로 사용합니다. 예제 정답을 본인 사진에 사용하지 않습니다.

경로에 날짜나 회차 표시가 있으면 혼합을 검사하지만 표시 없는 사진의 촬영 조건까지 자동으로 알아낼 수는 없습니다. 서로 다른 날의 center를 평균하거나 다른 날짜 사진 전체에 적용하지 않습니다.

동봉 예시는 두 허용오차 기준을 통과하는 정상 실행 연습용으로 선정했습니다. 전체 데이터의 정확도나 독립 검증 결과를 의미하지 않습니다. 원본 BMP를 무손실 PNG로 변환한 예시 11장이며 해상도와 픽셀 값, 측정값 일치를 확인했습니다. 출처는 data/examples/sources.txt에 있습니다.

선택 창에서 취소하면 평가를 시작하지 않습니다. 저장 중 오류가 발생하면 이번 결과 폴더에 일부 파일이 남을 수 있습니다. 명령 인자로 경로를 지정하는 실행은 원본을 직접 읽고 결과만 저장합니다. `--tolerance-y`, `--tolerance-t`는 설정 기준과 기존 CSV 열에 적용되며 고정된 두 기준 비교에는 영향을 주지 않습니다.

center로 영점을 설정하는 작업과 QR 및 나사의 기준 위치 재등록은 별개입니다. 기준 재등록이 필요한 포팅 작업은 3-4절을 따릅니다.

## 1. 빌드와 확인

먼저 README.md가 있는 패키지 폴더에서 PowerShell을 열고 확인합니다.

```powershell
cmake --version
```

버전이 나오면 아래 빌드 명령으로 진행합니다. `cmake`를 찾지 못하면 다음 명령으로 Visual Studio에 포함된 CMake를 찾아 현재 창의 PATH에 추가합니다.

```powershell
$vswhere = "${env:ProgramFiles(x86)}\Microsoft Visual Studio\Installer\vswhere.exe"
if (Test-Path -LiteralPath $vswhere) {
    $cmakeExe = & $vswhere -latest -products * -find 'Common7\IDE\CommonExtensions\Microsoft\CMake\CMake\bin\cmake.exe' | Select-Object -First 1
    if ($cmakeExe) {
        $env:Path = "$(Split-Path -Parent $cmakeExe);$env:Path"
    }
}
cmake --version
```

여전히 버전이 나오지 않으면 빌드를 진행하지 않습니다. Visual Studio Installer의 수정 화면에서 C++용 CMake 도구를 설치하거나, 별도로 설치한 CMake의 bin 폴더를 PATH에 추가한 뒤 새 PowerShell에서 다시 확인합니다. 위 명령의 PATH 변경은 현재 창에만 적용됩니다.

PowerShell을 열 때 `profile.ps1` 실행 정책 오류가 나오면 `powershell -NoProfile`을 입력해 프로필을 읽지 않는 셸에서 진행할 수 있습니다. 이 경우 CMake 확인도 그 셸에서 다시 수행합니다. 프로필 오류와 CMake 경로 오류는 별개이며, 빌드를 위해 시스템 실행 정책을 변경할 필요는 없습니다.

설정과 빌드는 한 번에 붙여 넣지 말고 아래 순서로 실행합니다.

```
cmake -S . -B build -A x64 -T v141 -DOpenCV_DIR="C:/opencv/build"
```

설정이 성공하고 `Build files have been written to`가 나오면 빌드합니다. 오류가 나오면 해결 후 진행합니다.

```powershell
cmake --build build --config Release
```

DLL은 프로그램 실행에 필요한 OpenCV 파일입니다. 검증한 OpenCV 3.4.15 Windows 패키지에서는 빌드할 때 선택된 DLL을 실행 파일 옆에 자동 복사합니다. Release 실행 파일을 전달할 때 같은 폴더의 `opencv_world3415.dll`도 함께 전달합니다. 다른 버전의 DLL을 따로 받아 섞지 마세요. Visual C++ 실행 환경은 받는 PC에서도 필요하며 별도 PC 검증 대상입니다.

위 명령의 OpenCV 경로는 실제 설치 위치로 바꿉니다. v141 C++ 도구 집합과 Windows SDK가 설치되어 있어야 합니다. 다른 도구 집합으로 만든 기존 build 폴더가 있으면 새 빌드 폴더를 사용하세요.

실패와 경고의 현재 문구, 대응 방법, 구현된 차단 기능은 [03 상태와 알림](03_상태와_알림.md)에 모아 두었습니다. 대표 알림 코드만으로 보정 여부를 판단하지 마세요.


개발용 샘플 확인 (선택): 아래 check_photos는 동봉 모델과 샘플 5장의 기대값 재현을 확인합니다. 사용자 사진과 영점을 평가하는 명령은 위의 score_photos입니다. check_photos는 영점 사진 인자를 받지 않습니다.

```
./build/Release/check_photos.exe data/model data/sample/list.tsv auto data/sample/expected.tsv
```

data/model은 동봉 모델, data/sample/list.tsv는 동봉 사진 목록, auto는 data/results/check_photos 아래 새 폴더에 results.tsv를 저장하는 옵션, data/sample/expected.tsv는 동봉 기대값입니다. auto 대신 out.tsv처럼 파일 경로를 지정할 수도 있습니다. 지정한 파일이 이미 있으면 덮어씁니다. 사진마다 예측값, 기대값, 오차, 상태, 시간이 콘솔에 나오고 마지막에 결과 파일의 전체 경로와 explorer.exe 명령을 표시합니다. 이 검사는 별도 영점을 적용하지 않으며 실제 설비의 정확도 검증을 대신하지 않습니다.
콘솔은 `[1/5]`부터 `[5/5]`까지 사진마다 경로, 상태, 처리 시간, 예측 Y/T, 기대 Y/T, 오차를 표시합니다. 경고가 있으면 해당 사진에 코드와 내용을 표시합니다. 측정 실패 시 예측과 오차는 평가 불가, 기대값이 없으면 오차 평가 불가로 표시합니다. 마지막에는 전체 요약과 저장 위치가 나옵니다.

```text
[저장 완료]
  결과 파일: C:\패키지폴더\data\results\check_photos\실행별폴더\results.tsv
  폴더 열기: explorer.exe "C:\패키지폴더\data\results\check_photos\실행별폴더"
```

위 경로는 형식 예시입니다. 실제 콘솔에 출력된 explorer.exe 명령을 복사해 실행하고 results.tsv를 엽니다. auto는 실행마다 새 폴더를 생성합니다. 파일 저장에 실패하면 저장 완료를 표시하지 않고 오류와 함께 종료합니다.

results.tsv에는 사진 번호, 예측 Y/T, 상태 코드, QR와 나사 이동량, 점검값, 처리 시간이 저장됩니다. 기대값과 오차는 이 도구에서는 콘솔에 표시합니다. 정답과 오차가 포함된 평가 CSV 및 사진별 상세 TXT가 필요하면 앞의 score_photos 절차를 사용합니다.

전체 요약에서 아래 출력이면 동봉 기대값과 일치합니다.

```
기대값과 비교 5장: Y 차이 최대 0.00000000 mm, T 차이 최대 0.00000000 도
```

사진 한 장을 측정하려면:

```
build/Release/measure_one data/model data/sample/sample_1.png
build/Release/measure_one data/model "측정 사진.bmp" "영점 사진.bmp"
```

콘솔에는 번호가 있는 결과 요약과 `explorer.exe` 폴더 열기 명령을 표시한다.
`data/results/measure/` 아래 새 폴더의 `measurement.txt`에 실제 단계별 기록을 저장한다.
일괄 평가 `score_photos`는 결과 폴더의 `logs/`에 사진별 TXT를 저장하고 CSV의 `상세 로그` 열로 연결한다.
TXT는 입력 검사, QR 검출, 나사 검출, Y/T 계산, 결과 점검, 정답 비교 순서다.
하위 단계의 추출값, 다음 용도, 경고와 실패 사유도 기록한다. 실패 뒤의 단계는 미실행으로 표시한다.
파일명에 Y/T 명령값이 있으면 원래 라벨과 예측값의 차이를 비교한다. 정답이 없거나 측정이 실패하면 평가 불가다.
IN은 허용오차(Y 0.045 mm, T 0.01도) 이내, OUT은 초과다. 두 축 모두 IN이어야 종합 IN이다.
경고 판정은 정답을 사용하지 않는다. 경고 유무와 실제 오차는 별도로 비교한다.
측정 호출 시간은 로그 버퍼 작성 포함, 사진 읽기와 TXT 저장 제외다. 하위 단계별 시간은 별도로 측정하지 않는다.
기존 명령의 마지막 `simple` 또는 `detail`은 호환을 위해 받아들이되 모두 같은 요약과 TXT를 생성한다.

환경은 C++17, OpenCV 3.4.15 다. 다른 환경으로 옮길 때는 [08 포팅 안내서](08_포팅_안내서.md)를 본다.

## 2. 호출 순서

> 현재 API: 운영 측정 measure_alignment는 영점 설정 성공 후 사용한다. 실패 후에는 보정하지 않는다. 보정 허용 여부는 correction_allowed로 확인하고 모든 알림은 notices에서 읽는다. 샘플과 학습 도구의 영점 없는 측정은 measure_diagnostic을 사용하며 보정이 금지된다. set_zero_value의 반환형은 Result이며 초기화와 영점 실패, clear_zero, 기준 재등록 뒤의 상태 규칙은 03 상태와 알림을 따른다. 매일 영점 갱신은 장비 프로그램의 작업 시작 절차에서 강제한다.

```cpp
#include "alignment.hpp"

auto ready = alignment::initialize("data/model");
if (ready.status == alignment::Status::Failed) return;
auto zero = alignment::set_zero_from_photos(zero_photos);
if (zero.status == alignment::Status::Failed) return;
alignment::Result r = alignment::measure_alignment(photo);     // 3. 사진마다
if (!r.correction_allowed) return; // action과 notices 확인 후 처리
// r.y_mm, r.t_deg   → 보정 이동은 (-r.y_mm, -r.t_deg)
// r.status, r.code, r.message → 4절
```

| 함수 | 하는 일 | 호출 시점 |
|---|---|---|
| `initialize(data_folder, settings_file)` | 기준 사진, 위치, 계수, 점검식을 읽는다 | 시작할 때 한 번 |
| `set_zero_from_photos(명령 0 사진들)` | 그날의 0 을 맞춘다 | 매일 (3절) |
| `measure_alignment(photo)` | 사진 한 장의 Y, T 를 잰다 | 사진마다 |
| `read_photo(path)` | 사진 파일을 회색으로 읽는다 (한글이 든 경로도 읽힌다) | 파일에서 사진을 읽을 때 |

- 입력 사진은 3840×2160, 8비트다. 회색 또는 컬러(BGR, BGRA)를 받는다. 컬러 순서를 주의해야 하는 이유는 [08 포팅 안내서](08_포팅_안내서.md) 2-1 에 있다.
- 결과의 status, action, correction_allowed와 notices를 확인한다. read_photo 등에서 예외가 전달될 수 있으므로 호출 경계의 예외 처리도 필요하다.
- 함수와 구조체 전체는 `include/alignment.hpp` 에 있다.

## 3. 영점 설정

**필수 조건: 매일 로봇을 명령 0 (Y 0, T 0) 으로 보내 찍은 사진 5 ~ 10장으로 영점을 잡는다.**

```cpp
std::vector<cv::Mat> zero_photos = { 사진1, 사진2, 사진3, 사진4, 사진5 };   // 명령 0 에서 찍은 사진
alignment::Result zero = alignment::set_zero_from_photos(zero_photos);
if (zero.status == alignment::Status::Failed) return; // 사진 확인 후 다시 설정
```

### 3-1. 영점을 매일 잡는 이유

| 이유 | 내용 |
|---|---|
| 로봇의 "명령 0" 자리가 날마다 다르다 | 받은 사진에서 Y 로 0.04 ~ 0.13 mm 차이가 났다. 허용오차(0.045 mm)보다 크다. 영점을 잡지 않으면 이 차이가 그대로 오차가 된다 |
| 카메라가 조금만 움직여도 값이 치우친다 | 카메라가 0.05도만 돌아도 Y 가 0.27 mm 틀어진다. 영점을 다시 잡으면 없어진다 |

| 처음 보는 날의 통과율 | |
|---|---|
| 영점을 잡지 않으면 | 31.6% |
| 그날 사진 5장으로 영점을 잡으면 | 현재 재실행 결과와 채점 조건은 6-1 정확도를 따른다. 과거 영점 모의실험과 현장 평가를 구분한다 |

### 3-2. 관련 함수

| 함수 | 하는 일 | 호출 시점 |
|---|---|---|
| `set_zero_from_photos(명령 0 사진들)` | 그 사진의 자세를 (0, 0) 으로 삼는다. 여러 장이면 평균을 쓴다 | 매일. 카메라, 조명, 판을 조정한 뒤에는 반드시 |
| `set_zero_value(y, t)` | 적어 둔 영점을 다시 넣는다 | 프로그램을 다시 켰을 때 (영점은 메모리에만 있다) |
| `clear_zero()` | 영점을 지우고 운영 측정을 차단한다 | 필요할 때 |
| `set_reference_from_photos(센터 사진들)` | QR 과 나사 위치를 다시 찾는다 | 화면이 많이 밀려 QR, 나사를 못 찾을 때만 |

### 3-3. 주의 사항

- 명령값을 모르는 "센터 사진"으로 영점을 잡으면 안 된다. 그 사진이 그날 명령 0 과 다른 만큼 값이 치우친다.
- 영점이 무엇인지, 사진 수에 따른 차이, 명령 0 이 아닌 자세로 잡는 방법은 [5-0 준비와 영점](05_구현_방법/5-0_준비와_영점.md)에 있다.

---

### 3-4. QR와 나사의 기준 위치를 다시 등록할 때

당일 원점 차이만 맞추는 경우에는 위의 영점 설정을 사용합니다. 설치 변화로 QR와 나사의 기준 위치를 다시 등록해야 하는 경우에는 장비 연동 코드에서 `set_reference_from_photos`를 호출합니다. 현재 이 작업을 수행하고 새 모델로 저장하는 전용 콘솔 명령은 없습니다.

1. `initialize`로 기존 모델을 읽고 성공 여부를 확인합니다.
2. 같은 센터 자세에서 촬영한 사진들을 `read_photo`로 읽습니다.
3. `set_reference_from_photos`에 사진 목록을 전달하고 반환 결과와 모든 알림을 확인합니다. 실패하면 측정을 진행하지 않습니다.
4. 기준 재등록 후에는 평가 원점 사진으로 `set_zero_from_photos`를 호출하고 영점 설정 성공을 확인합니다.
5. 그다음 `measure_alignment`를 호출하며 `correction_allowed`와 알림을 확인합니다.

재등록 결과는 메모리에 적용됩니다. 프로그램을 다시 시작하거나 initialize를 다시 호출하면 모델 파일의 기준을 읽으므로 필요한 등록 절차를 다시 수행해야 합니다. 카메라나 렌즈 변경에 따른 정확도를 기준 재등록만으로 보장하지 않으며 별도 평가가 필요합니다.
## 4. 측정 결과 처리

| 상태 | 뜻 | 측정값 | 로봇 |
|---|---|---|---|
| 정상 (`Ok`) | 구현된 점검 통과. 실제 오차 보장은 아님 | 나옴 | correction_allowed와 장비 이동 조건 확인 |
| 경고 (`Warning`) | 조건별 검토 필요 | 나옴 | action과 notices 확인. 보정 허용 여부는 correction_allowed로 판단 |
| 실패 (`Failed`) | 잴 수 없거나 쓰면 안 된다 | 쓰지 않는다 | 멈춘다 |

경고와 실패의 코드마다 조건, 위험, 조치는 [03 상태와 알림](03_상태와_알림.md)에 모두 있다.

## 5. 설정과 기본값

설정 파일 없이 `initialize("data/model")` 만 불러도 기본값으로 동작한다. 바꾸려면 `initialize("data/model", "config/settings.json")` 으로 설정 파일을 지정한다.

| 항목 | 기본값 | 바꾸는 곳 |
|---|---|---|
| 쓸 나사 | 4개 모두 | `config/settings.json` 의 `screws` |
| 값이 서로 안 맞을 때 | 경고만 | `fail_on_disagreement` |
| 알림 출력 | 콘솔(stderr) | `log_file` |
| QR 탐색 범위 | 사진 전체 폭의 QR 띠 (QR 상자 세로 범위 ±40 px). QR 3개가 아니면 실패 | (자동) |
| 영점 | 미설정. 설정 성공 전 운영 측정 차단 | `set_zero_from_photos` (3절) |

장비에는 `data/model/` 폴더만 같이 보내면 된다. 경로에 한글이 있으면 Windows 에서 설정, 위치 파일을 읽지 못할 수 있으니 영문 경로에 둔다.

## 6. 담당자용 전체 실행 목록

이 절은 현재 사용자용 실행 파일 17개와 대화형 입력을 정리한다.
명령은 모두 패키지 최상위 폴더의 PowerShell에서 실행한다. `<사진>` 같은 표기는 실제 경로로 바꾼다.
공백이나 한글이 있는 경로는 큰따옴표로 감싼다. 명령을 한 번에 모두 실행할 필요는 없다.
평가를 먼저 하고, 재학습과 합성 시험은 해당 목적이 있을 때 실행한다.

### 6-1. 처음 실행할 때 준비

1. 받은 패키지 전체를 한 폴더에 푼다. `data/model`과 `data/sample`의 구성 파일을 유지한다.
2. Visual Studio C++ 빌드 도구, CMake, OpenCV 3.4.15가 필요하다. 검증 컴파일러는 MSVC v141이다.
3. 아래 OpenCV 경로는 설치 위치에 맞춘다. 실행에 필요한 OpenCV 파일은 빌드 시 실행 파일 옆으로 복사한다.

```powershell
cmake -S . -B build -A x64 -T v141 -DOpenCV_DIR=C:/opencv/build
```

설정이 성공하고 `Build files have been written to`가 나오면 빌드합니다. 오류가 나오면 해결 후 진행합니다.

```powershell
cmake --build build --config Release
```

Visual Studio용 생성기가 아닌 환경에서는 프로젝트의 지원 환경과 생성기를 먼저 맞춘다.
이 실행 목록을 시작하기 전에 [1. 빌드와 확인](#1-빌드와-확인)의 CMake 버전 확인과 경로 설정을 완료한다. 설정 명령이 실패하면 다음 빌드 명령을 실행하지 않는다.

```powershell
Get-ChildItem ./build/Release/*.exe
./build/Release/score_photos.exe data/sample auto --answers data/sample/answers.tsv
```

두 번째 명령이 가장 먼저 해볼 평가다. 기대 출력 재현용 5장이고 독립 정확도 시험은 아니다.
콘솔 마지막의 `explorer.exe` 명령을 복사해 결과 폴더를 열고 `results.csv`부터 확인한다.

### 6-2. 넣어야 하는 데이터

| 자료 | 어디에 준비하는가 | 형식과 주의점 |
|---|---|---|
| 측정 모델 | `data/model/` | 기준 사진, reference.json, coefficients, checks. 파일을 임의로 빼지 않음 |
| 한 번의 평가 사진 | 원본 사진 위치에서 선택 | 같은 촬영일과 같은 설치 조건, 3840x2160, 8비트 BMP 또는 PNG |
| 평가용 영점 사진 | 원본 기준 사진 위치에서 선택 | 같은 날 같은 조건에서 평가 좌표의 (Y 0, T 0)을 찍은 사진 5~10장. 폴더에 영점 사진만 넣음 |
| 별도 정답표 | 원본 정답표 위치에서 선택 | UTF-8 탭 구분, 첫 행 file, y_mm, t_deg. 파일명과 평가 정답을 입력 |
| 학습 사진 | `data/new_photos/<회차>/` | 회차마다 폴더. 파일명에 Y/T 명령값. 회차별 명령 0 사진도 포함 |
| 학습용 표 | `prepare_dataset`의 출력 폴더 | photos, features, labels, splits, sessions 등의 TSV. 직접 수치 편집하지 않음 |
| 샘플 목록 | `data/sample/list.tsv` | 헤더 없이 번호와 사진 경로를 탭으로 구분. 경로 기준은 실행한 폴더 |
| 샘플 기대값 | `data/sample/expected.tsv` | 헤더 없이 번호, Y, T. 별도 정답표 answers.tsv와 형식이 다름 |
| 전처리 규칙 | `config/data_preprocessing.tsv` | 학습 전처리 규칙. 기존 규칙의 의미를 확인한 뒤 변경 |

사진을 원래 위치에서 클릭으로 선택하려면 다음 명령을 실행한다. 고정 입력 폴더를 만들 필요가 없다.

```powershell
./build/Release/score_photos.exe
```

별도 정답표가 필요하면 data/sample/answers.tsv의 형식을 참고해 실제 사진 정보로 작성하고 선택 창에서 고른다.
정답표 첫 행은 유지하고 Excel에서는 UTF-8 탭 구분 텍스트로 저장한다.

```text
file	y_mm	t_deg
001.bmp	0.1	0.16
002.bmp	1.1	0.16
```

위 숫자는 작성 형식 예시다. 담당자가 확인한 실제 정답을 넣어야 한다.
장비 명령값과 평가 기준값의 원점이 다르면 평가 기준값을 넣고, 영점도 같은 좌표의 (0, 0) 사진을 사용한다.
파일명에 정답이 없다고 프로그램이 정답을 추측하지 않는다.
재촬영은 별도 파일명과 행으로 남긴다. 서로 다른 회차의 동일 파일명은 한 번의 평가에 섞지 않는다.

### 6-3. 한 장 측정과 여러 장 평가

한 장 측정:

```powershell
./build/Release/measure_one.exe data/model "C:/evaluation/photos/001.bmp" "C:/evaluation/center/center_1.bmp"
```

- 콘솔: 영점 적용, 예측 Y/T, 상태, 경고, 시간, 결과 폴더 열기 명령.
- 파일: `data/results/measure/<실행 시각>/measurement.txt`.
- TXT: 입력, 실제 단계별 추출값, 하위 단계, 판정 근거, 실패 시 중단 위치, 시간.
- 별도 정답표는 받지 않는다. `001.bmp`의 정답 비교는 일괄 평가에서 한다.
- 한 장의 영점을 쓰므로 여러 영점 사진을 평균한 일괄 평가와 결과가 다를 수 있다.
- 마지막의 예전 `simple`, `detail` 인자는 호환 목적으로 받지만 이제 출력 방식은 동일하다.

경로를 직접 입력하는 여러 장 평가 (C:/evaluation은 예시이며 실제 원본 경로로 바꾼다):

```powershell
./build/Release/score_photos.exe C:/evaluation/photos auto --zero C:/evaluation/center --answers C:/evaluation/answers.tsv
```

| 입력 옵션 | 의미 | 생략하면 |
|---|---|---|
| 첫 번째 경로 | 평가 사진 폴더 | 필수 |
| 두 번째 경로 | 결과 폴더 또는 `auto` | 필수. auto는 새 폴더를 자동 생성 |
| `--zero <경로>` | 영점 사진 한 장 또는 폴더 | 평가 폴더에서 정답 (0, 0) 사진을 찾음. 없으면 영점 없이 평가한 사실을 알림 |
| `--answers <TSV>` | 별도 평가 정답표 | 파일명의 Y/T 값을 읽음. 한 축만 있으면 다른 축은 0 |
| `--data <모델 폴더>` | 사용할 모델 | data/model |
| `--tolerance-y <양수>` | Y 허용오차(mm) | 0.045 |
| `--tolerance-t <양수>` | T 허용오차(도) | 0.01 |

```powershell
./build/Release/score_photos.exe C:/evaluation/photos auto --zero C:/evaluation/center --answers C:/evaluation/answers.tsv --data data/model --tolerance-y 0.045 --tolerance-t 0.01
```

결과 폴더에는 `results.csv`, `summary.txt`, `logs/00001.txt` 등의 사진별 기록이 생긴다.
CSV의 `상세 로그` 열로 사진과 TXT를 연결한다. 평가 사진이 실패하면 그 사진의 후속 측정은 중단하고 다음 사진으로 넘어간다.
정답표 오류, 영점 설정 실패, 출력 저장 실패는 전체 평가를 중단한다.

CSV에서 먼저 볼 열:

1. 정답 Y/T, 측정 Y/T, 오차 Y/T.
2. 종합 판정(IN, OUT, 평가 불가).
3. Y 여유 mm, T 여유 도. 양수는 기준 안 여유, 음수는 초과량.
4. 경고와 실제 오차. `경고 없음 / OUT (미검출)`을 우선 확인.
5. 코드, 메시지, 상세 로그.

### 6-4. 파일 선택 창으로 평가

```powershell
./build/Release/score_photos.exe
```

선택 창은 기준 사진(center), 평가 사진, 정답 방식 순서로 열립니다. 사진 다중 선택과 폴더 선택을 지원합니다. 취소하면 평가를 시작하지 않습니다. 마지막 콘솔 확인에서 Enter 또는 y로 시작하며 n으로 취소합니다. 결과 확인 뒤 Enter를 누르면 종료합니다.

### 6-5. 빌드 확인과 포팅 진단

```powershell
./build/Release/check_photos.exe data/model data/sample/list.tsv auto data/sample/expected.tsv
./build/Release/show_steps.exe data/model data/sample/sample_1.png
./build/Release/check_setup.exe data/model data/sample/list.tsv
```

| 실행 파일 | 입력 | 얻는 결과 |
|---|---|---|
| check_photos | 모델, 목록 TSV, 출력 TSV 또는 auto, 선택 기대값 TSV | 사진별 예측값, 기대값, 오차, 상태, 시간과 결과 TSV 저장 경로 |
| show_steps | 모델, 사진 한 장 | QR, 나사, 계산식 기여량, 점검의 콘솔 진단. 별도 정답표나 영점 인자 없음 |
| check_setup | 모델, 목록 TSV | 영점 설정, 기준 재등록, 나사 가림 진단 결과를 콘솔로 표시 |

`check_photos`에는 영상 전체의 이동량을 추가할 수 있다. 순서는 오른쪽 px, 아래쪽 px다.
기대값 없이 이동만 시험하려면 그 자리에 `-`를 넣는다.

```powershell
./build/Release/check_photos.exe data/model data/sample/list.tsv auto - 0 40
```

진단 도구의 출력은 실제 장비 명령이 아니다. 장비 이동은 이 프로그램들이 수행하지 않는다.

### 6-6. 속도 측정

```powershell
./build/Release/measure_speed.exe data/model data/sample data/results/speed_trial_01 --count 5
```

사진 폴더 또는 학습 tables 폴더를 받는다. 사진은 2장 이상 필요하다.
`--count`는 읽을 사진 수의 상한이며 생략하면 수집한 사진을 사용한다.
초기화 시간, 스레드별 읽기 시간, 측정 시간, 합계가 콘솔과 `speed_report.txt`에 나온다.
사진별 시간은 `times.tsv`에 저장한다. 각 스레드 설정의 첫 사진은 요약 통계에서 제외한다.
출력 폴더는 새 이름을 사용한다. 이 도구에는 `auto`라는 특별한 옵션이 없다.

### 6-7. 재학습: 대화형

학습은 평가 폴더와 다르게 회차별 하위 폴더가 필요하다.

```text
data/new_photos/
  session_01/
    Y+0.00 T+0.00 (1).bmp
    Y+0.00 T+0.00 (2).bmp
    Y+0.10 T+0.20.bmp
  session_02/
    Y+0.00 T+0.00 (1).bmp
    Y-0.10 T-0.20.bmp
```

위는 이름 형식 예시이며, 이 정도 소량의 사진만으로 충분한 학습이 된다는 뜻은 아니다.
실제 동작 범위를 포함하는 여러 자세와 회차의 데이터가 필요하다. 상세 준비는 07 학습과 데이터 문서를 따른다.
학습 도구는 평가용 `--answers`를 받지 않는다. 명령값을 파일명에 넣는다.

```powershell
./build/Release/train.exe
```

| 질문 순서 | 입력 | Enter의 의미 |
|---|---|---|
| 사진 폴더 경로 | 회차 폴더들을 포함한 상위 폴더 | data/new_photos |
| 기존 표를 그대로 쓸까요 | 유효한 기존 표가 있을 때만 물음. y 또는 n | 기존 표 재사용 |
| 시작할까요 | y 또는 n | 학습 시작 |
| 완료 뒤 Enter | Enter | 종료 |

처리 순서는 사진 측정, 계수 생성, 정확도 평가다.
결과는 `data/results/train/<실행 시각>/`에 저장하며 새 `model/`, `accuracy/accuracy_report.txt`, 새 측정표 위치를 안내한다.
기존 `data/model`은 자동 교체하지 않는다. 새 모델은 다음처럼 별도 경로로 먼저 평가한다.

```powershell
./build/Release/score_photos.exe C:/evaluation/photos auto --zero C:/evaluation/center --answers C:/evaluation/answers.tsv --data "data/results/train/<실행 시각>/model"
```

### 6-8. 재학습: 단계별 직접 실행

출력 폴더 이름은 실행마다 새 이름으로 바꾼다. 아래 순서는 앞 단계가 성공해야 다음 단계를 실행할 수 있다.

```powershell
./build/Release/prepare_dataset.exe data/new_photos --data data/model --output data/results/manual_trial_01/tables --rules config/data_preprocessing.tsv
./build/Release/fit_coefficients.exe data/results/manual_trial_01/tables data/results/manual_trial_01/model --data data/model --rules config/data_preprocessing.tsv
./build/Release/evaluate_accuracy.exe data/results/manual_trial_01/tables data/results/manual_trial_01/accuracy
```

| 도구 | 선택 옵션 | 출력 |
|---|---|---|
| prepare_dataset | --data, --output, --rules | photos.tsv, features.tsv, labels.tsv, splits.tsv, sessions.tsv, preprocessing.tsv, prepare_report.txt |
| fit_coefficients | --data, --rules | 새 모델 폴더와 fit_report.txt |
| evaluate_accuracy | 없음 | 정확도 평가 콘솔과 accuracy_report.txt |

prepare_dataset의 기본 출력은 입력 폴더 아래 tables, 기본 모델은 data/model, 기본 규칙은 config/data_preprocessing.tsv다.
fit_coefficients의 첫 두 인자인 tables와 새 모델 폴더는 필수다.
evaluate_accuracy는 측정표로 학습과 검증 절차를 수행한다. 이미 만든 모델을 현장 사진에 적용해 평가하려면 score_photos를 쓴다.

### 6-9. 환경 시험과 그림 생성 도구

아래는 추가 개발과 원인 분석을 위한 도구다. 정상 운영 평가 전에 전부 돌릴 필요는 없다.

### 6-10. 개발 확인 명령

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/check_text_style.ps1
cmake --build build --config Release
ctest --test-dir build -C Release --output-on-failure
```

문자 검사는 현재 텍스트 소스와 문서를 검사하며 금지 문자가 있으면 종료 코드 1이다.
Windows에서 alignment를 빌드할 때도 자동으로 수행한다.
새 결과 폴더의 TXT, CSV까지 검사하려면 다음 명령을 쓴다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/check_text_style.ps1 -Path "data/results/eval/<결과 폴더>"
```

safety_tests는 BUILD_TESTING이 켜진 빌드에만 포함한다.
테스트가 없으면 다음과 같이 구성한 뒤 실행한다.

```powershell
cmake -S . -B build -DBUILD_TESTING=ON -DOpenCV_DIR=C:/opencv/build
cmake --build build --config Release --target safety_tests
ctest --test-dir build -C Release --output-on-failure
```

직접 호출 형식은 `safety_tests <model 폴더> <샘플 사진>`이다. 현재 작업 폴더에 시험용 모델 사본들을 생성하므로 보통 ctest로 실행한다.
