# 검증 결과와 한계

2026-11-16 로컬 Windows x64, MSVC v141 Release, OpenCV 3.4.15에서 확인했다. 라즈베리파이나 실제 로봇에서 검증한 결과는 아니다.

## 운영 계약 검사

현재 runtime_contract의 69개 검사를 통과했다. 주요 조건은 다음과 같다.

1. 초기화 전 호출, 영점 미설정, 잘못된 영상 형식의 거부.
2. 영점 설정 실패 후 이전 영점 무효화.
3. 나사 하나가 완전히 가려졌을 때 좌우 3개 조합 사용.
4. 한쪽 나사만 남았을 때 대략값은 반환하지만 보정은 차단.
5. Y와 T 각각의 상한 및 하한 초과 경고가 보정을 막지 않음.
6. 3.00 mm 출력에서도 범위 경고만 있으면 보정 허용.
7. 범위 경고와 다른 차단이 동시에 있을 때 차단 유지.
8. 진단 API의 보정 금지, 모델 파일 해시 불일치 거부.

3.00 mm 검사는 테스트용 범위와 영점 조건을 구성한 정책 검사다. 실제 3.00 mm로 촬영한 영상의 위치 정확도를 입증한 시험은 아니다.

## 사진 전체 실행

새 검출기와 조합 모델로 기존 사진 3680장을 한 번씩 진단 측정했다. 기준 및 중간 확인 사진도 포함했다. 측정 실패는 1장, 학습 범위 경고는 180장이었다.

기존 평균 보정 라벨이 있는 3638장 중 3624장이 통과했다(99.615%). 기준은 abs(Y 오차) <= 0.045 mm와 abs(T 오차) <= 0.01도 동시 만족이다. 라벨이 없는 42장도 측정 실행에는 포함했으나 정확도 정답을 임의로 만들지 않았다.

실패 사진은 rig_grid/Grid/Y+0.00 T+0.80 (1).bmp다. 나사 1의 밝기 맞춤과 테두리 맞춤 차이 0.59 px가 기준 0.5 px를 넘어서 E_SCREW_PARTIAL로 거부했다. 학습 범위 때문에 거부한 것이 아니며 기존 평균 라벨에서도 빠진 사진이다.

학습 사진 1959장을 원래 L2 정답으로 다시 비교한 4개 나사 모델 결과는 1950장 통과다(99.541%). 이는 재대입 결과다. 평균 보정 라벨과 L2 라벨은 서로 다른 정답표이며 두 점수 차이를 알고리즘 개선으로 해석하지 않는다.

## 속도

전체 3680장 실행에서 측정 호출 평균은 22.622 ms였다. OpenCV 스레드는 1개였고, 초기화 후 준비 측정 10회를 수행했다. 파일 읽기와 디코딩은 측정 호출 시간에서 제외한다. 이 실행은 1회 전수 진단이며 운영체제 캐시를 비우지 않았다.

이전 버전의 3회 전수 실행 평균 22.166 ms와는 코드, 실행 횟수와 알림 처리 조건이 다르므로 엄밀한 속도 개선 또는 악화 판정으로 사용하지 않는다. 현재 장비의 카메라 촬영, 전송, 모터 이동 시간은 포함하지 않는다.

## 해석 주의

보정 라벨의 99.615%는 실제 위치의 독립 계측 정확도가 아니다. 이전 버전에서 최초 기준 사진으로 영점을 맞추고 촬영 명령과 비교한 결과는 969/3640(26.621%)이었다. 명령값 역시 실제 위치의 독립 계측값이 아니며 라벨, 영점, 시간 변화의 차이가 섞여 있다.

범위 밖 보정 허용 변경은 결과 사용 정책의 변경이다. 모델 계수와 숫자 계산식을 바꾸지 않았고 마지막 정책 변경은 계약 테스트로 검증했다. 사진 전수 결과는 그 직전 동일 계산식의 진단 실행 기록이다.

## 재현에 필요한 자료

빌드 후 ctest --test-dir build -C Release --output-on-failure로 운영 계약을 재현한다. 사진 전수 재현에는 별도 촬영 원본, photos.tsv, 기존 정답표가 필요하다. 원본 사진과 큰 실행 결과는 Git에 넣지 않는다. 요약 수치는 [validation_summary.json](validation_summary.json)에 있다.
