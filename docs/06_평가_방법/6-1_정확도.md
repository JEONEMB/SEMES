## 2. 측정 방법과 근거

### 2-1. 지키는 것 세 가지

| 지키는 것 | 이유 |
|---|---|
| **시험하는 사진은 학습에 쓰지 않는다** | 학습에 쓴 사진으로 시험하면 답을 외운 시험이 된다 |
| **같은 자세를 여러 번 찍은 사진은 한 묶음으로 움직인다** | 거의 같은 사진이 학습과 시험에 나뉘어 들어가면 답을 미리 본 셈이 된다 |
| **채점 정답은 받은 명령값 그대로** | 기업 측이 같은 방식으로 채점해도 같은 숫자가 나와야 한다 |

### 2-2. 시험 네 가지

| 시험 | 방법 | 알려 주는 것 |
|---|---|---|
| 섞음 | 마지막 확인 사진을 뺀 571장을 다섯 묶음으로 나눈다. 네 묶음으로 배우고 한 묶음으로 시험하기를 다섯 번 해서 모든 사진이 한 번씩 시험받는다. 나누는 법을 바꿔 10번 되풀이한다 | 같은 촬영들 안에서, 처음 보는 사진을 얼마나 맞히나 |
| 마지막 확인 | 맨 처음에 131장을 따로 떼어 둔다. 방법을 다 정한 뒤 **한 번만** 시험한다 | 방법을 고르는 동안 한 번도 안 본 사진에서도 되나 |
| 처음 보는 날 | 촬영 하나를 통째로 빼고 나머지 셋으로 배운 뒤, 뺀 촬영으로 시험한다. 4번 | **다른 날 찍은 사진에서도 되나** (실제 쓰임에 가장 가깝다) |
| 범위 밖 | 안쪽(\|Y\| ≤ 1 mm, \|T\| ≤ 0.5도)으로만 배우고 바깥을 시험한다 | 배운 범위를 벗어나면 얼마나 틀리나 |

나누는 방법은 고정되어 있다 (`data/new_photos/tables/splits.tsv`). 누가 돌려도 같은 나누기, 같은 숫자가 나온다.

### 2-3. 그날의 영점

로봇의 "명령 0" 자리는 촬영한 날마다 Y 로 0.04 ~ 0.13 mm 달랐다 ([구현 방법 step 0](../05_구현_방법/5-0_준비와_영점.md)). 사진만으로는 이 차이를 알 수 없어서, 실제로 쓸 때는 **매일 명령 0 에서 사진 5 ~ 10장을 찍어 영점을 잡는다.**

그래서 "처음 보는 날" 시험은 세 가지로 채점했다.

| 채점 | 뜻 |
|---|---|
| 받은 정답, 영점 없음 | 영점을 잡지 않고 그대로 채점 |
| 받은 정답, 그날 영점 | 그날 사진 5장으로 영점을 잡고 채점. **실제 쓰임과 같은 조건** |
| 그날 0 의 차이를 아는 경우 | 그날 로봇 0 의 차이를 정확히 안다고 보고 채점. 측정 자체의 정확도 |

우리가 받은 사진에는 명령 0 에서 찍은 사진이 없다. 그래서 "그날 영점"은 센터 근처(\|Y\| ≤ 0.25 mm, \|T\| ≤ 0.05도)의 **명령값을 아는 사진 5장**으로 (측정 − 명령)의 평균을 구해 잡았다. 5장을 고르는 방법에 따라 달라지지 않게 200번 뽑아 평균했고, 영점에 쓴 사진은 채점에서 뺐다.

## 3. 결과

### 3-1. 시험 네 가지

| 시험 | 결과 |
|---|---|
| 섞음 (571장, 10번) | **100%** (허용오차 밖 0장) |
| 마지막 확인 (131장, 한 번) | **100%** (허용오차 밖 0장) |
| 범위 밖 (안쪽 406장으로 배우고 바깥 296장 시험) | 95.9%. Y 는 0.34%, T 는 0.39% 크게 읽는다 (나사 둘레 영역 값을 넣기 전 95.3%, 0.31%, 0.42%) |

2026-11-16 에 계수를 패키지 학습 도구(`train`)로 다시 만든 뒤 위 시험을 다시 돌렸다. 정답 정리 규칙이 바뀌어 섞음, 마지막 확인의 사진 수가 1장씩 달라졌다. 패키지에 들어 있는 계수 그대로 사진 719장(받은 사진 715장 + 센터 사진 4장)을 명령값으로 채점하면 714장이 통과한다(이전 계수 713장). 떨어진 5장은 학습 범위 밖인 T 2도 사진 4장과 명령값이 잘못 적힌 사진 1장이다.

### 3-2. 처음 보는 날

| 채점 | 1차 | 2차 | 3차 | 4차 | 합계 |
|---|---:|---:|---:|---:|---:|
| 받은 정답, 영점 없음 | 70.4% | 0% | 0% | 21.7% | 32.5% |
| **받은 정답, 그날 영점 (5장)** | **97.5%** | **97.0%** | **100%** | **86.7%** | **96.1%** |
| 그날 0 의 차이를 아는 경우 | 99.3% | 97.8% | 100% | 93.0% | 98.1% |

(2026-11-16 나사 둘레 영역 값을 Y, T 계산에 넣은 뒤 다시 잰 값. 넣기 전: 그날 영점 96.8%, 93.8%, 100%, 86.4%, 합계 95.5%. [9-11](../09_추가_논의/9-11_나사_둘레_영역_값_추가.md))

- **영점을 잡지 않으면 크게 떨어진다.** 그날 로봇 0 의 차이(0.04 ~ 0.13 mm)가 허용오차(0.045 mm)보다 커서, 그 차이가 그대로 오차가 된다.
- 영점을 잡으면 96.1% 다. 측정 자체의 정확도(98.1%)와의 차이는 영점 5장의 흔들림에서 온다.
- 4차가 가장 낮다. Y 와 T 를 함께 크게 움직인 자세가 많은 촬영이다. 원인은 확인하지 않았다.
- 2차는 45장뿐이라 1장이 2.2% 다.

### 3-3. 영점 사진 수에 따라

| 영점에 쓴 사진 | 영점의 흔들림 (Y) | 1차 통과율 (가장 나쁜 경우) |
|---|---|---|
| 1장 | 0.003 ~ 0.016 mm | 89.6% (61.3%) |
| 3장 | 0.001 ~ 0.008 mm | 95.6% (85.6%) |
| 5장 | 0.0005 ~ 0.006 mm | 96.4% (87.3%) |
| 10장 | 0.001 ~ 0.003 mm | 97.9% (91.5%) |

1장으로 잡으면 운이 나쁠 때 그날 전체가 치우친다. 5 ~ 10장을 권한다.

### 3-4. 배우는 촬영을 바꾸면

| 배운 촬영 | 시험한 촬영 | 통과율 (그날 0 의 차이를 아는 경우) |
|---|---|---|
| 1차만 (한 축씩 움직인 사진) | 2차, 3차, 4차 (함께 움직인 사진) | 91.1%, 99.6%, 98.6% |
| 2차 + 3차 + 4차 (함께 움직인 사진) | 1차 (한 축씩 움직인 사진) | 99.3% |

- **한 축씩만 움직여 찍은 사진으로 배워도, 함께 움직인 자세를 대부분 맞힌다.** 계수를 다시 만들 때 한 축씩만 찍어도 된다는 뜻이다.

### 3-5. 학습에 쓰는 정답

학습할 때만 촬영마다 로봇 0 의 차이를 구해 정답에서 뺀다 (이유는 [구현 방법 step 3](../05_구현_방법/5-3_YT계산.md) 2-4). 채점 정답은 고치지 않는다.

| 학습에 쓴 정답 | 처음 보는 날, 받은 정답으로 채점, 그날 영점 | 영점 없음 |
|---|---:|---:|
| 받은 정답 그대로 | 89.5% | 52.3% |
| **촬영마다 로봇 0 의 차이를 뺀 정답** | **95.3%** | 31.9% |

- 영점을 잡고 쓰는 조건에서는 차이를 뺀 쪽이 더 높다.
- 이 표는 3-2 와 따로 잰 것이라 숫자가 조금 다르다 (95.3% 와 95.5%).

## 4. 다시 재 보는 방법

```
build\Release\prepare_dataset.exe data/new_photos
```

- 둘째 줄은 위 시험 네 가지를 돌려 `결과폴더/accuracy_report.txt` 에 쓴다.
- 받은 사진을 그대로 채점만 하려면 [5. 평가 절차](6-5_평가_절차.md).

## 5. 한계

- 정답은 로봇 명령값이다. 따로 잰 실제 위치가 아니다. 로봇이 명령대로 정확히 가지 않았다면 그만큼이 오차에 들어 있다.
- 촬영은 4번뿐이다.
- 모두 **정지 사진**으로 잰 것이다. 잰 값으로 로봇을 움직여 센터로 돌아오는지는 시험하지 않았다.
- 받은 사진에 명령 0 사진이 없어서, 그날 영점은 센터 근처의 다른 사진으로 흉내 냈다.
- 큰 자세(Y ±2 mm, T ±1도 밖)는 사진이 12장뿐이다.

## 6. 배포 코드와 개발 코드의 일치

이 폴더의 코드는 개발할 때 쓴 코드를 읽기 쉽게 다시 쓴 것이다. 계산식은 바꾸지 않았다.

- 받은 사진 702장에서 두 코드의 Y, T 가 모두 같았다 (차이 0).
- 그 뒤 폴더와 코드를 정리할 때마다 사진 719장의 값이 정리 전과 같은지 확인했다.
