# 6-1. 정확도

담당자가 배포 모델을 평가할 때는 score_photos를 사용한다. evaluate_accuracy는 저장된 특징값 표로 계수를 다시 학습하는 내부 실험이다. 두 프로그램의 통과율은 조건이 다르므로 같은 성능으로 인용하면 안 된다.

## 1. 실제 사진 평가

같은 회차의 center와 photos를 [사용법](../02_사용법.md)대로 선택한다. 정답은 파일명 또는 정답표의 명령값이며 측정 후 비교에만 사용한다. 명령값은 외부 측정기로 확인한 실제 위치가 아니다. center가 평가 좌표의 (0, 0)인지 별도로 확인해야 한다.

1. 기준 1: Y 오차 절댓값 <= 0.045 mm, T 오차 절댓값 <= 0.01도.
2. 기준 2: Y 오차 절댓값 <= 0.09 mm, T 오차 절댓값 <= 0.01도.
3. 두 축 모두 만족해야 IN이다. 실패는 평가 불가이며 전체 통과율 분모에는 포함한다.
4. 정상 상태여도 실제 오차가 클 수 있다. 경고 없는 OUT을 별도로 확인한다.

예시는 첫 실행 확인용으로 선택한 성공 사례다. 전체 성능을 대표하지 않는다. 과거의 719장 중 714장 통과는 현재 모델, center 선택, 원래 명령값 비교 조건으로 재현된 결과가 아니므로 현재 성능 근거에서 제외한다.

## 2. 내부 실험 조건

prepare_dataset은 특징값을 추출하고 회차별 좌표 차이를 반영한 학습 라벨을 만든다. 정답 정리 규칙에 따른 수정과 제외도 적용한다. evaluate_accuracy의 섞음, 마지막 확인, 범위 밖 시험은 이 라벨로 채점한다. 받은 명령값 그대로 채점하는 시험이 아니다.

현재 표는 702장이다. 10/14 280장, 10/20 45장, 10/29 234장, 4차 143장이다. 제외한 사진이 잘못 촬영됐다는 외부 검증까지 완료됐다는 뜻은 아니다.

회차별 좌표 차이를 추정하는 전처리는 교차검증의 각 학습 묶음 안에서 다시 수행하지 않는다. 따라서 계수 학습에서 시험 행을 제외했더라도 전체 전처리까지 독립된 미관측 데이터 검증이라고 주장할 수 없다. 고정 확인 묶음을 반복 실행한 결과도 한 번만 사용한 최종 검증 성적으로 부르면 안 된다.

처음 보는 날 시험은 회차 하나를 제외해 계수를 다시 맞추고 다음을 비교한다.

| 비교 | 조건 |
|---|---|
| 받은 정답, 영점 없음 | 원래 명령값과 비교 |
| 받은 정답, 그날 영점 | 근처 자세 5장의 (예측 - 명령) 평균을 빼고 나머지 평가. 200회 표본 추출 평균 |
| 학습 정답 | 전처리된 라벨과 비교 |

두 번째 방식은 center 사진의 화소를 평균해 재는 set_zero_from_photos와 다르다. 이미 만든 특징값 표를 쓰므로 검출 단계와 운영 경고까지 재평가하지 않는다. 과거의 '영점 5장으로 95.5%'를 현장 center 5장 사용 시 성능으로 설명하면 안 된다.

## 4. 재실행 명령

패키지 루트에서 실행한다. 현재 특징값 표를 사용하며 배포 모델은 교체하지 않는다.

```powershell
.\build\Release\evaluate_accuracy.exe data/new_photos/tables data/results/accuracy_review
```

출력 폴더의 accuracy_report.txt를 확인한다. 원본 사진부터 다시 처리하려면 데이터 준비와 전처리 규칙을 먼저 확인한다. 다른 환경의 소수 오차와 경계 판정은 따로 비교해야 한다.

## 5. 한계

정지 사진과 특징값 표의 평가다. 실제 장비를 자동 이동시켜 복귀하는 동작, 외부 측정기로 확인한 위치 오차, 모든 가림과 조명 변화의 검출률을 보장하지 않는다. 학습 범위 밖 T 2도 사진은 12장으로 제한적이다.
