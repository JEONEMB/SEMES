# Simulator — 영점 맞춤 시뮬레이터 (콘솔 + MFC)

`Alignment` 모델(`alignment()`)을 장착한 가상 로봇이 **사진 → 판단 → 이동** 을 반복하며
20회 이내에 영점(허용 Y ±90 µm, Θ ±0.01°)을 맞추는지 시험한다.

## 1. 구성

| 폴더 | 내용 |
|---|---|
| `core/` | 콘솔·MFC 공용 시뮬레이터 (OpenCV 3.4 API, C++17) |
| `core/sim_world.*` | 실제 사진 → **운동장 + 파노라마** → 임의 자세의 사진 합성 |
| `core/sim_runner.*` | 로봇 · 제어 반복 · 다회 시험 · 합성 사진 검증 |
| `core/sim_draw.*` | 화면 그림 (카메라, 파노라마, 궤적, 수렴, 통계) |
| `console/` | 콘솔 앱 `Simulator` (일괄 실행 · 결과 파일) |
| `mfc/` | MFC 대화 상자 앱 `SimulatorMFC` (단계별 보기) |
| `config/simulator.yml` | 모든 설정 (경로, 운동장, 잡음, 로봇 오차, 허용 범위, 시험 횟수) |
| `world/` | 만든 가상 장면 (`panorama.png`, `field.yml`, `field_report.md`, 측정 캐시 `field_raw.bin`) — 실행 시 생성 |
| `results/` | 실행 결과 — 실행 시 생성 |

모델 코드는 복사하지 않고 `../Alignment/alignment.cpp` 를 그대로 컴파일한다 (모델을 고치면 시뮬레이터에도 바로 반영).

## 2. 가상 장면을 만드는 방법

1. **운동장 (motion field)** — 기준 사진을 80 px 격자(48 × 27)로 나누고, 1차 첫 번째 측정 사진
   (Θ 스윕 0.05° 간격 41장 + Y 0.1 mm 배수 40장)에서 격자마다 이동을 위상 상관 + ECC 로 잰 뒤
   `dx, dy = c + aY·Y + bT·Θ + qT·Θ²` 로 맞춘다.
   깊이(시차), 회전축 어긋남, 원근 휨이 물리 가정 없이 **측정값 그대로** 들어간다.
   질감이 없어 잴 수 없는 격자(민무늬 벽)는 이웃 값으로 채운다 — 무늬가 없으니 이동이 조금 틀려도 사진은 거의 같다.
2. **파노라마** — `center` 사진을 가운데 두고, 바깥 여유(좌우 160 px, 위아래 80 px)는
   Θ·Y 끝 쪽 사진을 운동장으로 되돌려 평균해 채운다. 사진이 없는 곳은 가장자리 복제(화면에 붉게 표시).
3. **합성** — 자세 (Y, Θ) 에서 각 화소가 파노라마의 어디를 보는지 운동장을 거꾸로 풀어(고정점 반복)
   `cv::remap` 으로 사진을 만들고, 촬영 잡음(σ 0.71)을 더해 8 bit 로 저장한다.

## 3. 제어 반복 (한 번의 시험)

```
참 자세 = 시작 자세
반복:
  사진 합성 (참 자세 + 잡음) → alignment() → 추정 (y, t)
  추정이 허용 × stop_ratio(0.5) 안 → 멈춤 → 참 자세가 허용 안이면 성공
  이동 20회를 이미 했으면 → 실패
  명령 = (−y, −t), 한 번 최대 2 mm / 2° 로 자름
  실제 이동 = 명령 × (1 + 배율 오차) + 반복 정밀도 잡음   → 참 자세 갱신
```

기준(티칭) 사진은 자세 (0, 0) 합성 사진 (시험마다 새 잡음).

## 4. 실행

두 프로젝트 모두 작업 폴더 = 이 `Simulator` 폴더 (`.vcxproj.user` 에 설정). **Release x64 권장** (Debug 는 5~10배 느림).
처음 한 번은 가상 장면을 만들어야 한다 (콘솔 `--build` 또는 MFC [파노라마 생성]).

### 콘솔 `Simulator`

| 인자 | 동작 |
|---|---|
| (없음) | 가상 장면이 없으면 만들고, 무작위 시작으로 한 번 시험 (창 표시, 아무 키 = 다음 단계) |
| `--build` | 가상 장면 만들기 → `world/`, `results/field_map.png`, `results/panorama_view.png` |
| `--run [Y Θ]` | 한 번 시험 (예 `--run 1.2 -0.6`), `--gui` 로 창 표시 → `results/trial_날짜/` (단계별 화면 jpg, csv, 그래프) |
| `--monte [N]` | N 번 시험 통계 → `results/monte_날짜.csv/.png/.md` |
| `--validate` | 같은 라벨의 실제 사진 vs 합성 사진에서 모델 추정 비교 → `results/validation.md/.csv` |

### MFC `SimulatorMFC`

| 버튼 | 동작 |
|---|---|
| 시작 Y / Θ, [무작위 시작], [시작 위치로] | 시작 자세 정하기 |
| [1 단계] | 사진 한 장 → 판단 → 이동 한 번 |
| [자동 실행] / [정지] | 멈출 때까지 반복 / 중단 |
| [다회 시험] + 횟수 | 무작위 시작 N 회 통계 (목록 = 시험별, 오른쪽 위 = 분포 그림) |
| [합성 검증] | `--validate` 와 같음 (목록 = 사진별) |
| [파노라마 생성] | 가상 장면 다시 만들기 |
| [결과 폴더] | `results` 열기 |

화면 : 왼쪽 위 카메라(합성 사진 + 모델이 본 ROI, 참값·추정값) · 왼쪽 아래 파노라마(초록 = 목표 시야, 빨강 = 현재 시야, 노랑 = 지나온 길)
· 오른쪽 (Y, Θ) 궤적(왼쪽 전체, 오른쪽 허용 범위 확대) · 수렴 그래프(|참 오차| / 허용, 로그) · 수치 패널 · 아래 단계 목록

## 5. 한계 (결과를 읽을 때)

- 가상 장면은 **1차(10/04) 사진**으로 만든다. 2차(10/15)의 약 1 % 배율 차 같은 '날짜 간 변화'는 들어 있지 않다
  → `--validate` 의 2차 묶음에서 실제와 합성의 차이로 확인할 수 있다.
- 운동장은 Θ ±1°, Y ±2 mm 사진으로 맞춘 식이라 그 밖은 외삽이다 (시작 범위 기본값을 이 안으로 둔 이유).
- Y 와 Θ 가 동시에 움직인 1차 사진이 없어 두 효과는 '더해진다' 고 본다 (2차 사진으로 검증).
- 로봇 오차(배율 0.2 %, 반복 2 µm / 0.001°)는 가정값 — 장비 사양으로 바꿔 넣을 것.

## 6. 검증 결과 (2026-10-28, 리눅스 컨테이너 · OpenCV 4.6 · 3.4 호환 API 빌드)

### 가상 장면

- 학습 사진 80장 (Θ 0.05° 간격 41 + Y 0.1 mm 배수 40, 1차 첫 번째 측정), 만드는 시간 약 4분 (2코어)
- 격자 1296개 중 질감 있음 367, 측정 성공 223 — 맞춤 잔차 중앙값 **0.036 px** (90 % 0.100 px)
- 사진별 공통 이동(라벨 대비 실제 자세 차) RMS 0.206 px → 운동장에서 빼고 로봇 오차로 따로 다룸
- 격자 감도와 ROI 회귀 비교 : QR_C 14.14 / 14.25 px/mm, 하단 문 W2 11.05 / 11.15 px/mm

### 합성 사진이 실제 사진을 대신할 수 있나 (`--validate`, 같은 라벨에서 모델 추정 비교)

| 묶음 | 장 | 실제 허용 안 | 합성 허용 안 | 실제 Θ RMS | 합성 Θ RMS | 실제 Y RMS | 합성 Y RMS |
|---|---|---|---|---|---|---|---|
| 1차 Θ 스윕 | 200 | 200 | 200 | 0.0030° | 0.0027° | 10.3 µm | 18.5 µm |
| 1차 Y 스윕 (첫 측정) | 40 | 40 | 40 | 0.0013° | 0.0025° | 20.3 µm | 24.1 µm |
| 1차 Y 스윕 (48분 뒤) | 40 | 40 | 40 | 0.0028° | 0.0025° | 18.1 µm | 23.6 µm |
| 2차 목표 근처 | 33 | 33 | 33 | 0.0024° | 0.0014° | 11.2 µm | 19.0 µm |
| 2차 Θ 1° | 12 | 9 | 12 | 0.0092° | 0.0046° | 28.2 µm | 12.2 µm |
| 2차 Θ 2° (범위 밖) | 12 | 0 | 0 | 0.0204° | 0.0151° | 64.6 µm | 61.9 µm |

- 학습 범위 안에서는 합성 사진의 판정·오차 크기가 실제와 같은 수준 (Y 는 합성이 약간 더 큼 → 보수적)
- 2차 Θ 1° 에서 실제 9/12 vs 합성 12/12 : 합성에는 날짜 간 배율 차(약 1 %)가 없음 (5장 한계와 같은 내용)
- Θ 2° 는 실제·합성 모두 0/12 : 학습 범위 밖

### 영점 맞춤 (`--monte`)

| 조건 | 시험 | 성공 | 이동 횟수 (평균 / 최대) | 멈춘 뒤 참 오차 Y RMS (최대) | Θ RMS (최대) |
|---|---|---|---|---|---|
| 기본 (로봇 배율 σ 0.2 %, 반복 2 µm / 0.001°) | 100 | 100 % | 1.08 / 2 | 18.6 µm (48.1) | 0.0025° (0.0057) |
| 가혹 (배율 σ 5 %, 반복 15 µm / 0.003°) | 50 | 100 % | 2.10 / 4 | 20.0 µm (52.3) | 0.0032° (0.0055) |

- 시작 자세 : Y ±2 mm, Θ ±1° 균일 분포. 20회 한도의 1/5 이하로 수렴
- 한 단계(합성 + 추정) 약 0.4~0.5 초 (2코어 컨테이너, Release 상당 -O2)

### 발견 : 모델 상수항은 '기준 사진' 에 묶여 있다

기준(티칭) 사진을 실제 center 사진 대신 **자세 (0,0) 합성 사진**으로 바꾸면(`teach_center_photo: 0`)
같은 100회 시험에서 멈춘 뒤 Y 오차 평균이 **−27 µm** 로 치우친다 (center 사진 기준이면 −11 µm, 둘 다 성공 100 %).
모델 계수의 상수항(c_s = −0.57 px, c_d = −0.11 px)이 '1차 center 사진과 스윕 원점의 차이' 를 함께 학습했기 때문으로 본다
(center 기준에서도 남는 −11 µm 는 운동장 근사 오차와 구분되지 않음).
→ 실제 장비에서 티칭 사진을 새로 찍으면 **상수항 2개만 다시 맞추는 1회 보정**(목표 자세 사진 몇 장)을 권장.
