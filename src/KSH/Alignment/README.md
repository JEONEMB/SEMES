# Alignment — 사진 한 장으로 Y·Θ 어긋남 추정 (제출 형식 프로젝트)

연구용 `QR_Image` 프로젝트(가설 검증·ROI 학습)에서 최종 채택한 방법만 골라, 주어진 스켈레톤
(`main.cpp`, `alignment.hpp`, `alignment.cpp`) 형식으로 정리한 프로젝트.

## 함수

```cpp
Alignment_t alignment(cv::Mat &src);   // y [mm], t [°] — 기준(티칭) 사진 대비 어긋남, 라벨과 같은 부호
```

- 로봇 보정 이동 = `(−y, −t)`
- 측정 실패 시 `y`, `t` 가 NaN → `alignment_last_info().message` 에 이유
- 설정·기준 사진은 첫 호출 때 `config/alignment.yml` 에서 자동으로 읽음
  (`alignment_init(path)` 로 다른 설정, `alignment_set_reference(img)` 로 기준 사진 교체)

| 단계 | 방법 | 설정 항목 |
|---|---|---|
| ① Coarse Alignment (대략 정렬) | 플레이트 주변 900×400 창 위상 상관 (해닝 창) | `coarse` |
| ② Fine Alignment (정밀 정렬) | QR 3개 + 하단 문 홀 W2·W3 (홀은 2배 창 위상 상관 먼저) → 평행이동 IC-GN + 3차 O-MOMS 보간 | `qr_rois`, `background_rois`, `fine` |
| ③ 특징 | s = QR 평균 dx, d = s − (W2, W3) 평균 dx | — |
| ④ 추정 | s (Θ 3차), d (Θ 2차) 두 식을 동시에 만족하는 (Y, Θ) — 1/σ² 가중 가우스–뉴턴 | `model` |

각 단계의 방법은 연구 프로젝트의 실험계획(DOE, `QR_Image` → `verify doe`)으로 골랐다.

| 실험 | 비교 | 채택 | 교차검증 J (허용 ±45 µm·±0.005° 기준) |
|---|---|---|---|
| 1 정렬 순서 | Coarse only / Fine only / Coarse→Fine / Fine→Coarse | Coarse → Fine | 0.874 / 136 / **0.721** / 102 |
| 2 보간 | 선형, Bicubic(−0.5, −0.75), Lanczos3, B-스플라인, O-MOMS × 가우시안 σ 0~1.5 | O-MOMS σ 0 | 0.721 → **0.682** |
| 3 식 차수 | s·d 의 Θ 1~3차 (9가지) + Y² | s Θ3 · d Θ2 | 0.682 → **0.604** |

`fine.method: "opencv_ecc"` 로 바꾸면 이전 방식(OpenCV findTransformECC)으로 돌아간다. 이때는 모델 계수도 이전 값으로 되돌려야 한다
(`QR_Image/_archive/20261029_alignment_v1/`).

모델 계수·ROI 는 `QR_Image` 의 H5 단계 학습 결과(`roi_selected.yml`, 1차 첫 번째 측정만 사용)를 옮긴 값이다.
재학습하면 그 결과를 `alignment.yml` 에 옮겨 적으면 된다 (학습 코드와 실행 코드 분리).

## 실행 (작업 폴더 = 이 폴더, `.vcxproj.user` 에 설정됨)

| 인자 | 동작 |
|---|---|
| 없음 | `demo_image` 한 장 추정 → 콘솔 출력 + 결과 창 |
| `<사진> [기준 사진]` | 지정한 사진 한 장 추정 |
| `--eval [폴더]` | 라벨 있는 사진 전체 평가 → 콘솔 표 + `results/alignment_eval.csv` |

## 검증 결과 (`--eval`, 2026-10-29, 리눅스 OpenCV 4.6 · 3.4 호환 API 로 빌드)

프로젝트 기본 허용 범위 : |Y 오차| ≤ 45 µm, |Θ 오차| ≤ 0.005° (과제 허용 90 µm · 0.01° 의 절반, `alignment.yml` 의 `tolerance_*`)

| 묶음 | 허용 안 (±45 µm · ±0.005°) | 과제 허용 안 (±90 µm · ±0.01°) | Θ RMS | Θ 최대 | Y RMS | Y 최대 |
|---|---|---|---|---|---|---|
| 1차 전체 (학습 데이터, 참고) | 276 / 280 | 280 / 280 | 0.0021° | 0.0059° | 12.3 µm | 42.0 µm |
| 2차 목표 근처 Θ ≤ 0.2° | 33 / 33 | 33 / 33 | 0.0024° | 0.0042° | 11.6 µm | 25.9 µm |
| 2차 Θ = 1° | 3 / 12 | 9 / 12 | 0.0076° | 0.0138° | 22.3 µm | 42.2 µm |
| 2차 Θ = 2° (학습 범위 밖) | 0 / 12 | 0 / 12 | 0.0288° | 0.0317° | 31.9 µm | 53.4 µm |

- 2차 57장 추정값이 DOE 의 채택 조합(O-MOMS σ 0, s Θ3 · d Θ2) 예측과 같음 (최대 차 1e-9)
- 처리 시간 : 한 장 평균 약 46 ms (이전 OpenCV ECC 방식 약 150 ms, 리눅스 컨테이너, 영상 읽기 제외). Windows Release 에서 다시 잴 것
- 시뮬레이터 100회 (허용 ±45 µm · ±0.005°) : 모두 성공, 이동 평균 1.25회 (최대 2), 멈춘 뒤 Y RMS 13.6 µm, Θ 최대 0.0034°

## 주의

- `typedef double error_t;` 는 스켈레톤 그대로 둠. MSVC 에서는 문제없지만 리눅스 glibc 는 `error_t` 를 int 로 이미 정의하므로
  리눅스에서 빌드할 때는 `-D__error_t_defined=1` 이 필요하다.
- Θ 2° 는 1차 학습 범위(±1°) 밖이라 한 번에 허용 안에 들지 않는다. 3차 항은 학습 범위 밖에서 커지므로(외삽) 오차가 약 0.03° 지만, 1회 보정 이동 뒤 다시 추정하면 목표 근처로 들어간다.
