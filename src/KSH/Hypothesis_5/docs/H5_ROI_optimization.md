## 1. 요청과 조건
- 하단 문과 중간 돌출부도 ROI 후보에 넣는다.
- 최적 ROI 는 학습으로 정하되, **1차의 첫 번째 측정만** 쓴다.
- 1차의 0.05 mm 묶음은 중심이 어긋난다고 알려져 있으니 다시 검증한다. 상대값으로 무의미해지면 학습에 넣는다.
- **2차는 시험에만** 쓴다.
- 결과는 ROI 범위 그림, 표·그래프(Y–Θ 좌표, 허용 회색 영역)로 낸다. 쉬운 설명 보고서, 재검증, 오버엔지니어링 검토도 포함한다.

## 3. 수행 방법
1. **후보 생성.** 기준 영상을 40 px 격자로 훑어 120×120 px 패치의 Shi–Tomasi 최소 고유값(질감)을 계산했습니다.
   - 구역마다 상위 K 개를 서로 130 px 이상 떨어지게 골랐습니다.
   - 구역 : 하단 문, 문 아래 바닥, 돌출부(브래킷 위·아래, 벽 선반), 나머지 벽.
   - 기존 벽 ROI 6개를 더해 후보는 58곳입니다.
   - 구역 좌표는 `config/roi_search.yml` 에 있습니다(없으면 기본값으로 생성).
2. **측정.** M1 과 같은 절차를 썼습니다 : 플레이트 거친 이동 → 2배 창 위상 상관 → ECC. 첫 번째와 두 번째 측정 280장 × 58곳을 쟀습니다(약 5분, `roi_meas_set1.csv` 에 저장해 다시 재지 않음).
3. **특징.**
   - s = QR 3개 평균 가로 이동
   - d = s − (선택 ROI 들의 평균 이동)
   - 기존 트랙 B(아래 벽 4곳 평균)는 이 형태의 한 경우입니다.
4. **모델 형태.** `s, d = c + a·Y + b·Θ (+ q·Θ²)` 에서 Θ² 항을 넣을지 블록 교차검증으로 정했습니다. → 직선 채택 (J 0.370 < 0.399).
5. **선택.** 블록 교차검증 오차 J = √mean((eY/90 µm)² + (eΘ/0.01°)²) 를 최소로 하는 ROI 묶음을 찾았습니다.
   - 교차검증은 14개 블록입니다 (Y 스윕 4 + Θ 스윕 10, 라벨 순으로 이어진 묶음을 통째로 뺌).
   - 탐색은 폭 5 의 빔 탐색, 추가 개선이 2 % 미만이면 중단했습니다.
6. **두 번째 측정 판정 (사전 기준).** 첫 번째 측정으로 학습한 선택 모델로 40장을 예측했습니다. 평균 치우침이 Y ≤ 22.5 µm, Θ ≤ 0.0025° 이고 95 % 이상이 허용 안이면 학습에 넣기로 했습니다.
7. **2차 시험.** 최종 모델로 57장을 예측했습니다. 기존 W1~W4 평균과 같은 조건에서 비교했습니다.
8. **정밀도 요구 시험.** 측정값을 0.01~1 px 단위로 반올림해 같은 계산을 반복했습니다.

## 4. 결과

### 4.1 중심 어긋남 (영점 = 라벨 0 근처 직선의 절편, 기준 center 대비)

| 묶음 | 플레이트 s 영점 | 시차 d 영점 |
|---|---|---|
| Y 0.1 배수 (첫 번째) | −0.229 px | −0.064 px |
| Y 0.05 홀수 (두 번째) | −0.424 px | −0.129 px |
| Θ + 쪽 | −0.667 px | −0.101 px |
| Θ − 쪽 | −0.249 px | −0.131 px |

- 0.05 묶음은 0.1 묶음보다 플레이트가 0.20 px 더 어긋나 있습니다(Y 환산 약 14 µm). 알려진 현상과 맞습니다.
- 다만 Θ 스윕도 방향에 따라 0.42 px 다르고, 첫 번째 측정의 영점도 0 이 아닙니다.
- 상대값 d 에서 추가 어긋남은 0.065 px 로 약 1/3 이 되지만 0 은 아닙니다.
- 사전 기준 판정 : 평균 치우침 Y −4.1 µm, Θ **+0.00253°** (기준 0.0025° 를 근소 초과), 40/40 허용 안. → **학습에서 제외**했습니다.

### 4.2 최적 ROI : 하단 문 홀 W2 (2867, 1357) + W3 (1010, 1677), 각 120×120 px

| 묶음 크기 | 가장 좋은 묶음 | 교차검증 J |
|---|---|---|
| 기존 | W1~W4 평균 | 0.370 |
| 1 | bottom_04 (문 아래 경첩) | 0.454 |
| **2** | **W2 + W3** | **0.360 (채택)** |
| 3 | W2 + W3 + bracket_lower_01 | 0.358 (개선 0.6 % → 중단) |

- 돌출부(브래킷·하우징)는 플레이트와 깊이가 비슷해 Y 감도가 0.04~0.8 px/mm 뿐입니다(하단 문 홀은 3.1). 시차가 거의 없습니다.
- 홀 하나만 쓰면 원근 때문에 Θ² 휨이 생깁니다(W2 −0.40, W3 +0.30 px/°²). 좌우 짝을 평균하면 −0.045 로 지워져 잡음이 σ 0.10 → 0.040 px 로 줄어듭니다.
- 문 아래 경첩(bottom_04)은 단독으로는 최고지만, Θ 반응이 반대 부호(+2.2 px/°)라 홀과 섞으면 나빠집니다.
- 최종 모델 계수 (`roi_selected.yml`) :
  - s = −0.569 + 14.139·Y + 80.061·Θ (σ 0.231 px)
  - d = −0.107 + 3.089·Y − 1.213·Θ (σ 0.040 px)

## 5. 시행착오 (모두 `backup/` 에 보관)
1. **v1** (Θ² 모델, 후보 끼리 따로 쓰는 특징, 단순 전진 선택) : W3+U2 선택, 2차 Θ 2° RMS 0.028°.
2. **모델 형태 단계 추가.** v1 의 2차 Θ 2° 오차를 본 뒤 Python 으로 Θ² 유무를 탐색했고, 이어서 C++ 에 "1차 교차검증으로 결정" 단계를 넣었습니다.
   - 결정은 1차만으로 했고(직선 J 0.370 < Θ² 0.399), 물리 모델(핀홀)도 곡률이 거의 0(0.006 px/°²)이라 같은 방향입니다.
   - 하지만 2차를 본 뒤 추가한 단계라는 점은 밝혀 둡니다.
3. **v2** (직선, 따로 쓰는 특징) : 첫 선택이 bottom 하나에 갇혀 기존보다 나빠졌습니다(J 0.467 > 0.370).
4. **v3** (평균 묶음 특징, 단순 전진) : 여전히 첫 선택에 갇혔습니다.
5. **v4** (빔 탐색) : W2+W3 를 찾았습니다.
6. **v5** : 구역을 다시 정의했습니다. 하단 문 = 홀이 있는 아래 패널, 돌출부 = 브래킷 위·아래 + 벽 선반, 좌우 여백은 비대칭. 결과는 같았습니다.
7. **v6** : 정밀도 요구 시험과 감사용 2차 측정 저장을 추가했습니다.

## 7. 오버엔지니어링 검토
- **운영에 남는 것** : M1(위상 상관 + ECC)으로 QR 3곳과 홀 2곳을 재고, 계수 6개 직선 모델로 2×2 가중 최소제곱을 풉니다. H4 트랙 B 보다 오히려 단순합니다(벽 4 → 2, Θ² 제거).
- **오프라인 도구로 둘 것** : 후보 58곳 측정, 빔 탐색, 반올림 시험, 영상 생성. 새 장비나 새 데이터가 들어올 때만 돌립니다.
- **하지 않은 것** : 3개 이상 ROI(개선 0.6 %), 날짜 간 배율 보정(2차를 학습에 써야 해서 조건 위반), 신경망(후순위).
- **결론** : 탐색의 실익은 "하단 문 좌우 홀이 최선이고 2개면 충분하다"를 근거로 확인한 것입니다. 정확도 향상 자체는 작습니다(J 2.5 %).

## 9. 수정 기록 — Windows Debug 실행 중 "Iterations do not converge" 문구 (2026-10-28)
- **원인** : 버전 차이로 결과가 달라진 것이 아닙니다. OpenCV **디버그 라이브러리**(opencv_world3415d)는 예외를 던지기 전에 오류 문구를 콘솔에 찍습니다(OPENCV_DUMP_ERRORS 기본값 켜짐). 리눅스 릴리스 라이브러리는 찍지 않습니다.
- 해당 예외는 무늬가 약한 ROI 후보에서 ECC 가 수렴하지 못할 때 납니다. 코드가 원래 잡아서 "측정 실패(NaN)"로 처리하는 정상 경로입니다. 1차 280장 × 58곳 중 605건이며, 7개 후보(bracket_lower_05·06, door_panel_06·11, bottom_01, wall_08·10)에서만 났고, 이 후보들은 선택에서 자동 제외됩니다.
- **재현** : 리눅스에서 OPENCV_DUMP_ERRORS=1 로 같은 문구를 재현했습니다.
- **수정** :
  - `m1::eccTranslation` 이 ECC 호출 동안만 `cv::redirectError` 로 문구 출력을 막고 실패 건수(`eccFailCount`)를 셉니다. 호출 뒤에는 원래 처리기로 되돌립니다.
  - RESULT.md 에 실패 건수를 한 줄로 보고합니다.
  - 설정 파일이 없을 때 FileStorage 가 찍던 "Can't open file" 문구도 존재 확인으로 없앴습니다.
- **확인** : OPENCV_DUMP_ERRORS=1 로 M1 과 H5 를 처음부터 다시 측정했습니다. 문구 0건, m1_shifts·roi_meas·예측·선택 결과가 수정 전과 비트 단위로 같습니다.
- 수정 전 파일 : `backup/code/m1_phase_ecc.v1.*.bak`, `roi_opt.v7_before_ecc_quiet.cpp.bak`
