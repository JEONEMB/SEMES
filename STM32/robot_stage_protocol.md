# robot_stage 통신 프로토콜 (Raspberry Pi ↔ STM32)

| 항목 | 내용 |
| --- | --- |
| 프로토콜 버전 | `0x01` (초안) |
| 대상 | Raspberry Pi 5 `robot_stage` 커널 드라이버 ↔ NUCLEO-F446RE 펌웨어 |
| 공용 헤더 | [`robot_stage_protocol.h`](robot_stage_protocol.h) |

이 문서는 Pi와 STM32 사이에 오가는 **바이트 형식과 동작 규칙**을 정의합니다. 양쪽 구현은 이 문서와 공용 헤더를 기준으로 하며, 변경이 필요하면 문서와 헤더를 함께 수정하고 `VER`를 올립니다.

## 1. 전체 구조

```text
[비전 앱] --ioctl--> [robot_stage 드라이버] --프레임--> cdc_acm --USB--> ST-LINK --UART--> [STM32 펌웨어]
                     프레임 조립/해석, 재전송                                              프레임 해석, 모터 구동
```

- Pi 쪽 프레임 처리는 `robot_stage` 커널 드라이버가 담당합니다. STM32 입장에서는 일반 UART 통신과 같습니다.
- **리밋 값과 물리 단위 → 펄스 변환은 STM32가 담당합니다.** Pi는 물리 단위(µm, 0.001°) 정수만 보냅니다.

## 2. 링크 설정

| 항목 | 값 |
| --- | --- |
| 연결 | NUCLEO USB (ST-LINK 가상 COM 포트), Pi에서 `/dev/ttyACM0` |
| STM32 UART | USART2 (PA2 TX, PA3 RX) |
| 설정 | 115200 bps, 8N1, 흐름 제어 없음 |
| 바이트 순서 | 리틀 엔디언 |

## 3. 프레임 구조

```text
 0      1      2     3      4     5     6 ........... 6+N-1   6+N   6+N+1
+------+------+-----+------+-----+-----+-----------------+-------+-------+
| 0xAA | 0x55 | VER | TYPE | SEQ | LEN |  PAYLOAD (N)    | CRC_L | CRC_H |
+------+------+-----+------+-----+-----+-----------------+-------+-------+
 \___ SOF ___/ \_______ 헤더 _________/                   \___ CRC16 ___/
```

| 필드 | 크기 | 설명 |
| --- | --- | --- |
| SOF | 2 | 프레임 시작 표시 `0xAA 0x55` |
| VER | 1 | 프로토콜 버전 `0x01`. 다르면 프레임을 버립니다 |
| TYPE | 1 | 메시지 종류 (4장) |
| SEQ | 1 | 명령 번호 0~255 순환. 응답은 해당 명령의 SEQ를 그대로 사용 |
| LEN | 1 | 페이로드 길이 N, 0~32 |
| PAYLOAD | N | TYPE별 데이터 (5장) |
| CRC16 | 2 | CRC-16/CCITT-FALSE, **VER~PAYLOAD** 범위, 리틀 엔디언 |

**CRC-16/CCITT-FALSE**: 다항식 `0x1021`, 초기값 `0xFFFF`, 비트 반사 없음, 최종 XOR 없음.
검증값은 `"123456789"` → `0x29B1`입니다. 구현은 공용 헤더의 `rs_crc16()`을 사용합니다.

프레임 길이는 `8 + N` 바이트이고, 최대 40바이트입니다.

## 4. 메시지 목록

TYPE `0x01~0x7F`는 Pi → STM32, `0x80~0xFF`는 STM32 → Pi입니다.

### Pi → STM32

| TYPE | 이름 | 분류 | LEN | 정상 응답 |
| --- | --- | --- | --- | --- |
| `0x01` | PING | 조회 | 0 | PONG |
| `0x02` | HOME | 동작 | 1 | ACK → DONE |
| `0x03` | MOVE_REL | 동작 | 8 | ACK → DONE |
| `0x04` | MOVE_ABS | 동작 | 8 | ACK → DONE |
| `0x05` | STOP | 동작 | 0 | ACK |
| `0x06` | GET_STATUS | 조회 | 0 | STATUS |
| `0x07` | SET_SPEED | 동작 | 8 | ACK |
| `0x08` | GET_CONFIG | 조회 | 0 | CONFIG |

### STM32 → Pi

| TYPE | 이름 | LEN | 보내는 시점 |
| --- | --- | --- | --- |
| `0x81` | ACK | 1 | 동작 명령을 수락했을 때 |
| `0x82` | NAK | 2 | 명령을 거부했을 때 |
| `0x83` | DONE | 12 | HOME/MOVE가 끝났을 때 (성공, 중단, 실패 모두) |
| `0x84` | STATUS | 20 | GET_STATUS 응답 |
| `0x85` | PONG | 4 | PING 응답 |
| `0x86` | CONFIG | 16 | GET_CONFIG 응답 |
| `0x90` | EVENT | 9 | STM32가 먼저 알릴 일이 생겼을 때 |

모든 정수는 리틀 엔디언입니다. 공용 헤더의 `struct rs_*` 구조체와 1:1로 대응합니다.

| 축 | 단위 | 타입 | 양(+) 방향 |
| --- | --- | --- | --- |
| Y | 1 = 1 µm | `int32` | 모터에서 멀어지는 방향 **(확정 필요)** |
| Θ | 1 = 0.001° | `int32` | 위에서 봤을 때 반시계 방향 **(확정 필요)** |

**STATUS flags**

| 비트 | 의미 |
| --- | --- |
| 0 | Y 원점 설정됨 |
| 1 | Θ 원점 설정됨 |
| 2 | Y- 끝 스위치 눌림 |
| 3 | Y+ 끝 스위치 눌림 |
| 4 | Θ 원점 스위치 눌림 |

**NAK 사유**

| 코드 | 이름 | 상황 |
| --- | --- | --- |
| 1 | UNKNOWN_TYPE | 정의되지 않은 TYPE |
| 2 | BAD_LEN | TYPE에 맞지 않는 LEN |
| 3 | NOT_HOMED | 원점 설정 전 MOVE |
| 4 | OUT_OF_RANGE | 목표 위치가 허용 범위 밖 |
| 5 | BUSY | 이동 중 HOME/MOVE/SET_SPEED |
| 6 | FAULT | 고장 상태에서 동작 명령 |
| 7 | BAD_PARAM | 그 밖의 잘못된 값 (예: HOME axis_mask = 0) |

## 6. 동작 규칙

### 6.1 응답 방식

- **조회 명령**(PING, GET_STATUS, GET_CONFIG)은 ACK 없이 해당 응답(PONG, STATUS, CONFIG)을 바로 보냅니다. 상태와 관계없이 언제든 응답합니다.
- **동작 명령**은 수락하면 ACK, 거부하면 NAK를 보냅니다.
- HOME, MOVE_REL, MOVE_ABS는 ACK 뒤에 **반드시 DONE으로 끝납니다.** 성공, STOP으로 중단, 리밋 감지, 고장 모두 DONE의 `result`로 구분하며, DONE의 SEQ는 원래 명령의 SEQ입니다.
- STM32는 프레임 수신 후 **20 ms 이내**에 ACK/NAK 또는 조회 응답을 보냅니다.

### 6.2 동시 실행

- 이동(HOME/MOVE)은 **한 번에 하나**만 실행합니다. 이동 중 HOME/MOVE/SET_SPEED는 `NAK(BUSY)`로 거부합니다.
- **STOP과 조회 명령은 이동 중에도 받습니다.** 이동 중 STOP을 받으면 STOP에 ACK를 보내고, 감속 정지한 뒤 진행 중이던 이동에 `DONE(result=STOPPED)`를 보냅니다.
- 대기 중 STOP은 ACK만 보냅니다.

### 6.3 SEQ와 재전송

- Pi는 새 명령마다 SEQ를 1씩 올립니다 (255 다음은 0).
- Pi는 응답을 **100 ms** 안에 받지 못하면 **같은 SEQ로 최대 3회** 재전송합니다. 그래도 없으면 통신 오류로 처리합니다.
- STM32는 마지막으로 처리한 명령의 SEQ, TYPE, 보낸 응답을 기억합니다. **직전과 SEQ와 TYPE이 같은 명령이 오면 다시 실행하지 않고 저장된 응답만 다시 보냅니다.** 재전송 때문에 같은 이동이 두 번 실행되는 것을 막기 위한 규칙입니다.
- Pi는 DONE을 기다리다 시간이 초과되면 이동 명령을 다시 보내지 않고, GET_STATUS로 상태를 확인합니다.

### 6.4 수신 오류 처리 (양쪽 공통)

- CRC가 틀리거나, VER가 다르거나, LEN이 32를 넘으면 **응답 없이 버립니다.** 송신 측은 타임아웃 후 재전송합니다.
- 버린 뒤에는 다음 바이트부터 다시 `0xAA 0x55`를 찾습니다.
- 프레임 수신 도중 **20 ms** 동안 다음 바이트가 오지 않으면 받던 프레임을 버리고 SOF 탐색으로 돌아갑니다.

### 6.5 상태 머신 (STM32)

```text
            전원 ON / 리셋 (EVENT BOOT 전송, 원점 플래그 0)
                          │
                          ▼
        ┌───────────── IDLE ◀────────────┐
        │ HOME           │ MOVE (원점 설정 후) │ DONE
        ▼                ▼                   │
     HOMING           MOVING ────────────────┘
        │                │
        └──── 고장 ──▶ FAULT ── HOME 성공 시 ──▶ IDLE
```

- 전원을 켜거나 리셋하면 원점 플래그가 0이고, `EVENT(BOOT)`를 한 번 보냅니다.
- 펌웨어 0.3.1의 Θ는 수동 원점 모드입니다. `HOME axis_mask=2`는 모터를 회전시키지 않고 정지한 현재 위치를 Θ=0으로 설정합니다. 스위치 3의 눌림/해제는 HOME 및 일반 Θ 이동을 제한하지 않습니다. STATUS bit4는 실제 스위치 입력을 계속 보고합니다.
- `HOME axis_mask=3`은 Y 물리적 원점복귀와 Θ 수동 원점 설정을 수행하고, 전체 성공 시 두 원점 플래그를 설정합니다. 실패/STOP이면 해당 HOME을 성공 처리하지 않습니다. ACK/DONE 형식과 원래 요청의 SEQ 규칙은 그대로입니다.
- Θ CONFIG 범위는 `-10000~10000` mdeg(−10°~+10°)입니다. MOVE_REL/MOVE_ABS의 최종 목표에 적용되며, HOME을 다시 실행하면 범위의 기준 위치도 바뀝니다. 이는 장비에 고정된 절대 회전 한계나 인코더 실측 위치가 아닙니다.
- 해당 축의 원점이 설정되지 않았으면 MOVE는 `NAK(NOT_HOMED)`입니다.
- FAULT 상태에서는 HOME과 STOP을 제외한 동작 명령을 `NAK(FAULT)`로 거부합니다. HOME에 성공하면 IDLE로 돌아갑니다.

### 6.6 EVENT

- 대기 중 리밋 스위치가 눌리거나 고장이 생기면 STM32가 먼저 EVENT를 보냅니다. **이동 중에 생긴 일은 EVENT가 아니라 DONE의 result로 알립니다.**
- EVENT의 SEQ는 STM32가 따로 관리하는 이벤트 번호(0~255 순환)입니다. Pi는 EVENT에 응답하지 않습니다.

## 7. STM32 담당 사항

### 7.1 리밋

- Y 양 끝 스위치, Θ 원점 스위치 감지와 소프트 리밋 판단은 모두 STM32가 합니다.
- 소프트 리밋 값은 STM32에만 두고, Pi는 필요할 때 GET_CONFIG로 조회합니다.
- Θ에는 양 끝 스위치가 없으므로 **소프트 리밋이 유일한 보호 장치**입니다. 카메라 FPC 케이블이 감기지 않는 범위로 설정합니다.

### 7.2 물리 단위 → 펄스 변환

상대 이동도 **절대 목표 위치를 기준으로** 변환해야 반올림 오차가 쌓이지 않습니다.

```c
target_um   += delta_um;                                        /* MOVE_REL */
target_steps = round_div((int64_t)target_um * STEPS_PER_MM, 1000);
move_steps   = target_steps - current_steps;
```

변환 상수는 하드웨어 설정에 따라 STM32가 정합니다. Pi와 프로토콜은 바뀌지 않습니다.

| 축 | 하드웨어 | 확인 필요 |
| --- | --- | --- |
| Y | LSM-NK223 + TMC2209 (STEP/DIR) | 리드 1 mm인지 6 mm인지, 마이크로스텝 설정 |
| Θ | PSH42 하모닉 1/100 폐루프 (PUL/DIR/ENA) | 드라이버 펄스/회전 설정 |

## 8. 시퀀스 예시

### 정상 이동

```text
Pi                                   STM32
 │ MOVE_REL seq=12 (Y=-1250, Θ=350)   │
 │──────────────────────────────────▶│
 │                  ACK seq=12        │
 │◀──────────────────────────────────│
 │                                    │ (모터 이동)
 │      DONE seq=12 result=OK         │
 │◀──────────────────────────────────│
```

### ACK 유실 후 재전송

```text
Pi                                   STM32
 │ MOVE_REL seq=13                    │
 │──────────────────────────────────▶│ 실행 시작
 │                  ACK seq=13  ✕ 유실│
 │   (100 ms 경과)                     │
 │ MOVE_REL seq=13 (재전송)            │
 │──────────────────────────────────▶│ 같은 SEQ → 다시 실행하지 않음
 │                  ACK seq=13        │ 저장된 응답 재전송
 │◀──────────────────────────────────│
 │      DONE seq=13 result=OK         │
 │◀──────────────────────────────────│
```

### 이동 중 STOP

```text
Pi                                   STM32
 │ MOVE_ABS seq=20                    │
 │──────────────────────────────────▶│
 │                  ACK seq=20        │
 │◀──────────────────────────────────│
 │ STOP seq=21                        │
 │──────────────────────────────────▶│
 │                  ACK seq=21        │
 │◀──────────────────────────────────│ (감속 정지)
 │ DONE seq=20 result=STOPPED         │
 │◀──────────────────────────────────│
```
