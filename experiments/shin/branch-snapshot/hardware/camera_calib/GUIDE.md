# 카메라 캘리브레이션 가이드

Raspberry Pi HQ 카메라(IMX477) + 6mm 렌즈를 SEMES 사진 규격에 맞추기 위한 캘리브레이션 절차와 원칙.
도구 사용법(명령어, 옵션)은 [README.md](README.md)를 본다.

## 1. 캘리브레이션을 하는 이유

| 이유 | 설명 |
|---|---|
| 렌즈 왜곡 제거 | 6mm 광각 렌즈는 사진 가장자리를 휘게 찍는다. 측정 목표(0.01° ≈ 0.8px, 0.09mm ≈ 1.3px)보다 휨이 훨씬 클 수 있다. 평평한 벽에서는 "Θ 회전 시 가장자리가 더 많이 움직이는 것"으로 Y와 Θ를 구분하는데, 렌즈 휨이 이 신호와 섞인다 |
| px → mm, ° 변환 | 알고리즘은 픽셀 이동량만 안다. 로봇에 mm·°로 명령하려면 정확한 초점거리(fx, fy)가 필요하다. 명목값(6mm)은 몇 % 틀릴 수 있다 |
| 진짜 중심점 | 렌즈 중심(cx, cy)은 센서 정중앙과 수십 px 어긋나 있다. 회전 계산과 크롭의 기준점이다 |
| SEMES 규격 맞추기 | 측정한 fx, fy로 크롭 크기를 계산해 3840×2160, fx 4018 / fy 4286 (SEMES와 같은 화각·픽셀 비율)로 변환한다 |

## 2. 용어

| 이름 | 뜻 | 단위 | 비고 |
|---|---|---|---|
| f | 렌즈 초점거리 (확대 능력) | mm | 명목 6mm (SEMES 12mm) |
| 화소 크기 | 센서 칸 하나의 크기 | µm | 사양값 1.55µm (SEMES 2.8µm) |
| **fx, fy** | 초점거리를 가로·세로 칸 수로 센 값 = f ÷ 화소 크기 | px | **캘리브레이션으로 측정** (명목 약 3871) |
| cx, cy | 사진에서 렌즈 중심 위치 | px | 캘리브레이션으로 측정 |
| 왜곡 계수 | 렌즈가 휘게 찍는 정도 (k1, k2, p1, p2, k3) | — | 캘리브레이션으로 측정 |

사진에서 움직인 픽셀 = fx × (물체 이동 mm) ÷ (거리 mm). 예: SEMES 4018 × 1mm ÷ 282mm ≈ 14.25px.

## 3. 캘리브레이션 값은 무엇으로 정해지나

캘리브레이션 값(fx, fy, cx, cy, 왜곡)은 **렌즈와 센서의 관계**로만 정해진다. 카메라를 어디에 달았는지와는 무관하다.

| 다시 해야 한다 (렌즈 쪽 변화) | 다시 안 해도 된다 (위치 변화) |
|---|---|
| 초점 링(NEAR/FAR)을 돌림 | 카메라를 다른 곳으로 옮겨 장착 (예: 하모닉 모터 위) |
| 렌즈를 뺐다 끼움 | 벽까지 거리·각도가 바뀜 |
| 백포커스 링, C-CS 어댑터를 건드림 | 재부팅, 케이블 재연결 |
| 조리개 링(OPEN/CLOSE)을 크게 돌림 | 조명·노출 변경 |
| 카메라 낙하·렌즈 충격 | |
| 센서 모드 변경 (단순 크롭 모드는 cy 보정으로 가능) | |

## 4. 진행 순서

### 4-1. 지금 (기구 조립 전, 하모닉 모터 도착 전)

캘리브레이션은 **기구가 없어도 지금 할 수 있다.** 카메라가 최종 위치에 있을 필요가 없고, 촬영하는 동안만 흔들리지 않으면 된다.

1. **초점 먼저 맞추고 잠그기 (가장 중요)**
   - 실제 촬영 거리인 **약 28~30cm** 앞에 글자나 QR을 두고 초점을 맞춘다.
   - 이유: SEMES 감도(14.25 px/mm)와 fx(4018px)로 계산한 실제 거리가 약 282mm다. 우리도 그 거리에서 찍을 것이므로, 그 거리에서 선명해야 한다.
   - 다른 거리에서 맞추면 나중에 초점을 다시 맞춰야 하고, 그러면 캘리브레이션도 다시 해야 한다.
   - 조리개는 너무 어둡지 않은 선에서 조금 조인다(초점 맞는 범위가 넓어짐).
   - **초점 링·조리개 링 고정 나사를 잠근다.** 이후 렌즈는 손대지 않는다.
2. **카메라 임시 고정**: 클램프·테이프 등으로 아무 곳에나 단단히 고정한다.
3. **체커보드 준비**: `checkerboard_A4_12x9_15mm.pdf`를 실제 크기(100%)로 인쇄하고 눈금자로 100mm 확인. 평평한 판에 붙인다.
4. **촬영 (15~25장)**: 보드를 약 30cm 거리에서 가운데·네 구석·가장자리에 두고, 20~40° 기울인 사진도 섞는다. 보드 전체가 화면 안에 들어와야 한다.
5. **계산**: `camera_calib`을 실행해 RMS 0.5px 이하인지 확인한다. 1px 넘는 사진은 빼고 다시 돌린다.
6. **결과 보관**: `camera_calib.yml`을 저장·공유한다. 촬영 날짜, 초점·조리개 상태를 함께 기록한다.

### 4-2. 하모닉 모터 도착 후 (장비 세팅, 캘리브레이션 아님)

캘리브레이션 결과는 그대로 쓴다. 바뀐 **카메라 위치**만 맞춘다.

1. 카메라를 Y 스테이지 + Θ 모터에 장착한다. **카메라 몸체·보드를 잡고, 렌즈는 잡지 않는다.**
2. 벽에서 **약 28cm, 대략 정면**으로 두고 **꽉 고정**한다.
3. **사진으로 확인**: 변환된 3840×2160 사진에서 QR 중심 간격(18mm)이 **약 257px** (= 14.25 px/mm)인지 본다. 자로 mm까지 맞출 필요 없다.
4. **남은 차이는 디지털로 보정**: 예를 들어 14.0 px/mm면 크롭 크기를 약 2% 줄여 14.25 px/mm로 맞춘다.
5. 기준 사진(`center.bmp`)을 찍고, 이동 방향 부호(로봇 + = 사진 어느 쪽)를 확인한다.
6. 이후 데이터 촬영 / 실시간 보정을 진행한다.

## 5. 원칙

- **정확함보다 "안 움직임"이 중요하다.** 282mm 대신 285mm에 둔 것은 문제가 없지만, 촬영 도중 0.5mm 움직이면 그 뒤 데이터는 모두 틀어진다.
- 우리 장비는 벽에 QR 종이를 바로 붙이므로 SEMES 장면과 다르다. 어차피 **우리 장비 데이터로 다시 학습·조정**하므로, 거리·회전축을 SEMES와 mm 단위로 똑같이 맞출 필요는 없다.
- 렌즈를 건드렸다면 캘리브레이션을 다시 한다 (체커보드 20장, 15~20분).

## 6. SEMES 규격으로 바꾸는 계산

| | 값 |
|---|---|
| SEMES 3840 사진 | fx 4018, fy 4286 (4096→3840 가로만 축소), 3840×2160 |
| 우리 (명목) | fx ≈ fy ≈ 3871 |
| 크롭 크기 | 가로 3840 × fx ÷ 4018 ≈ 3700, 세로 2160 × fy ÷ 4286 ≈ 1951 |
| 변환 | 왜곡 펴기 → (cx, cy) 중심으로 크롭 → 3840×2160 리사이즈. 실제로는 `initUndistortRectifyMap`(목표 K = SEMES 값)으로 만든 변환표 하나로 처리 |

같아지는 것: 크기, 화각, 픽셀 비율, 왜곡 없음, 흑백 8비트.
변환만으로는 안 되는 것: px/mm·px/° (거리·회전축 세팅 필요), 실제 디테일(약 10% 낮음), 배경 깊이.
