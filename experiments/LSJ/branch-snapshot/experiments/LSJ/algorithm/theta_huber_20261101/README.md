# 상·하단 구조물 기반 θ 보정 작성본

이미지 한 장에서 외부 구조물의 상·하단 각도를 측정하고, **Y가 섞여 있을 때의 θ를 계산해 θ 보정치 한 개를 반환**한다. 기존 dev 스켈레톤의 `Alignment_t alignment(cv::Mat &src)` 형태를 유지했다.

현재 단계는 θ 모듈 구현이다. Y 보정은 다음 단계이므로 반환 구조체의 `y=0`은 **Y 이동 명령 없음**을 뜻한다. Y 정렬 완료를 뜻하지 않는다.

## 처리 순서

```text
3840×2160 이미지 1장
  → 그레이스케일
  → 세로 Sobel (dx=0, dy=1, ksize=3)
  → 상·하단 탐색 영역의 각 x열에서 signed Gy 최대 위치 선택
  → 상단 점들을 일반 Huber로 직선 피팅 / 하단도 별도로 피팅
  → 각 직선의 기울기 m에서 영상 각도 atan(m) 계산
  → 두 영상 각도로 Y와 θ가 섞인 두 식을 풀어 θ 추정
  → θ 보정치 = 목표 θ − 추정 θ
```

### 1. 경계점 추출

기존 분석의 설정을 그대로 옮겼다. 좌표는 원본 픽셀 기준이며 구간 양 끝을 포함한다.

| 항목 | 상단 | 하단 |
|---|---|---|
| x 탐색 범위 | 24~3816 | 24~3816 |
| y 탐색 범위 | 692~736 | 1845~1905 |
| 중앙 가림 x 범위 | 1370~2450 | 1560~2300 |
| 선택점 개수 | 2,712 | 3,052 |

Sobel 결과는 `CV_32F`, 경계 처리는 `BORDER_REFLECT_101`이다. 가로로 1px씩 이동하며 각 열에서 **부호를 유지한 세로 응답의 최대값**을 고른다. 동률이면 가장 위쪽 위치를 선택한다. 모든 응답이 음수인 열도 최대값을 그대로 선택한다. 중앙 가림을 제외한 좌우 점들은 합쳐서 구조물 하나당 직선 하나로 만든다.

### 2. 일반 Huber 직선 피팅

직선은 `y = b + m*x`이고 잔차는 세로 거리 `y_i − (b + m*x_i)`다.

- 시작 직선: 일반 최소제곱(OLS).
- 잔차 규모: `s = median(abs(residual)) / 0.6744897501960817`.
- 영향 감소 기준: `τ = 1.345 × s`. 1.345px로 고정하지 않는다.
- 가중치: `|residual/s| ≤ 1.345`이면 1, 그 밖에서는 `1.345 / |residual/s|`.
- 가중 최소제곱을 반복하며 `s`도 매번 다시 계산한다.
- 기존 검증 설정: 최대 50회(초기 OLS 포함), deviance 변화량 `1e-8` 이하에서 종료.

검증한 statsmodels 0.15.0 구현을 C++로 옮겼다. 특히 해당 구현의 종료용 deviance는 **WLS 잔차 분산으로 잔차를 나누어 계산**한다. 가중치에 사용하는 MAD 규모와 다른 계산이며, 이전 검증과 맞추기 위해 그대로 유지했다. `cov='H1'`로 계산했던 계수 공분산은 이 모듈의 직선/보정치 반환에 사용하지 않으므로 구현하지 않았다.

Gaussian, 응답 8 미만 제거, 초기점에서 2px 이동 시 제거, 직선에서 1~2px 밖의 점 제거, 최소 점 개수 품질 필터는 적용하지 않는다. `n>2`와 x 변화 존재 여부 검사는 이 피팅의 잔차 자유도·직선 계산이 정의되는지 확인하는 수학적 검사다. 규모가 0인 경우 임의의 작은 값을 넣지 않고 오류를 반환한다.

### 3. 이번에 추가한 θ 계산

현재 영상 각도를 각각 `φ상`, `φ하`라고 할 때 아래 두 식을 사용한다.

```text
φ상 = b상 + aY상 × Y + aθ상 × θ
φ하 = b하 + aY하 × Y + aθ하 × θ
```

예를 들어 상단 각도만 달라지면 Y와 θ 중 어느 영향인지 구별하기 어렵다. 상·하단 각도 두 개를 함께 넣어 두 식의 미지수 Y와 θ를 구한다. 이때 Y는 θ를 분리하기 위한 내부 계산값이며 실제 Y 보정 명령으로 내보내지 않는다.

**새 모델 가정은 Y와 θ의 영향을 더한 하나의 선형식으로 표현한다는 것이다.** 앞서 구간별 민감도를 조사한 결과에서 자동으로 보장되는 사실은 아니다. 이번 구현의 첫 모델로 만들었으며, 테스트 성능에 따라 이 부분을 판단할 수 있도록 이미지 처리와 분리했다.

2차 (1)·(2)번 40장에 일반 최소제곱을 적용한 계수는 다음과 같다. 반복 사진을 평균 내거나 가중치를 붙이지 않고 40장을 각각 한 관측으로 사용했다.

| 구조물 | b (영상 °) | aY (영상 °/mm) | aθ (영상 °/장비 °) |
|---|---:|---:|---:|
| 상단 | 0.2714001061540482 | −0.0013007004607225314 | −0.08820199315018504 |
| 하단 | 0.2166220179900279 | −0.000538170429168372 | 0.19791396218238544 |

`φ = atan(m) × 180/π`이며 이미지 y축은 아래쪽이 양수다. 위 표의 영상 각도와 장비 θ 각도는 서로 다른 값이다.

두 식을 푸는 계산은 다음과 같다.

```text
u = φ상 − b상
l = φ하 − b하
D = aY상*aθ하 − aθ상*aY하
θ추정 = (aY상*l − aY하*u) / D
θ보정 = θ목표 − θ추정
```

목표 θ는 설정 파일의 `target_theta_deg=0`이다. 기준은 **2차 데이터의 라벨 영점**이다. 실제 기계적 영점을 새로 확인했다는 뜻은 아니다. 보정치는 연속 각도로 출력하며 tick 반올림, 명령 크기 제한, 20회 반복 관리는 추가하지 않았다. 입력 이미지 한 장당 보정치 한 번을 계산한다.

## 데이터 분리

사용자가 지정한 분리를 고정했다.

| 용도 | 데이터 | 장수 |
|---|---|---:|
| 계수 계산·C++ 구현 확인 | 2차의 (1)·(2)번, center1·center2 포함 | 40 |
| 보류 테스트 | 2차의 (3)번, center3 포함 | 20 |
| 보류 테스트 | 3차 전체 | 234 |

1차의 다른 라벨 영점은 이번 2차 기준 모델에 섞지 않았다. `calibration/data_split.json`에 이미지 경로·해시·분리 내역을 저장했다. 계수 계산 스크립트는 선정된 40장의 기존 Huber 각도만 사용한다. 테스트 254장의 각도는 계수 계산에 넣지 않는다.

전체 자료는 이전 분석에서 이미 살펴본 상태이므로 이후 평가는 이 모델의 **고정 내부 테스트**다. 지금까지 전혀 열어 보지 않은 독립 자료라고 표현하지 않는다. 구현 검증까지는 테스트를 보류했고, 이후 사용자의 실행 요청으로 진행한 254장 평가는 아래 별도 보고서에 기록했다.

## 실행

프로젝트 루트 PowerShell에서 빌드한다. 기존 OpenCV 3.4.15와 MSVC v141 환경을 사용한다.

```powershell
& '.\algorithm\theta_huber_20261101\tools\build.cmd'
```

프로젝트 루트에서 이미지 한 장을 입력한다.

```powershell
& '.\.tmp\theta_huber_20261101_build\Release\theta_alignment.exe' `
  '.\algorithm\theta_huber_20261101\config\calibration.json' `
  'C:\실제\이미지경로.bmp'
```

출력은 표준 출력 JSON이다. `theta_estimate_deg`는 추정 θ, `theta_correction_deg`는 목표까지의 보정치다. `nuisance_y_estimate_mm`는 θ 분리를 위한 내부 Y 추정값이다. `y_command_available=false`이며 Y 명령을 생성하지 않는다. 실제 정렬 완료 판정은 출력하지 않는다.

스켈레톤에 붙일 때는 프로그램 시작 시 한 번 설정을 읽는다.

```cpp
configureThetaAlignment("algorithm/theta_huber_20261101/config/calibration.json");
Alignment_t command = alignment(image); // command.t: θ 보정 °, command.y: 0
```

빈 이미지·크기/형식 불일치·계산 불능·Huber 반복 제한 도달은 예외로 반환한다. CLI는 오류 메시지와 종료 코드 1을 내고 보정 JSON을 생성하지 않는다. 성공한 것처럼 0 명령으로 바꾸지 않는다.

## 구현 확인 결과

- 기존 OpenCV 3.4.15/MSVC v141에서 Release 빌드 성공.
- 알려진 Y·θ에 대한 식 복원, 보정 부호, 경계점 선택, 이상 입력, 반복 제한 구분 등 구성요소 테스트 통과.
- 계수 계산용 40장 × 상·하단 = 80개 직선을 C++에서 계산했다.
- 경계점 230,560개의 좌표가 기존 Python 결과와 모두 정확히 일치했다.
- 직선 각도 최대 차이: 약 `5.03e-13°`.
- SVD 구현·부동소수점 계산 차이로 80개 중 19개는 종료 반복 횟수가 달랐다. 위 최종 각도 차이는 이를 포함한 값이다.
- 원래 `alignment()` 인터페이스의 출력이 새 Detector 출력과 일치했다.
- 보류 테스트 이미지 실행 수: 0.

수치 비교의 테스트 허용값은 **C++ 이식 회귀 테스트용**이다. 이미지의 점을 제거하거나 정렬 성공을 판정하는 기준으로 사용하지 않는다. 상세 결과는 `validation/parity_summary.json`에 있다.

위 `validation/` 결과는 구현 당시의 이식·인터페이스 검사 기록이다. **후속 고정 테스트에서는 254장 중 82장(32.3%)만 ±0.005° 이내였고, 현재 모델은 목표 정확도를 충족하지 못했다.** 2차는 3/20장, 3차는 79/234장이 범위 안이었다. 코드와 계수를 변경하지 않은 전체 결과는 [254장 테스트 보고서](../../analysis/theta_huber_holdout_20261101/report.html)에 있다. 이 시험은 이미지 라벨 대비 보정치 평가이며 실제 장비 이동 후 결과는 아니다.

학습 좌표 범위는 Y=0~1mm, θ=0~2°다. 음의 θ 등 그 밖의 구간도 식 계산 자체는 가능하지만 해당 범위의 보정 정확도는 이번 계수에서 확인되지 않았다.
