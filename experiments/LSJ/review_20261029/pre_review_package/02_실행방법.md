# 검증 실행 방법

새 빌드/출력 폴더를 사용하여 기존 코드와 검증 기록을 보존하세요. **아래는 검토자가 재현할 명령이며, 전달서 작성 과정에서 새로 실행한 로그가 아닙니다.**

## 1. 이 PC의 실제 작성본을 읽을 수 있는 경우

PowerShell에서 설정합니다. 변수 이름은 사용자 홈/시스템 변수와 겹치지 않습니다.

```powershell
$projectRoot = 'C:\Users\SSAFY\Desktop\LSJ_Private\자율PJT'
$codeRoot = Join-Path $projectRoot '.tmp\theta_implementation_20261029\payload'
$reviewRoot = Join-Path $projectRoot '.tmp\claude_alignment_review_20261029'
$reviewBuild = Join-Path $reviewRoot 'build'
$cmakePath = 'C:\Program Files (x86)\Microsoft Visual Studio\18\BuildTools\Common7\IDE\CommonExtensions\Microsoft\CMake\CMake\bin\cmake.exe'
$ctestPath = 'C:\Program Files (x86)\Microsoft Visual Studio\18\BuildTools\Common7\IDE\CommonExtensions\Microsoft\CMake\CMake\bin\ctest.exe'
```

다음 명령은 알려진 로컬 환경(MSVC v141, OpenCV 3.4.15 vc15)을 사용합니다.

```powershell
& $cmakePath -S $codeRoot -B $reviewBuild -G 'Visual Studio 18 2026' -A x64 -T v141 '-DCMAKE_GENERATOR_INSTANCE=C:/Program Files (x86)/Microsoft Visual Studio/18/BuildTools' '-DOpenCV_DIR=C:/Users/SSAFY/opencv/build' -DBUILD_TESTING=ON
# 이전 명령이 성공한 경우에만 다음 명령 실행
& $cmakePath --build $reviewBuild --config Release -- /m:1 /v:minimal
& $ctestPath --test-dir $reviewBuild -C Release --output-on-failure
```

예상 CTest 항목은 `theta_alignment_contract`, `y_alignment_contract` 두 개이며 성공 종료 코드는 0입니다. 새 환경에서는 본인이 실제 실행한 결과를 보고하세요. 위 내용이 성공을 미리 보장하지 않습니다.

## 2. 원본 기준 영상을 이용한 추가 통합 테스트

원본 이미지가 존재하는 같은 PC에서만 가능합니다.

```powershell
$referencePath = Get-Content -LiteralPath (Join-Path $projectRoot '.tmp\theta_implementation_20261029\reference_path.txt') -Encoding UTF8 -Raw
Test-Path -LiteralPath $referencePath
Push-Location -LiteralPath $codeRoot
try {
    & (Join-Path $reviewBuild 'Release\y_alignment_test.exe') 'configs/theta_alignment.json' 'configs/y_alignment.json' '../reference_path.txt'
} finally {
    Pop-Location
}
```

테스트는 원본을 읽고 메모리에서 가로 5px 이동한 이미지를 생성합니다. 원본을 변경하거나 실제 로봇을 움직이지 않습니다. config/경로목록 인자는 위처럼 ASCII 상대 경로를 쓰고, UTF-8 경로목록 내부에 한글 원본 경로를 넣습니다. C++ 테스트 실행 파일의 일반 `main(char**)` 인자와 CLI의 Windows `wmain` 처리를 혼동하지 마세요.


## 3. CLI 한 장 실행

```powershell
Push-Location -LiteralPath $codeRoot
try {
    & (Join-Path $reviewBuild 'Release\main.exe') --reference $referencePath --config 'configs/theta_alignment.json' --y-config 'configs/y_alignment.json' --output (Join-Path $reviewRoot 'center_review.json') $referencePath
} finally {
    Pop-Location
}
```

위 기준 영상 자기 비교의 기존 결과는 `status=aligned`, 두 명령 0입니다. 이것은 좌표/연결 확인이며 물리적 영점 정확도 시험이 아닙니다.

- `--y-config`를 생략하면 θ 단독 모드이므로 Y 통합 시험으로 보고하지 마세요.
- 종료 코드 0은 모든 입력에서 명령 계산 또는 완료 판정이 가능했다는 뜻이며, 모든 입력이 정렬 완료라는 뜻은 아닙니다.
- 코드 1은 일부 이미지의 측정 실패 또는 명령 산출 불가를 포함합니다. JSON의 `valid`, `status`, `command_available`, `aligned`를 함께 확인하세요.
- 코드 2는 인자/초기화 오류입니다.
- 원본·설정·기존 로그와 다른 출력 경로를 쓰세요. 경로 보호의 취약성을 재현할 때에는 임시 복사본만 사용하세요.

## 4. ZIP만 사용할 수 있는 다른 채팅/환경

먼저 압축을 풀고 `00_검증요청서.md`, `01_검증파일목록.md`, `payload/` 소스를 읽습니다. `$codeRoot`는 압축 해제 위치의 `payload`로 바꾸고, 빌드는 별도 디렉터리에 생성합니다. `baseline_dev/`와 비교하면 GitLab 접근 없이도 원래 인터페이스를 확인할 수 있습니다.

원본 BMP는 ZIP에 없으므로 영상 통합 테스트는 기본적으로 실행할 수 없습니다. CTest의 수치/합성 테스트는 원본 BMP가 필요하지 않지만 C++/OpenCV 빌드 환경은 필요합니다. 다른 운영체제나 OpenCV 버전에서 실행했다면 차이를 기록하세요. 환경이 없으면 정적 검토만 수행하고, 빌드/실행/실제 이미지 검증을 했다고 표현하지 마세요.

같은 PC에서 ZIP 복사본으로 원본 통합 시험을 할 경우 `y_alignment_test.exe`의 마지막 인자는 `../context/reference_path.txt`가 됩니다. 원본 작성본의 `../reference_path.txt`와 경로가 다릅니다.

## 5. 기존 헬퍼 스크립트 주의

`.tmp/theta_implementation_20261029/verify_y_implementation.py`는 당시 실행 절차의 근거로 읽을 수 있습니다. 다만 내부에 기존 `validation/` 로그와 `validation_summary.json`을 쓰는 동작이 있으므로 **이 리뷰에서 원본 스크립트를 그대로 재실행하지 마세요.** 필요한 검사는 위처럼 새 출력 디렉터리를 사용하거나 별도 복사본에서 경로를 수정해 수행하세요.

`export_y_config.py`도 기존 결과를 설정으로 복사하는 스크립트이지 검정 알고리즘이 아닙니다. 현재 리뷰에서 실행하여 설정 파일을 덮어쓸 필요가 없습니다.
