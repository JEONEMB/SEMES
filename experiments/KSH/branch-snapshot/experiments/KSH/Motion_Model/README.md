# Motion_Model — 운동 모델 계산기 (Y·Θ 에 따라 영상이 어떻게 움직이는가)

> 원본 위치 : VS 프로젝트 `QR_Image` (2026-10-27). 이 폴더의 `code/` = 프로젝트의 `src/`, `project/` = 당시 `QR_Image.vcxproj(.filters)`.
> 다시 빌드하려면 `code/` 를 프로젝트의 `src/` 로, `config/` 를 그대로, `project/` 의 vcxproj 를 프로젝트 폴더에 두고 `img/` 를 함께 배치합니다.

로봇 자세 (Y 이동, Θ 회전)가 바뀔 때 카메라 영상의 각 점이 어떻게 움직이는지를 **3D 카메라 모델**로 계산하고,
OpenCV 화면으로 보여 주며, 실제 사진과 비교해 모델이 맞는지 확인하는 프로젝트입니다.

- 이전 실험 코드(H1 Gabor, H2 ECC, Center_check, H3·H6·H7)는 git 저장소 `src/KSH/Hypothesis_1~3/` 로 옮겼습니다.
- 환경 : C++20, OpenCV 3.4.15 (`C:\opencv\build`), Visual Studio (x64 Debug/Release)

## 3. 운동 모델

좌표 : 기준 카메라 = 세계 좌표 (x 오른쪽, y 아래, z 앞, mm).

```
카메라     K = [fx 0 cx; 0 fy cy; 0 0 1],  fx = fy × 15/16 (센서 4096 → 출력 3840, 가로만 축소)
           방사 왜곡 : x_d = x·(1 + k1·r²)
Y 이동     카메라 중심 C = (−Y, 0, 0)                    → 장면이 +x 로 fx·Y/Z 이동 (깊이에 반비례)
Θ 회전     R = R_y(−Θ),  C = A − R·A,  A = (0, 0, a)    → 광학 중심 앞쪽 a mm 의 세로축 둘레 회전
투영       Xc = Rᵀ(X − C),  u = fx·Xc.x/Xc.z + cx,  v = fy·Xc.y/Xc.z + cy

작은 각 근사 (화면 2·3 의 회색 선, 왜곡 무시)
  Δu ≈ fx·Y/Z + fx·Θ·(1 + u²/fx²) − fx·a·Θ/Z
  Δv ≈ Θ·u·v/fx
깊이 Z 정면 평면의 호모그래피 (k1 = 0)
  H = K · Rᵀ · (Z·I − C·e3ᵀ) · K⁻¹
```

이 식에서 과제의 구조가 바로 보입니다.

1. **평균 이동은 Y 와 Θ 가 거의 같다** : 플레이트 중심 이동 = 14.25·Y + 80.06·Θ (px). Y 1 mm ↔ Θ 0.178°.
2. **Θ 에만 있는 성분 (QR 단독 단서)** : 가로 2차 항(U 자), 좌·우 QR 폭 차 (0.6 px/°), 세로 u·v 항.
3. **깊이에 따라 다른 성분 (배경 활용 단서)** : Y 이동은 1/Z 에 비례 → 플레이트(14.2 px/mm)와 아래 벽(11.1 px/mm)이 다르게 움직임.

## 4. 화면

| 화면 | 보여 주는 것 |
|---|---|
| 1 Field | 현재 자세의 화면 전체 변위 화살표, QR 위치(초록 = 현재, 회색 = 기준), 평균 이동을 뺀 나머지(Δu, Δv) 색 지도 |
| 2 Separation | 같은 플레이트 이동을 만드는 Y 와 Θ 의 변위장 비교 — Y 는 평평, Θ 는 U 자. 둘의 차이가 Y·Θ 구분 신호 |
| 3 Profile | QR 높이 가로 단면의 Δu, (Δu − 중심 이동), Θ 의 Δv. QR L·C·R 위치 표시 |
| 4 Depth | 깊이별 이동량 (Y ∝ 1/Z, Θ ≈ 일정), 플레이트·배경 2 × 2 감도 행렬, 이동량 잡음 0.011 px 일 때의 Y·Θ 정밀도 |
| 5 Real vs model | 실제 사진의 QR 띠, 모델로 다시 그린 띠, 차이 영상 + 영역별(QR 3, 위 벽 2, 아래 벽 4) 실측·모델 이동량 |

화면 5 의 기준 영상 : 1차 세트 = `center.bmp`, 2차 세트 = `center1.bmp`.
실측은 위상 상관(거친 이동) → ECC 평행이동(정밀) 으로 재며, 모델 값은 쓰지 않습니다.

### 개발 환경 시험 결과 (사진 70장 일부, 리눅스 OpenCV 4.6)

| 영역 | 제원 모델 잔차 RMS | 데이터 맞춤 B 잔차 RMS |
|---|---|---|
| 플레이트 QR (1차 / 2차) | 0.57 / 0.61 px | 0.54 / 0.56 px |
| 위쪽 벽 (1차 / 2차) | 1.18 / 1.97 px | 0.50 / 0.50 px |
| 아래쪽 벽 (1차 / 2차) | 2.57 / 5.14 px | 0.45 / 0.56 px |

- 제원 모델(렌즈 앞면 385 mm 기준)은 플레이트 이동은 맞지만, **배경 벽의 Θ 이동을 3 % 정도 크게 예측**합니다. 화면 가장자리의 2차 항·왜곡·회전축 위치가 아직 정확하지 않다는 뜻입니다.
- 데이터 맞춤 모델은 모든 영역을 0.5 px 수준으로 맞추지만, 벽이 "깊이가 멀다"와 "화면 가장자리"를 함께 가져 **fx·회전축·k1 이 서로 얽힙니다**. 예측용(실효) 모델로만 쓰고 개별 값을 물리값으로 해석하지 마세요.
- 전체 341장으로 `--batch` 를 다시 실행하면 감도 회귀가 더 정확해집니다.

## 6. 주의

- `cv::phaseCorrelate` 에 창 함수를 넘기면 크기가 DFT 최적 크기일 때 **입력 영상을 제자리에서 곱해 버립니다**. 기준 영상의 일부(ROI)를 넘기면 기준 영상이 망가지므로 항상 `.clone()` 해서 넘깁니다 (`real_compare.cpp`).
- 영상 위 글자는 OpenCV 한계로 영어만 씁니다. 콘솔 출력은 UTF-8 (`SetConsoleOutputCP`).
