# QR Y·Θ 분리 — 데이터 EDA 및 자동 분석 툴 계획서

> 이 문서는 Claude Code 에 작업을 지시하기 위한 계획서다.
> **한 번에 한 단계(Stage)씩** 진행하고, 단계가 끝나면 결과를 요약해 보고한 뒤 사용자 확인을 받고 다음 단계로 넘어간다.
> 지시 예 : "EDA_PLAN.md 의 Stage 0 을 수행해줘"

---

## 1. 목적

1. 측정 알고리즘을 다시 고르기 전에, **데이터 자체가 무엇을 담고 있는지** 단계적으로 확인한다.
   - 1차 데이터 : Y 이동 사진과 Θ 회전 사진을 비교해 **둘을 가르는 단서가 무엇이고, 잡음보다 얼마나 큰지** 찾는다.
   - 2차 데이터 : Y·Θ 동시 이동에서 1차의 단서가 그대로 성립하는지 확인한다.
2. 데이터는 앞으로도 계속 들어온다. EDA 의 각 단계를 **재사용 가능한 모듈**로 만들어, 새 세트가 들어오면 명령 한 줄로 같은 분석과 보고서가 나오게 한다.
   - 즉, **툴을 만들면서 그 툴로 1·2차 EDA 를 수행**한다.

## 2. 고정 사실 (배경 지식)

| 항목 | 값 |
|---|---|
| 과제 | SEMES×SSAFY 비전 기반 2축(Y·Θ) 로봇 얼라인먼트 |
| 판정 기준 | 사진마다 Θ 오차 ±0.01°, Y 오차 ±90 µm |
| 불변 대상 | **QR 3개만 불변** (한 변 13 mm 정사각형, QR 사이 간격 5 mm). 플레이트·배경은 현장에서 바뀔 수 있음 |
| 영상 | 3840 × 2160, BMP (EXIF 없음) |
| 대략적 감도 (기존 분석) | Y 1 mm ≈ 14.1 px, Θ 1° ≈ 80 px 가로 이동 → **Y 1 mm ≈ Θ 0.177°** 가 화면에서 같은 이동 |
| 핵심 난점 | Y 와 Θ 모두 화면에서는 거의 같은 옆 이동. 차이는 원근 효과(좌·우 QR 의 배율 차 등)뿐이며, Θ 0.01° 구분에는 약 0.003 px 수준의 변화가 필요 |
| 기존 결론 | QR 만 쓰는 방법들의 한계 ≈ 사진당 0.017~0.02°. 남은 오차는 촬영 잡음(반복성 0.003°)이 아닌 **자세마다 바뀌는 계통 오차** |

## 3. 작업 원칙 (Claude Code 준수 사항)

1. **단계별 진행** : 한 번에 한 Stage. 끝나면 핵심 결과 3~5줄 + 대표 그림 경로를 보고하고 멈춘다.
2. **가정 금지** : 파일 이름 규칙, 세트 구성, 시각 정보는 반드시 실제 파일로 확인한다. 모르는 것은 추측하지 말고 묻는다.
3. **원본 보존** : `img\` 안의 원본 영상은 수정·이동·삭제하지 않는다. 모든 결과는 `eda_results\` 아래에 쓴다.
4. **커밋 금지** : commit / push 는 사용자가 요청할 때만 한다. `img`, 명세서, `.CLAUDE` 는 커밋 대상이 아니다.
5. **범위 밖 작업 확인** : 기존 코드 리팩터링, 파일 삭제, 기존 C++ 프로젝트 설정 변경은 먼저 확인받는다.
6. **언어·형식**
   - 분석 툴은 **Python** (numpy, opencv-python, pandas, matplotlib, imageio). 최종 측정 알고리즘만 C++ 로 유지.
   - 그림 글꼴은 한글이 깨지지 않게 설정한다 (예 : Malgun Gothic).
   - 표는 UTF-8 (BOM 포함) CSV — 엑셀에서 바로 열리도록.
7. **재계산 최소화** : 사진마다 계산한 값은 파일 해시 기준으로 `cache\` 에 저장하고, 새 사진만 계산한다.
8. **수치 표기** : 단위를 항상 함께 적는다 (px, µm, °). 판정 기준(±0.01°, ±90 µm)과 비교 가능한 형태로 보고한다.

python eda_tool\qr_eda.py --all                  # 모든 세트 + 세트 간 비교 + 누적 요약
python eda_tool\qr_eda.py --set ... --stages 2 --force   # 캐시 무시 재계산

## 5. 단계별 계획

각 Stage 는 **목표 → 입력 → 처리 → 산출물 → 완료 조건 → 보고할 질문** 순서로 기술한다.

### Stage 0. 데이터 목록 점검 + 촬영 과정 영상(기본판)

- **목표** : 데이터 구성이 맞는지 확인하고, 촬영 순서를 복원한다.
- **입력** : `img\` 전체
- **처리**
  1. 폴더 구조와 파일 이름 규칙을 조사해 지령값(Y mm, Θ °)과 종류(Y / Θ / 혼합 / 기준)를 해석한다.
  2. 해상도, 비트 깊이, 파일 크기, 해시를 기록하고 누락·중복(같은 해시)을 찾는다.
  3. **생성일시와 수정일시를 모두** 추출한다.
     - Windows 에서 파일을 복사하면 생성일시가 복사 시각으로 바뀌고 수정일시는 유지되는 경우가 많다.
     - 두 시각 중 어느 쪽이 실제 촬영 순서로 타당한지 판단한다 (간격의 규칙성, 지령값 순서와의 일치, 같은 시각에 몰린 파일 수).
     - 둘 다 신뢰할 수 없으면 **멈추고 사용자에게 원본 촬영 로그·원본 PC 파일 여부를 묻는다.**
  4. 촬영 순서로 각 사진의 **접근 방향**(직전 지령값보다 큰 쪽에서 왔는지 / 작은 쪽에서 왔는지)을 계산한다.
  5. **A-1 촬영 과정 영상(기본판)** 을 만든다 (6장 참고).
- **산출물**
  - `tables\catalog.csv` : 사진 1장당 1행 — 파일명, 세트, 종류, 지령 Y, 지령 Θ, 생성일시, 수정일시, 채택 시각, 촬영 순번, 접근 방향(Y·Θ 각각), 해상도, 해시
  - `tables\inventory_summary.csv` : 세트별 장수, 지령값 범위·간격, 누락·중복 목록
  - `figures\s0_command_dist_*.png` : 1차 Y·Θ 스윕 값 분포, 2차 (Y, Θ) 산점도
  - `figures\s0_timeline_*.png` : 촬영 순번에 따른 지령값 (접근 방향 색 구분)
  - `videos\<세트>_shooting.gif`, `.mp4`
  - `img\<세트>\set.yaml` 초안 (사용자 확인 전까지 `eda_results\set_yaml_draft\` 에 저장)
- **완료 조건** : 모든 영상이 catalog 에 있고 지령값이 해석됨. 해석 불가 파일은 목록으로 따로 보고.
- **보고할 질문** : 장수·범위가 예상과 맞는가? 어떤 시각을 채택했고 근거는? 접근 방향이 섞여 있는가?

### Stage 1. 영상 화질과 환경

- **목표** : 영상 자체가 고른지, 측정 오차와 화질 사이에 관계가 있는지 확인한다.
- **입력** : catalog, 영상
- **처리**
  1. QR 3개 영역(대략 위치는 기준 영상에서 검출)마다 평균 밝기, 대비(표준편차), 포화 화소 비율, 초점(라플라시안 분산)을 계산한다.
  2. 같은 지령값의 연속 촬영 사진이 있으면 차영상으로 **촬영 잡음 크기**를 구한다.
  3. 영상마다 밝기가 크게 변하는 영역(반사 : 나사 구멍 등)을 찾는다.
  4. 기준값에서 크게 벗어난 사진에 경고 표시를 한다 (기준은 세트 내 중앙값 ± 3 MAD).
  5. A-1 영상에 화질 경고를 표시한 버전을 만든다.
- **산출물**
  - `tables\quality.csv` : 사진별 QR별 밝기·대비·포화·초점, 경고 플래그
  - `figures\s1_quality_trend_*.png` : 촬영 순번에 따른 화질 추이, 1차 vs 2차 비교
  - `figures\s1_noise_map_*.png` : 연속 촬영 차영상과 잡음 크기(px)
  - `figures\s1_reflection_*.png` : 반사 영역 표시
- **완료 조건** : 모든 사진에 화질 값이 있고, 경고 사진 목록이 정리됨.
- **보고할 질문** : 다시 찍어야 할 사진이 있는가? 1·2차 사이 조명·초점 차이가 있는가?

### Stage 2. 1차 데이터 — Y 이동 vs Θ 회전 비교 (핵심)

- **목표** : Y 와 Θ 를 가르는 단서의 종류·크기·잡음 대비 비율을 찾는다.
- **입력** : catalog (1차), 영상
- **처리**
  1. **QR 꼭짓점 검출** : 장마다 QR 3개의 꼭짓점 4개씩(총 12개)을 서브픽셀로 검출한다. 검출 실패·불안정 사진은 표시.
  2. **C-1 Center 정의** (7장) : QR 중심, 플레이트 중심을 정의하고 계산한다.
  3. **특징 계산** (장마다)
     - QR별 중심 x·y, 변 길이 4개, 면적
     - QR 간 간격 (L–C, C–R)
     - 기울기 (roll)
     - 사다리꼴 정도 (QR별 왼쪽 변 − 오른쪽 변, 위 변 − 아래 변)
     - 좌·우 QR 크기 비
  4. **선형성** : 각 특징을 지령값(Y 또는 Θ)에 대해 1·2차 적합 → 기울기(단위당 변화), 잔차 크기, 잔차 패턴.
  5. **짝지은 차영상** : 화면 가로 이동량이 같은 Y 사진과 Θ 사진 쌍(예 : Y 1 mm ↔ Θ 0.177°)을 찾아, 이동을 맞춘 뒤 차영상을 만든다. 차이가 화면 어디에 나타나는지 지도로 표시.
  6. **변위장 비교** : 기준 영상 대비 QR 영역 dense flow 를 구해, Y 단위 이동당·Θ 단위 회전당 평균 패턴을 화살표·색 지도로 비교.
  7. **분리도 순위** : 특징마다
     - Y 1 mm 당 변화, Θ 0.177° 당 변화 (화면 이동이 같을 때의 차이 = 구분 신호)
     - 같은 지령값 반복·잔차로 구한 잡음 σ
     - 신호/잡음 비, Θ 0.01° 를 구분하는 데 필요한 정밀도 대비 여유
     를 계산해 순위를 매긴다.
  8. **B QR 정보 그래프** 와 **A-2 동기화 영상**(Y 스윕·Θ 스윕 나란히)을 만든다 (6장).
- **산출물**
  - `tables\features.csv`, `tables\linearity.csv`, `tables\separability.csv`
  - `center\center_definition.json`, `center\center_by_image.csv`
  - `figures\s2_feature_vs_cmd_*.png` (Y 스윕과 Θ 스윕 겹쳐 그림)
  - `figures\s2_paired_diff_*.png`, `figures\s2_flow_compare_*.png`
  - `figures\s2_separability_rank.png`
  - `figures\qr_info_*.png`, `videos\set1_sync_*.mp4/gif`
- **완료 조건** : 분리도 순위표가 완성되고, 상위 단서마다 "Θ 0.01° 에 해당하는 신호 크기 vs 잡음" 이 숫자로 정리됨.
- **보고할 질문** : Y·Θ 를 가장 잘 가르는 단서는? 그 단서로 Θ 0.01° 구분이 이론적으로 가능한가? 꼭짓점 검출 자체의 정밀도는?

### Stage 3. 2차 데이터 — Y·Θ 혼합 이동

- **목표** : 1차의 단서가 동시 이동에서 성립하는지, 날짜 간 차이가 얼마인지 확인한다.
- **입력** : catalog (2차), Stage 2 의 특징 계산 함수와 1차 결과
- **처리**
  1. 2차 사진에 Stage 2 와 같은 특징을 계산한다.
  2. 2차 지령값 중 **1차 범위 밖**(Θ ±1°, Y ±2 mm 초과 등, 실제 범위는 Stage 0 값 사용)인 사진 비율을 구하고 표시한다.
  3. **중첩 검사** : 특징 = a·Y + b·Θ (+ c·Y·Θ + 2차항) 적합. 1차에서 구한 계수로 2차를 예측했을 때의 잔차를 분석한다.
  4. **C-2 세트별 원점** : center, center1~3 을 비교해 날짜 간 원점 이동(px → µm, ° 환산), 배율, 밝기 차이를 정리한다.
  5. A-2 동기화 영상의 2차 세트판을 만든다 (QR 궤적 겹침).
- **산출물**
  - `tables\superposition.csv`, `tables\drift.csv`
  - `center\center_by_set.csv`, `figures\s3_center_compare.png`
  - `figures\s3_out_of_range.png`, `figures\s3_superposition_*.png`
  - `videos\set2_sync_*.mp4/gif`
- **완료 조건** : 단서별 중첩 성립 여부(교차항 크기)와 세트 간 원점 차이가 숫자로 정리됨.
- **보고할 질문** : 혼합 이동에서 새로 생기는 효과가 있는가? 날짜 간 원점 차이가 판정 기준 대비 얼마인가?

### Stage 4. 라벨(지령값) 신뢰도

- **목표** : 정답(지령값) 자체가 판정 기준에 비해 얼마나 정확한지 확인한다.
- **입력** : catalog(접근 방향), 배경 시차 정답 CSV, center 데이터
- **처리**
  1. 지령값 vs 배경 시차 추정값 차이를 사진별로 계산 (배경 시차는 **정답 확인용 도구로만** 사용).
  2. 접근 방향(+/−)별 평균 차이 → 백래시 크기 추정.
  3. 같은 지령값 사진 사이의 흩어짐.
  4. **C-3** : 원점(center) 반복 촬영 불확도를 라벨 불확도에 합산.
  5. 최종 라벨 불확도를 판정 기준(±0.01°, ±90 µm) 대비 % 로 정리.
- **산출물**
  - `tables\label_check.csv`
  - `figures\s4_backlash.png`, `figures\s4_label_uncertainty.png`
- **완료 조건** : "정답 자체의 불확도 = Θ ___°, Y ___ µm (기준의 __ %)" 문장을 숫자로 채울 수 있음.
- **보고할 질문** : 라벨 오차가 판정 기준에 비해 무시할 만한가? 접근 방향을 촬영 절차에서 통일해야 하는가?

### Stage 5. 보고서 + 누적 요약 + 자동화 마무리

- **처리**
  1. `EDA_보고서.pdf` 생성 — 그림 위주, 본문 글꼴 크게.
     - 첫 장 : 단계별 핵심 결론 1줄씩 + 품질 경고(재촬영 필요 사진)
     - 영상은 대표 프레임 몇 장과 파일 경로로 수록
  2. `summary_all_sets.csv` : 세트당 1행 (장수, 화질 요약, 원점 위치·변화, 라벨 오차, 경고 수).
  3. `--all` 실행으로 처음부터 끝까지 재현되는지 확인. 새 세트를 가정한 시험(1차 세트 일부를 새 세트처럼 복사한 임시 폴더)으로 증분 처리 동작 확인 후 임시 폴더 정리.
  4. `eda_tool\README.md` : 새 세트 추가 방법, 실행 명령, 산출물 설명.
- **완료 조건** : 새 세트 폴더 + `set.yaml` 만 넣고 명령 한 줄로 보고서까지 나온다.

## 6. 추가 산출물 A · B — 촬영 과정 영상과 QR 정보 그래프

| 구분 | 내용 | 적용 단계 |
|---|---|---|
| **A-1 기본판** | 촬영 시각 순서로 사진을 이어 붙인 영상. 왼쪽 사진(축소), 오른쪽 지령값 타임라인(현재 위치 표시), 위쪽 파일명·시각·지령값 | Stage 0 생성, Stage 1 에서 화질 경고 표시 추가 |
| **A-2 동기화판** | 사진 위에 검출한 꼭짓점·QR 중심·플레이트 중심을 겹쳐 그리고, 오른쪽 그래프(B)가 프레임마다 한 점씩 그려짐 | Stage 2 (1차 Y·Θ 나란히), Stage 3 (2차) |
| **B QR 정보 그래프** | QR 3개 중심 x·y 궤적, 변 길이, 간격, 기울기, 사다리꼴 정도를 촬영 순번·지령값 기준으로 그림 | Stage 2, Stage 3 |

- 형식 : GIF(공유용, 가로 960 px 내외, 용량 20 MB 이하 목표), MP4(원본 비율, H.264)
- 재생 속도 옵션 : 균일 간격 / 실제 촬영 시간 비율 (정지·재촬영 구간 확인용)
- 프레임 위 QR 부분을 확대한 인셋을 넣어 미세 변화가 보이게 한다.

## 7. 추가 산출물 C — Center(원점) 정의 데이터

| 구분 | 내용 | 적용 단계 |
|---|---|---|
| **C-1 정의** | QR 중심 = 꼭짓점 4개 대각선 교점 (단순 평균과 비교), 플레이트 중심 = QR 3개 중심 평균 및 가운데 QR 중심 (두 정의 비교). 사진별 값 기록 | Stage 2 |

## 8. 미결정 사항 (진행 중 사용자에게 확인)

1. 새 데이터 유입 방식 : 날짜별 폴더 / 한 폴더 누적 — 기본값은 **세트별 폴더 + set.yaml**

3. 보고서 형식 : 기본값은 **세트·전체 PDF + 누적 CSV**. HTML 대시보드는 필요 시 추가
