# 웹 화면 (apps/web)

세메스 Y·T 비전 얼라인먼트의 웹 화면이다. 캔버스의 "서비스"와 "알고리즘 개발 및 평가"를 탭으로 나눈다.

## 탭 계획

| 탭 | 내용 | 상태 |
|---|---|---|
| 서비스 | 입력 사진 → Y·T 추정 → Y와 T 동시 이동을 도착까지 반복하는 과정을 단계별로 보여 준다 | **구현 중** (시나리오 재생) |
| 디지털 트윈 | 장비와 로봇의 현재 자세를 가상 모델로 보여 준다 | 나중에 |
| 평가 | 후보 알고리즘을 같은 사진으로 채점하고 비교한다 | **구현** (결과 폴더 열기) |
| 데이터 분포 | 라벨 (Y,T)마다 이변량 정규 봉우리와 사진별 OOF 예측 점을 3D로 본다 | **구현** ([apps/distribution](../distribution/index.html), `#dist`) |
| 보고서 | 실험 보고서를 주제별 블록으로 모아 본다 | **구현** (데이터 증강 연결, 알고리즘과 EDA는 준비 중) |

**서비스 + 디지털 트윈 한 화면 보기**를 고려한다. 서비스 탭의 사진 뷰어 옆(또는 아래)에 디지털 트윈 뷰를 함께 띄우고, 같은 단계 선택을 공유해 사진의 판단과 장비의 움직임을 동시에 본다. 화면 배치는 디지털 트윈 탭 설계 때 정한다.

## 지금 열어 보기

서버 없이 `static/index.html`을 브라우저로 연다. 글꼴(Pretendard)은 인터넷에서 받고, 연결이 없으면 맑은 고딕으로 표시된다.

특정 단계를 바로 여는 링크: `index.html#S05_YT_pp_small/3` (시나리오 ID / 단계 / 선택 `full`). 장비 시나리오는 `R01_Y_small` ~ `R06_YT_pp_large`이고, 링크로 열면 모델도 장비 모델로 바뀐다

## 서비스 탭 구성

| 영역 | 내용 |
|---|---|
| 상단 | 탭 4개, 입력 상태 |
| 모델 줄 | Y·T 추정 모델 두 개 중 하나를 고른다: **SEMES 사진으로 학습**(채택 모듈 `00000_final_Y_T`, 702장) / **우리 장비 사진 전체로 학습**(실험 모델, 1959장). 고르면 그 모델의 사진으로 만든 시나리오 6개로 바뀐다 |
| 현재 사진 | QR 확대 / 전체 보기. QR 상자는 추정값이 |Y| ≤ 0.045이고 |T| ≤ 0.01이면 초록, 아니면 빨강. 왼쪽 위 추정값(통과해도 0으로 바꾸지 않고 그대로 표시)과 판정, 아래 이동 계획 |
| 추정값, Y-T 평면, 결론 | 현재 단계 숫자, 시뮬레이션 자세와 추정의 궤적, 진행·도착·중단 |
| 특징점 이동 성분 | QR 내부 고정 536점(Y·T 추정 모듈도 이 점들의 가로 이동 평균을 쓴다)이 기준 사진에서 얼마나 움직였는지를 평행이동 X·Y(px), 회전(mrad), 크기 변화(ppm)로 나눈다. 굵은 화살표는 평행이동 방향, 파란 화살표는 회전과 크기 성분만 확대한 패턴. LK 추적 근사값(모듈의 GN 정밀화 생략)이며 잔차를 함께 표시 |
| 입력 | 카메라(미연결, 나중에), 시나리오(모델마다 6개), **시뮬레이션(기본)**: Y, T를 넣거나 "무작위로 실행"을 누르면 그 자리에서 바로 돌린다 |
| 단계 | 단계별 추정·판단·이동. 누르면 그 단계로 이동 |

## 평가 탭

1. 채점: 저장소 루트에서 [tool/03_benchmark.cpp](../../tool/03_benchmark.cpp)로 만든 `benchmark.exe`를 실행한다. 평가 탭의 "새 평가 실행"에 사진 폴더 경로를 넣으면 이 명령을 만들어 준다

   ```powershell
   .\build\Release\benchmark.exe "data\clean\clean_20261020" "evals\20261028_1805_clean_20261020"
   ```

   - 사진 폴더 아래의 BMP/PNG를 모두 찾아 1차 joint와 2차 control로 추정한다 (`joint` 또는 `control`을 붙이면 하나만)
   - 정답: 가장 가까운 `_metadata/manifest.csv`의 파일명 명령값, 없으면 파일 이름의 `Y+0.10`, `T-0.20`, `center`
   - 모델: 기본은 selected_modules.cmake의 채택 모델. `--joint-assets`, `--control-assets`로 후보 지정
   - 결과 폴더는 새로 만들고 덮어쓰지 않는다: `predictions.csv`(사진별), `summary.json`(통과 수, 오차 평균·최대·p95, 시간 중앙값, 조건별 통과)
2. 보기: 평가 탭의 "결과 폴더 열기"로 결과 폴더(또는 `evals` 폴더 전체)를 고른다. 여러 개를 열면 첫 번째를 기준으로 비교한다

화면: 통과 수와 오차 요약, 결과 비교, 조건별 통과(기준 위치, Y만, T만, Y와 T 함께), 명령값과 추정값 산점도, 오차가 큰 사진 15장.

2026-10-28 `data/clean` 341장 결과: 1차 joint 341/341 (Y 오차 평균 0.0170, 최대 0.0744), 2차 control 302/341 (Y와 T 함께 18/57). 모두 개발에 쓴 사진이라 재대입 성적이다.

우리 장비 화면(rig_1st 축 사진 280장, rig_grid 격자 사진 1679장, 센터 22장):

- 봉우리는 명령 좌표 1881개, 점은 값 7개 Huber 선형식의 5-fold OOF 예측을 "명령 + (예측 − 라벨)" 자리에 찍은 것이다
- "라벨"에서 명령 그대로, 절대 영점, 영점+보정을 고르면 그 라벨로 다시 학습한 예측과 봉우리 폭으로 바뀐다 (OOF 탈락 310, 310, 14 / 1959장)
- 부호가 SEMES 와 반대이고 T 단위는 도다. 영점+보정 라벨은 영상 값에서 나온 것이라 그 성적은 독립된 정답과의 비교가 아니다
- 근거: [결과.md](../../experiments/hye/20261113_0950_우리장비사진거부_장비기준자료와라벨보정/결과/결과.md)
- 다시 만들기: 저장소 루트에서 `python apps/distribution/rig/make_page.py` (rig/template.html + vendor/plotly-2.35.3.min.js → rig/index.html)

SEMES 화면:

- 데이터: 커밋 46152fd의 `experiments/hye/20261111_0944_final_Y_T/evidence/group_oof.tsv`와 `training_features.tsv`(1~4차, ID 702 제외 714장)
- 봉우리: 라벨마다 하나. 폭은 전체 OOF 오차의 공통 공분산(σY 0.0139 mm, σT 0.0032, ρ −0.54). 전체 좌표 보기는 시각화용으로 폭을 넓히며 배율을 화면에 표시한다
- 점: 사진별 그룹 5-fold OOF 예측. 기본은 흐리게 표시하고 점을 누르면 그 점과 자기 라벨(다른 라벨이 더 가까우면 그 라벨도)만 선명하게 표시한다

## 데이터

지금 화면은 `static/demo/data.js`를 읽는다. 이 파일은 [tools/make_demo.py](tools/make_demo.py)가 만든다.

- 모델 두 개(2026-11-13 사용자 지시). 모델마다 자기 사진만 쓴다. 채택 모듈은 장비 사진의 QR·나사 자리가 달라 거부하고(11-13 실험), 장비 모델도 SEMES 사진의 자리에 맞지 않는다

| 모델 | 추정값 | 사진과 자세 |
|---|---|---|
| SEMES 사진으로 학습 | `data/scenarios/*/scenario.yml`의 사진에 `build/Release/main.exe joint`를 **실제로 실행한 결과**. 모델 이름은 `experiments/selected_modules.cmake`의 `SEMES_JOINT_DIR`(지금 `00000_final_Y_T`, 절대 영점 기준) | `data/clean`의 SEMES 사진. 자세는 파일명 명령값 |
| 우리 장비 사진 전체로 학습 | [11-13 실험](../../experiments/hye/20261113_0950_우리장비사진거부_장비기준자료와라벨보정/결과/결과.md)의 `실험/assets_rig`(장비 센터 사진·자리, 1959장 전체를 보정 라벨 L2로 학습한 계수). 공개 API(`initialize_joint`, `joint`)로 1959장을 예측한 `결과/predict_L2/predictions.tsv`를 읽는다 | `data/clean/rig_20261112`(`data/raw/rig_1st.zip`, `rig_grid.zip`). 자세는 보정 라벨 L2(절대 영점). 시작 사진은 SEMES 6개와 같은 구성(rig_1st Y+0.20, Y+1.50, T+0.20, T+1.00, rig_grid Y+0.10 T+0.10, Y+1.00 T+1.00) |

- 장비 모델은 **실험 자료이고 전달 모듈이 아니다.** 학습한 사진을 그대로 다시 넣는 재대입이며, L2 라벨이 같은 영상 값에서 나왔으므로 독립된 정답과의 비교가 아니다. 부호는 우리 장비 스테이지 방향(SEMES와 반대), T 단위는 도다
- 규칙(2026-11-13 사용자 지시): **Y와 T를 동시에 보정한다. 2차 control은 쓰지 않는다.** 사진마다 (Y, T)를 추정해 |Y| ≤ 0.045이고 |T| ≤ 0.01이면 도착, 아니면 두 축을 추정값만큼 함께 움직이고 다시 찍는다. 최대 20회. `include/pipeline.hpp`의 서비스 흐름(1차 joint → 2차 control, 두 축 0.09)과 다르다
- 첫 사진은 시나리오의 시작 사진. 이동 후 사진은 `data/clean` 전체에서 계산된 자세와 가장 가까운 사진(SEMES는 허용 Y 0.025, T 0.02, 장비는 격자 간격의 절반인 Y 0.05, T 0.025 안에서 가장 가까운 사진). 없으면 중단. T 허용은 시나리오의 0.005에서 0.02로 넓혔다. 1차 모듈이 절대 영점 기준이라 다른 날 사진은 T가 0.012~0.016 어긋나게 읽히고(10-20 center1이 T +0.0138), 명령 좌표로 계산한 자세와 사진 사이에 그만큼 틈이 생기기 때문이다. `clean_20261014/center.bmp`는 모듈의 기준 사진(assets/center.bmp)과 같은 파일이라 후보에서 뺀다. 도착 장면은 다시 찍은 `clean_20261020/기준 위치/center1.bmp`
- QR 상자 위치는 NCC 탐색으로 사진마다 찾는다
- 특징점 이동 성분: 사진마다 536점을 QR별 NCC 이동 + LK 15×15(σ 0.8 흐림)로 추적하고, 평행이동·회전·크기 4개 값으로 최소제곱 분해한다. Y와 T 모두 이미지에서는 주로 가로 평행이동으로 나타난다 (예: Y +0.20 → X +2.33px, T +0.20 → X +15.2px)
- 사진은 `static/demo/img/`의 축소 JPEG (전체 1600×900, QR 확대 영역 1600×900: SEMES x1120 y620, 장비는 QR이 62 px 아래라 x1125 y682). 특징점 이동 성분도 모델마다 자기 센터 사진과 536점으로 잰다

### 시뮬레이션 (2026-11-13 사용자 지시)

입력한 (Y, T)에서 시작해 시나리오와 같은 규칙(Y와 T 동시 이동, |Y| ≤ 0.045이고 |T| ≤ 0.01이면 도착, 최대 20회)으로 화면(`static/app.js`)에서 바로 계산한다.

- 매 단계 자세 근처에 실제 사진이 있으면(SEMES 허용 Y 0.025, T 0.02 / 장비 Y 0.05, T 0.025) **그 사진의 실제 모델 추정값**을 쓰고 사진을 보여 준다
- 근처에 사진이 없으면 **오차 모형**: 참 자세 + 그 모델의 주 검증 rms 만큼의 정규 잡음(Y·T 독립). SEMES `00000_final_Y_T/evidence/cpp/eval.txt` σY 0.01315, σT 0.00288 / 장비 `결과/eval_L2/eval.txt` σY 0.01119, σT 0.00209. 이 단계는 화면에 "오차 모형 추정"과 "사진 없음"으로 표시한다
- 장비 사진은 0.1 mm × 0.05° 격자라 어떤 값이든 실제 사진이 있다. SEMES 사진(719장)은 축과 일부 조합에만 있어 무작위 시작값의 약 12%만 첫 단계에 실제 사진이 있다
- 자료: `static/demo/sim.js`(모델마다 사진 전체의 자세, 실제 추정값, QR 상자)와 `static/demo/sim/<모델>/`(QR 확대 미리보기 640×360). SEMES 추정값은 `main.exe joint`를 사진마다 실행하고 `build/demo_cache/`에 모아 둔다(처음 한 번 약 4분)
- 특징점 이동 성분은 시뮬레이션에서 계산하지 않는다

다시 만들기 (저장소 루트, 빌드 후):

```powershell
python apps/web/tools/make_demo.py .
```

`make_demo.py`는 C++ 서비스 API가 생기기 전까지 쓰는 **임시 데모 생성기**다(Python + OpenCV). 서비스 흐름(include/pipeline.hpp)과 웹 서버가 생기면 화면은 같은 형태의 데이터를 API에서 받고, 이 스크립트와 `static/demo/`는 지운다.
