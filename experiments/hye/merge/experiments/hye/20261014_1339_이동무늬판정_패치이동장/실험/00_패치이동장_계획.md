# 패치 이동장(motion field) 매핑 방법: 단계별 체크리스트

목표: center 사진을 기준으로 QR 영역을 작은 패치로 나누고, 패치마다 서브픽셀 이동량을 잰다.
Y와 Θ가 만드는 "이동 무늬"를 매핑 함수로 학습한 뒤, 새 사진 1장의 이동 무늬를 함수에 맞춰서 Y 또는 Θ를 구한다.

공통 규칙
- 원본(사진, 14번, 15번 CSV)은 읽기만 한다. 코드는 `analysis_v5/`, 결과는 36번부터 새 번호로 저장한다.
- 정답은 raw(명령값)와 보정본(① 백래시 + 드리프트) 두 가지를 모두 들고 간다.
- 채점은 짝수/홀수 교차검증, 그리고 구간 하나 빼기 검증(학습에 안 쓴 촬영 구간으로 채점)을 함께 한다.
- 각 단계는 아래 "확인" 항목을 통과해야 다음 단계로 간다.

---

## 0단계. 결정할 것 (사용자 확인)
- [ ] 출력: "Y인지 Θ인지 판정 + 그 값"인지, "Y와 Θ를 동시에 추정"하는지
  - 지금 데이터는 십자 모양이에요 (Y와 Θ가 동시에 0이 아닌 사진이 없음). 그래서 동시 추정은 "두 효과가 더해진다"는 가정에 의존해요.
- [ ] 영역: QR 판만 쓰는지, QR 밖 구조물(볼트, 파인더)까지 쓰는지
  - QR 판은 평평해서 이동 무늬가 거의 원근 변환(G1과 같은 정보)이에요. 거리가 다른 물체가 들어가야 시차 정보가 늘어요.
  - 제안: 두 가지 모두 돌려서 비교 (A안: QR만, B안: QR + 주변)
- [ ] 학습 정답: 보정본으로 학습하고 두 기준으로 채점 (제안)

## 1단계. 기준 영상 만들기
- 할 일: center 1장과 "학습 사진을 center 좌표로 되돌린 평균 영상" 두 가지를 만든다.
- 산출물: 기준 영상 2장, 밝기와 선명도 비교표
- 확인
  - [ ] center와 평균 영상의 밝기 차이가 이미 알려진 값(+1.2%)과 맞는가
  - [ ] 평균 영상을 만들 때 시험 사진이 섞이지 않았는가 (교차검증 폴드마다 따로 만듦)

## 2단계. 패치 나누기
- 할 일: 영역을 정사각 패치로 나눈다 (기본 32×32px, 16px씩 겹치게). 무늬가 약한 패치는 뺀다.
  - 무늬 세기 = 패치 안 밝기 기울기 행렬(구조 텐서)의 작은 고유값. 작으면 한 방향으로만 무늬가 있어서 이동을 잴 수 없음.
- 산출물: 패치 지도 그림 (쓰는 패치 / 빠진 패치 색 구분), 패치 개수
- 확인
  - [ ] 빠진 패치가 실제로 민무늬 영역(흰 바탕 등)인가
  - [ ] 패치 크기 16 / 32 / 64 중 무엇을 기본으로 할지 (4단계 잡음 결과를 보고 결정)

## 3단계. 패치별 서브픽셀 이동 재기
- 할 일: 사진 281장 × 패치 P개마다 기준 영상 대비 (dx, dy)를 잰다.
  - 방법: 위상 상관(업샘플링)으로 대략 → 3차 스플라인 보간 + 가우스-뉴턴(밝기 a, b 포함)으로 정밀하게.
  - OpenCV remap은 1/32px 단위로 잘려서 쓰지 않는다 (v3에서 확인한 문제).
- 산출물: 이동장 배열 (281 × P × 2), 패치별 정합 점수
- 확인
  - [ ] 합성 검증: 기준 영상을 0.01 / 0.05 / 0.1px 만큼 일부러 옮겨서 잰 값이 맞는가 (편향, 잡음 표)
  - [ ] QR 3개 위치의 패치 평균 이동이 14번 CSV 값과 0.02px 안으로 맞는가
  - [ ] 패치별 잡음 크기 지도 (center 근처 사진들의 흩어짐으로 추정)

## 4단계. 이동장 분석 (Y, Θ가 각각 어떤 무늬를 만드나)
- 할 일
  - 패치마다 Y 사진으로 d = s_Y(p)·Y + b, Θ 사진으로 d = s_Θ(p)·Θ + b 를 맞춘다.
  - s_Y, s_Θ를 화살표 지도로 그린다. 두 무늬의 차이(정규화한 두 벡터장의 각도, 조건수)를 계산한다.
  - 직선에서 벗어난 양을 패치별로 본다 (가장자리일수록 커지는지 = 원근, 렌즈 왜곡).
  - 백래시 0점 어긋남이 모든 패치에 같은 양으로 나타나는지 본다 (같으면 스테이지 오차, 다르면 영상 쪽 문제).
- 산출물: s_Y, s_Θ 화살표 지도, 차이 무늬 지도, 패치별 직선성 지도
- 확인
  - [ ] s_Y와 s_Θ가 거의 같은 무늬인가, 다른 무늬인가 (이게 Y와 Θ를 구분할 수 있는 한계를 정함)
  - [ ] 차이 무늬가 어디서 큰가 (QR 안 / 밖)
  - [ ] 0점 어긋남이 패치 전체에 균일한가

## 5단계. 매핑 함수 만들기
- 할 일: 세 가지 형태를 만들어 비교한다.
  - M-a 선형: d(p) = s_Y(p)·Y + s_Θ(p)·Θ + 방해 무늬(세로 이동, 화면 회전, 크기)
  - M-b 비선형 표: 패치마다 Y 방향, Θ 방향으로 각각 스플라인 (이동 무늬 사전)
  - M-c 압축: 이동장을 주성분으로 줄인 뒤 주성분 점수 → Y, Θ 회귀
- 산출물: 함수별 학습 잔차, 패치별 잔차 지도
- 확인
  - [ ] 학습 잔차가 3단계 잡음 크기 수준까지 내려가는가 (더 크면 함수가 무늬를 다 못 담은 것)
  - [ ] M-b, M-c가 M-a보다 나은 만큼이 교차검증에서도 유지되는가 (과하게 맞춘 것 아닌지)

## 6단계. 맞추기 (새 사진 1장 → Y 또는 Θ)
- 할 일
  - 새 사진의 이동장을 재고, 패치 잡음으로 가중한 제곱합 Σ w_p |d_p − f(Y, Θ)|² 를 최소화한다.
  - 튀는 패치에 강하도록 Huber 가중을 쓴다.
  - 십자 데이터라서 "Y만 움직였다" 가설과 "Θ만 움직였다" 가설을 각각 풀고, 비용이 작은 쪽을 고른다. 2차원 동시 풀이도 같이 낸다.
- 산출물: 사진별 예측값, 고른 가설, 두 가설의 비용 비
- 확인
  - [ ] Y/Θ 판정 오류 수 (특히 Y ±0.30mm, Θ ±0.04 근처의 헷갈리는 짝)
  - [ ] 비용 비가 1에 가까운(애매한) 사진 목록

## 7단계. 평가
- 할 일: 예측 오차를 정리하고 기존 방법과 비교한다.
- 산출물: 결과표 (A안 / B안 × M-a / M-b / M-c), 최악 사진 목록, 히트맵
- 확인
  - [ ] 허용 오차 0.09 통과율 (명령값 기준, 실제 위치 기준)
  - [ ] 짝수/홀수 교차검증과 구간 하나 빼기 검증 결과가 비슷한가 (크게 나쁘면 시간 드리프트에 약한 것)
  - [ ] 기존 G1(Y RMS 91µm, QR만), QR 밖 구조물 방법(14~19µm), 17번 결과표와 비교

## 8단계. 강건성
- 할 일: 잡음 추가, 밝기 ±2%, 패치 일부 가리기(10%, 30%), 패치 크기 변경
- 확인
  - [ ] 각 조건에서 0.09 통과율이 얼마나 떨어지는가
  - [ ] center 밝기 차이(+1.2%) 수준에서 결과가 흔들리지 않는가

## 9단계. 정리
- [ ] 36번부터 그림, 결과표 저장
- [ ] 결과 리포트 (`00_v5결과리포트.md`)
- [ ] PPT 반영 여부 결정

## 미리 알려 둘 점
- 가능한 방법이에요. 사진 281장 × 패치 수백 개라 계산량도 괜찮아요.
- 다만 QR만 쓰면(A안) 판이 평평해서 이동장의 정보가 원근 변환 8개 값과 거의 같아요. 그래서 G1과 비슷한 성능이 예상돼요.
  이득은 패치별 가중(잡음 큰 곳 덜 믿기), 렌즈 왜곡처럼 원근 변환이 못 담는 부분에서 나와요.
- Y와 Θ 구분을 크게 개선하려면 깊이가 다른 물체가 들어간 B안이 핵심이에요. 4단계의 "두 무늬 차이"에서 미리 판단할 수 있어요.
