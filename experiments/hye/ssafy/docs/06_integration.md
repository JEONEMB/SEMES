# 카메라와 장치 통합

## 책임 구분

카메라는 3840x2160 8비트 영상을 제공한다. 모듈은 영상에서 Y와 T를 추정하고 notices 및 correction_allowed를 반환한다. 장치 제어기는 축 부호, 이동 단위와 명령 형식에 맞춰 보정 명령을 생성하고 실행 후 새 사진을 촬영한다.

출력 Y, T를 그대로 모터 명령이라고 취급하지 않는다. 이 패키지에는 카메라 드라이버, 네트워크 수신부, PLC 또는 모터 통신 코드가 없다.

## 호출부에서 지킬 조건

1. 카메라 형식과 실제 Mat 크기를 확인한다. 요구 해상도와 다르면 E_PHOTO다.
2. 모델 초기화와 영점 설정 결과가 Failed인지 확인한다.
3. 측정 결과의 correction_allowed가 true인지 확인한다. Warning을 일괄 거부하면 범위 경고가 다시 차단된다.
4. 범위 경고는 화면이나 로그에 남기되, 그것만으로 측정값을 삭제하거나 이동량을 0으로 바꾸지 않는다.
5. 측정 실패의 NaN을 0, 0으로 대체하지 않는다.
6. 모델을 바꾸거나 기준을 재등록한 뒤에는 영점을 다시 설정한다.

API 내부에는 공유 상태와 mutex가 있으므로 한 라이브러리 인스턴스는 현재 한 장비의 모델과 영점을 보관한다. 진행 콜백에서 같은 모듈 API를 다시 호출하지 않는다. 여러 카메라의 상태를 동시에 섞어 사용하는 설계는 별도 구현이 필요하다.

## 라즈베리파이 상태

현재 Git에 올라가는 것은 로컬에서 검증한 소스와 모델이다. 라즈베리파이에 설치된 바이너리, 카메라 호출부, 실제 실행 버전은 확인하지 않았으며 배포하지 않았다.

현행 기본 CMake에는 PowerShell 문자 검사 대상이 있다. Linux에서 빌드하려면 해당 검사를 Windows 조건으로 분리하거나 별도 검사 환경에서 실행하도록 빌드 구성을 조정해야 한다. ARM 환경의 OpenCV 3.4.15와 C++17 빌드 및 실행도 별도로 확인해야 한다. Windows 검사 통과를 라즈베리파이 실행 확인으로 해석하지 않는다.

장치에 적용할 때는 소스 버전, 모델 묶음, 영점 설정 방법, 호출부의 Warning 처리와 실제 반환값을 함께 확인한다. 3.00 mm를 포함한 범위 밖 결과가 현장에서 계속 차단된다면 호출부의 status != Ok, outside_training_range 검사 또는 예전 바이너리 사용 여부를 확인한다.
