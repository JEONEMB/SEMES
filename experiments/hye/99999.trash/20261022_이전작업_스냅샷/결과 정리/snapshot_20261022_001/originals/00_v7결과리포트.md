## B. 이동 모델링: 점을 다 넣으면 안 되나? (질문하신 것)

![](../../../실험%20방법/snapshot_20261022_001/originals/55_v7_점전부vs골라쓰기.png)

- **다 넣어도 상쇄되지 않아요.** 약한 점을 더해도 나빠지지 않아요 (상위 50개 + 약한 점 182개: 가중 없음 91.1% → 93.6%로 오히려 좋아짐).
- 진짜 문제는 **점끼리 같이 흔들리는 성분**(사진마다 판 전체가 미세하게 같이 움직임)이에요. 이걸 무시하고 점마다 독립으로 가중하면 90.4%까지 떨어져요. 공분산으로 반영하면 97~98%예요.
- 상위 k개만 고르는 건 도움이 안 돼요 (상위 25개 97.9% ≈ 전부 98.2%). 단서는 퍼져 있어요: 상위 10% 점이 단서의 44%, 상위 50%가 93%.
- **움직임마다 단서 큰 점이 다른가**: +방향 사진으로 매긴 순위와 −방향 순위의 상관 0.04, 작은 값과 큰 값 순위 상관 −0.30이에요. 하지만 짝/홀 사진으로 매긴 순위는 0.95로 같아요. 즉 한쪽 방향이나 한쪽 크기만으로는 점 순위를 안정적으로 매길 수 없어서, 움직임마다 점을 골라 쓰는 방식은 쓸 수 없어요. 전부 넣고 공분산으로 묶는 게 안전해요.
- QR 하나만 쓰면 가운데 QR이 가장 약해요 (91.8%). 원근 단서는 양 끝 QR에 있어요. 좌+우 2개로 97.9%, 3개 98.2%.

## D. 0점 보정: 필요한가, 했을 때와 안 했을 때 차이

7개 0점 (center = 0 기준, QR만):

| 구간 | 값 쪽 0점 (Y 환산) | 모양 쪽 0점 (판정 방향 치우침, Y 환산) |
|---|---|---|
| center | 0 | 0 |
| Y1+ | −36µm | +53µm |
| Y1− | +5µm | +203µm |
| Y2+ | −30µm | +62µm |
| Y2− | −27µm | +178µm |
| Θ+ | −55µm (Θ −0.0097) | +47µm |
| Θ− | −14µm (Θ −0.0024) | +142µm |

![](../../../실험%20방법/snapshot_20261022_001/originals/54_v7_0점7개.png)

0점 처리별 축 정확도 (무작위 반반 40번 평균, 측정/요약 72개 설정의 평균 / 최고):

| 0점 처리 | 배포 가능? | QR만 | QR+나사 |
|---|---|---|---|
| center를 그대로 0점 (보정 안 함) | 가능 | 98.0 / 98.8% | 97.9 / 98.9% |
| 두 가설이 같이 쓰는 0점 1개를 학습 | 가능 | 98.1 / 98.8% | 97.9 / 98.6% |
| 축마다 0점을 따로 학습 | 가능 | 97.3 / 98.1% | 97.0 / 97.7% |
| 구간 0점을 정확히 앎 (완벽 보정, 상한) | 불가능 | 98.7 / 99.1% | 98.9 / 99.3% |

결론:
1. **축 판정에는 0점 보정이 거의 필요 없어요.** 완벽히 보정해도 평균 +0.7~1.0%p (2~3장)이고, 최종 파이프라인에서는 차이가 없어요 (3.3장 vs 3.7장). 완벽 보정해도 100%가 안 돼요 → 남은 오류는 0점이 아니라 측정 잡음 때문이에요.
2. **축마다 0점을 따로 학습하면 오히려 나빠져요** (−0.8%p). Y 가설과 Θ 가설의 출발점이 달라져서 작은 값에서 한쪽으로 기울어요. 0점을 쓰려면 두 가설이 같은 0점을 써야 해요.
3. **값 오차는 정답 기준에 따라 크게 달라요.** 학습 라벨과 정답 기준이 같으면 작고, 다르면 커요:

| 학습 라벨 → 정답 기준 | Y 평균 / 최대 오차 | Θ 평균 / 최대 오차 |
|---|---|---|
| 명령값 → 명령값 | 14 / 36µm | 2.4 / 8.5 mΘ |
| 명령값 → 실제 위치 | 26 / 66µm | 7.2 / 21 mΘ |
| 보정본 → 명령값 | 27 / 41µm | 7.9 / 14 mΘ |
| 보정본 → 실제 위치 | 1.4 / 10µm | 0.3 / 1.5 mΘ |

   - 어느 조합이든 0.09 안이에요. 0점 차이(최대 Y 55µm)는 허용 오차보다 작아서 값 쪽 목표에는 보정이 필요 없어요.
   - "보정본 → 실제 위치" 1.4µm는 보정값을 영상으로 만들었기 때문에 일부 순환이라 그대로 믿으면 안 돼요.
4. 참고: 모양 쪽 0점이 6구간 모두 같은 방향(+)이에요. center 사진만 조건이 다르다(조명 예열, 밝기 +1.2%)는 기존 발견과 맞아요. 다만 공통 0점을 학습해 빼도 정확도가 오르지 않았어요.

## E. 왜 100%가 안 되나: 크기별 틀림률

![](../../../실험%20방법/snapshot_20261022_001/originals/57_v7_크기별_축틀림률.png)

- Y와 Θ를 가르는 단서는 원근(양 끝 QR이 가운데보다 더 움직임) 하나예요. Y 1mm와 같은 평균 이동의 Θ에서 이 차이는 약 0.05px이고, 사진 1장의 잡음은 13.5σ/mm (QR만) → 1σ = Y 0.074mm.
- 그래서 |Y| 0.15~0.3mm (Θ 0.03~0.05) 사진은 반복할 때마다 20~45% 확률로 틀려요. 0.4mm 이상은 0%.
- 이 데이터 크기 분포에서 기대 틀림 수는 QR만 3.5장, QR+나사 2.4장 (이론). 실측 3.3장, 4.1장과 맞아요.
- 0.05mm (가장 작은 값) 쪽은 오히려 덜 틀려요. 두 가설이 둘 다 0 근처라 비용 차이가 0점 치우침 방향으로 일정하게 기울기 때문이에요. 이 구간에서 틀려도 0.09 통과예요.
- **틀림 0장을 기대하려면 잡음이 46σ/mm가 돼야 해요 = 지금의 약 3.4배.** 잡음이 사진끼리 독립이라 같은 자세에서 약 11장을 찍어 평균하면 도달하는 수준이에요 (계산값, 실측 아님). 2장(center + 현재)만 쓰는 조건에서는 어떤 계산법으로도 도달할 수 없어요.
