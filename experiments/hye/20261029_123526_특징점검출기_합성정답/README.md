# 특징점 검출기: 합성 정답 실험

작성: 2026-10-29. 상태: 합성 영상에서 검출 위치·짝짓기·추적을 측정했다. Y/T 결과 영향과 실측 평가는 하지 않았다.
[1단계 부화소 정합 실험](../20261029_122323_부화소정합_합성정답/README.md)과 **같은 72개 합성 조건·같은 생성기·같은 LK 설정**을 쓴다. 1단계 소스(`synth.cpp`, `methods.cpp`)를 그대로 링크했다. 공통 규칙은 [ALGORITHM_RULES.md](../../../ALGORITHM_RULES.md)를 따른다.

## 무엇을 쟀나

검출기는 "점을 고르는" 단계라서 1단계처럼 변위 하나로만 볼 수 없다. 세 경로로 나눠 쟀다. 모든 경로의 정답은 합성에 넣은 변형이다.

| 경로 | 대상 | 방법 | 지표 |
|---|---|---|---|
| (1) 검출 위치 | 전부 | center와 합성 영상에서 각각 검출. center 점을 정답 변형으로 옮긴 위치에서 가장 가까운 합성 검출점을 찾음 | 반복률(1.5 px 안에 다시 검출된 비율), 위치 오차 중앙값·p95, 검출 시간 |
| (2) 기술자 짝짓기 | ORB·BRISK·AKAZE·KAZE | 전수 knn(2) + 비율 검사 0.8 | **진짜 오매칭률**(정답과 3 px 넘게 어긋난 짝), 맞은 짝의 위치 오차, 검출+기술자+짝짓기 시간 |
| (3) 검출+LK 추적 | Harris·Shi-Tomasi·Förstner·FAST·QR 구조점 630 | center 검출점을 1단계의 `NCC+LK(1단)`으로 추적 | 1단계와 같은 지표 (오차 p95, 실패 또는 >0.5 비율, 시간) |

- 검출 영역은 이전 [검출기 비교](../20261029_112722_QR특징점검출기_비교/README.md)와 같다. center는 QR 상자 3개 안에서 검출하고, 합성 영상은 QR 상자를 가로 ±110, 세로 ±22 px 넓힌 영역에서 검출한다. 검출기 설정도 그 실험과 같다(아래).
- 오매칭 기준 3 px는 QR 모듈 한 칸(약 7 px)의 절반보다 작다. 처음에는 1.5 px로 정했는데, 빠른 확인 실행에서 ORB 상위 피라미드 점이 같은 점이어도 1.5 px 넘게 어긋나는 것을 보고 바꿨다. "다른 점을 가리킨 짝"과 "위치가 덜 정확한 짝"을 나누려는 목적이다. 0.5 px 초과 비율은 따로 보고한다.
- 이전 실험의 "변위 중앙값에서 2 px 넘게 벗어난 짝" 대리 지표도 같이 계산해, 진짜 오매칭과 비교했다.

## 검출기 설정

| 검출기 | 설정 | 비고 |
|---|---|---|
| Harris / Shi-Tomasi | `goodFeaturesToTrack` 최대 800, 품질 0.01, 최소 간격 4, 블록 5 (Harris k 0.04) | 화소 단위 좌표 |
| Harris / Shi-Tomasi + cornerSubPix | 위 결과에 `cornerSubPix` 창 11×11 | 표의 "부화소는 별도 보정"에 해당 |
| Förstner | 직접 구현: 구조 텐서(σ 1.5) w = det/trace, 원형도 q > 0.5, w > 0.01·max, 5×5 극대, 최소 간격 4, 7×7 창 기울기 직선 교점으로 부화소 | OpenCV에 없음. 매개변수는 조정하지 않았다 |
| FAST | 문턱 25, 응답 상위 800 | |
| ORB | `ORB::create(3000)` | |
| BRISK | `BRISK::create(20)` | |
| AKAZE | MLDB, 문턱 1e-4 | |
| KAZE | 문턱 1e-4 | 표에는 없지만 이전 비교와 맞추려고 넣었다 |
| QR 구조점 630 | 채택 control `points.json` | 검출이 아니라 디코딩된 격자 구조로 정해진다 |
| SIFT, SURF | **미평가** | 팀 기준 OpenCV 3.4.15 `opencv_world`에 contrib(`xfeatures2d`)가 없다. SURF는 nonfree이기도 하다. 기준 OpenCV를 바꾸지 않았다 |

| 점 집합 | 점 수 /장 | 오차 중앙값 | p95 | 실패 또는 >0.5 | 추적 시간 중앙값 ms |
|---|---|---|---|---|---|
| QR 구조점 630 | 630 | 0.022 | 0.108 | 0.0149 | 15.1 |
| Harris | 800 | 0.016 | 0.086 | 0.0142 | 17.2 |
| Harris+cornerSubPix | 788 | 0.020 | 0.087 | 0.0120 | 17.4 |
| Shi-Tomasi | 800 | 0.016 | 0.079 | 0.0129 | 17.0 |
| Shi-Tomasi+cornerSubPix | 797 | 0.020 | 0.083 | 0.0112 | 17.3 |
| Förstner | 285 | 0.022 | 0.107 | 0.0139 | 10.8 |
| FAST | 801 | 0.018 | 0.091 | 0.0123 | 17.0 |

QR 구조점 630 행은 1단계 `NCC+LK(1단)` 결과와 같은 값이다(같은 코드·조건 확인). 묶음별로 보면 평행이동·회전에서는 모든 점 집합의 p95가 0.035~0.055 px로 비슷하다. 밝기·흐림·잡음에서는 0.70~0.89 px, 가림에서는 0.26~0.34 px로 함께 나빠진다. 이 차이는 점보다 LK의 밝기 불변 가정에서 온다(1단계 참고).

1단계에서 QR 구조점 630에 채택 GN 측정기를 쓴 p95는 평행이동 0.005, 회전·배율 0.019, 밝기·흐림·잡음 0.107 px였다. 검출기 점에는 GN 측정기를 적용하지 않았으므로 "검출기 점 + GN"은 비교하지 못했다.

## 해석 (합성 영상 범위 안에서)

- **화소 단위 검출기(Harris, Shi-Tomasi, FAST, ORB, BRISK)는 따로 검출한 위치를 그대로 쓰면 오차 중앙값이 0.4~0.7 px다.** 같은 점을 두 번 검출하면 정수 반올림이 두 번 들어간다. cornerSubPix를 붙이면 Harris·Shi-Tomasi의 p95가 0.24~0.35 px로 줄어든다.
- **AKAZE·KAZE는 반복률(0.95)과 위치(중앙값 0.05~0.07 px)가 검출기 중 가장 좋았다.** 그러나 반복 무늬 때문에 짝의 7~8%가 다른 점을 가리켰고, 검출+짝짓기 시간이 200~800 ms였다.
- **ORB·BRISK는 짝의 16~18%가 다른 점을 가리켰다.** 맞은 짝도 0.5 px를 넘는 경우가 35~71%였다. 이 정밀도 영역에는 맞지 않는다.
- **Förstner(이 구현)는 다시 검출되면 정밀했다(중앙값 0.044 px).** 다만 반복률이 0.36으로 낮았다. 원형도 문턱 근처의 점이 영상마다 들어갔다 빠졌다 하는 것으로 보인다. 매개변수를 조정하지 않은 결과다.
- **추적 경로에서는 어떤 점을 고르든 LK 오차가 비슷했다.** 코너 검출점(Harris, Shi-Tomasi)은 QR 경계 점보다 p95가 약간 작았다(0.08~0.09 대 0.11). 경계 점은 모서리 방향으로 위치가 덜 정해지기 때문(조리개 문제)으로 보인다. 오차를 크게 가르는 것은 점 선택보다 정밀화 방법이다(1단계의 GN 대 LK).
- **QR 구조점의 장점인 "오매칭 없음"은 이 실험의 추적 경로에서 모든 검출점에 똑같이 성립했다.** QR 단위 NCC로 초기값을 잡고 같은 점을 추적했기 때문이다. 구조점만의 고유한 장점은 QR 내용이 바뀌어도 같은 물리점에 ID를 줄 수 있다는 것이다. 이 합성 실험은 그 부분을 시험하지 않는다.

## 한계

- 1단계와 같은 합성 영상의 한계(실제 렌즈·조명 미반영, 가정한 변형 범위, 양자화된 잡음 추정)가 그대로 적용된다.
- 반복률은 검출 영역 경계와 개수 상한(800, 3000 등)의 영향을 받는다. 검출기마다 점 수가 다르므로 점 수를 맞춘 비교가 아니다.
- 오매칭 기준(3 px)은 빠른 확인 실행을 본 뒤 정했다.
- 시간은 1스레드, 조건마다 1회 실행이다. 정식 속도 측정이 아니다.

## 빌드와 실행

저장소 루트 PowerShell. `results/`가 있으면 덮어쓰지 않고 멈춘다.

```powershell
cmake -S "experiments/hye/20261029_123526_특징점검출기_합성정답" -B build-detector-synthetic-20261029 -G "Visual Studio 18 2026" -A x64 -T v141 -DCMAKE_GENERATOR_INSTANCE="C:/Program Files (x86)/Microsoft Visual Studio/18/BuildTools" -DOpenCV_DIR="C:/opencv/build"
cmake --build build-detector-synthetic-20261029 --config Release
.\build-detector-synthetic-20261029\Release\detector_synthetic.exe
```

인자 `<결과 폴더> quick`은 조건 10개 중 1개만 돌린다. 1단계 폴더의 `src/synth.cpp`, `src/methods.cpp`를 함께 컴파일하므로 그 파일을 바꾸면 이 실험의 조건도 바뀐다.
