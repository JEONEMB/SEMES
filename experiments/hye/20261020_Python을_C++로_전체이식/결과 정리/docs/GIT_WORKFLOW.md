# 파일 정리 이후의 Git 작업 순서

현재 사용자 지시는 ‘우선 final 파일 정리만 진행’이다. 아래 내용은 재개할 때의 작업 기준이며, 지금 저장소 생성·브랜치 생성·커밋·푸시·병합은 수행하지 않는다.

## 저장소 경계

조사 당시 `final`은 상위 `projects` GitHub 저장소 안의 일반 폴더이고, `hw-analysis`는 별도 GitLab 저장소였다. `hw-analysis` 작업 트리에는 `.gitignore`, `docs/hw`, `tool/hw`의 기존 변경이 있었다. 그 변경을 이번 이식 커밋에 섞지 않는다.

재개 시 먼저 저장소를 결정하고 `final`의 경로를 어떻게 그 이력에 포함할지 정한다. 외부에 있는 폴더를 `git add ../final`로 별도 저장소에 포함할 수는 없다. 원본·DATA 이동이나 새 저장소 생성을 자동으로 전제하지 않는다.

## 브랜치 흐름

팀 규약의 원본은 `../../hw-analysis/docs/gitConvention.md`다. 논리적인 흐름은 작업 브랜치 → 개발 통합 브랜치 → 안정 브랜치이며 PR/MR로 검토한다. 팀 문서의 이름은 `develop/main`이지만 조사 당시 원격에는 `dev/master`가 있었으므로, 재개할 때 실제 원격 브랜치와 보호 설정을 확인한다. 문서 이름에 맞춘다고 기존 브랜치를 임의로 바꾸지 않는다.

Codex가 만드는 작업 브랜치의 기본 접두사는 `codex/`다. 단계별로 독립된 변경을 검토할 수 있게 하고 검증된 변경만 통합한다. 별도 release/hotfix 관리가 실제로 필요해질 때 확장한다.

## 단계별 커밋 묶음

| 사용자 순서 | 검토 가능한 변경 단위 | 커밋 예시 |
|---|---|---|
| 0 | 원본 해시·시간 기준과 이식 원장 | `docs: 과거 실험 출처와 이식 범위 정리` |
| 1 | CMake·의존성·실행 명령 | `build: C++ 공통 빌드와 실행 환경 구성` |
| 2 | 자료 입력·고정 분할·입력 오류 처리 | `feat: 고정 데이터 분할과 검증 입력 로딩` |
| 3 | center·구조 ID·좌표 자산 | `feat: 고정 구조 ID와 기준 좌표 로딩` |
| 4 | 경계 측정과 사진별 진단 | `feat: 고정 630점 경계 측정 이식` |
| 5 | 변위·P12와 중간 계산 대조 | `feat: 변위와 P12 특징 계산 이식` |
| 6 | 모델 학습·추론과 축·부호 대조 | `feat: YT 모델 추론과 학습 이식` |
| 7 | 평가·속도·실패·수치 차이 보고 | `test: 고정 분할 평가와 원본 대조 기록` |
| 8 | 검증된 라이브러리 제품 호출 | `feat: 이미지 바이트 기반 제품 호출 연결` |

개별 과거 실험은 날짜·실험별로 추가 커밋을 나눈다. 같은 알고리즘의 중간 계산·검증·필수 설명은 함께 검토할 수 있도록 묶고, 별개 실험·원본 이동·대량 산출물을 한 커밋에 섞지 않는다. 현재 미이식 파일은 완료 커밋의 범위에 넣지 않는다.

## 커밋과 PR/MR에 남길 내용

문제, 원본 기준 파일·해시, 유지한 조건, 변경한 계산·의존성, 수행한 대조와 수치 차이를 기록한다. 저장된 관측 재생·실제 사진 측정·재대입·OOF를 구별한다. 실패하거나 차이가 남은 경로는 그대로 밝힌다.

코드·빌드 설정·모델 출처·재실행 명령·간결한 검증 요약을 이력으로 관리한다. DATA, build, 실행 바이너리, 큰 중간 결과, 로컬 대화 로그 경로는 자동으로 올리지 않는다. 현재 `.gitignore`는 `results`와 로컬 작성 흔적 목록을 제외한다. 검증 근거를 팀 이력에 남길 때는 필요한 작은 표·요약만 별도로 골라 검토한다.
