# 추가 데이터 요청서 (반복 시험, 노이즈 통계, 정확도 검증용)

## 0. 요청 배경

현재 데이터(281장)는 **한 번의 촬영(약 58분), 한 가지 조명, 장비 한 대**에서 나온 결과입니다. 이 데이터로 확인한 것과 확인할 수 없는 것은 아래와 같습니다.

| 확인된 것 | 확인할 수 없는 것 |
| --- | --- |
| 이미지 측정 정밀도가 높음 (같은 이동 구간 안에서 0.04px 수준) | 같은 자세를 다시 찍었을 때 결과가 얼마나 흔들리는지 (반복성) |
| Θ와 Y를 구분하는 단서가 존재함 (시차, 원근 왜곡) | Θ와 Y가 **동시에** 틀어졌을 때도 맞는지 |
| 이동 방향에 따라 Y 0점이 -0.016 ~ +0.037mm 치우침 (백래시로 추정) | 백래시인지, 시간에 따른 드리프트인지, 정답값 기록 오차인지 |
| center 사진만 밝기가 1.2% 높음 (조명 예열로 추정) | 조명, 온도, 진동, 장비가 바뀌어도 성능이 유지되는지 |

그래서 **같은 조건을 약 100회 반복한 데이터**로 노이즈 통계와 정확도를 검증하고자 합니다.

## 1. 요청 데이터 세트 (우선순위순)

### [필수] A. 정지 반복 촬영: 이미지 노이즈 측정
- 로봇을 움직이지 않고 같은 자세에서 연속으로 **100장** 촬영
- 자세 3곳: center / Θ +0.5 / Y +1.0mm
- 목적: 카메라 노이즈와 측정 알고리즘 자체의 흔들림을 측정 (로봇 오차와 분리)
- 수량: 300장

### [필수] B. 원점 복귀 반복: 로봇 반복 정밀도, 백래시 측정
- 임의 위치로 이동했다가 center로 복귀한 뒤 촬영, 이 과정을 **100회** 반복
- 복귀 방향을 + 방향 50회, - 방향 50회로 나눠서 기록
- 목적: 같은 명령에 대해 로봇이 실제로 서는 위치가 얼마나 흔들리는지, 방향에 따라 얼마나 달라지는지 측정
- 수량: 100장

### [필수] C. Θ와 Y 혼합 격자: 실제 사용 조건 검증
- Θ ∈ {-1.0, -0.5, -0.2, 0, +0.2, +0.5, +1.0} × Y ∈ {-2.0, -1.0, -0.5, 0, +0.5, +1.0, +2.0} (mm) = 49개 자세
- 무작위 순서로 촬영, **2회 반복**
- 추가로 범위 안의 임의 자세 100개를 1장씩 촬영 (최종 시험용, 알고리즘 개발에 사용하지 않음)
- 목적: 두 축이 섞였을 때의 정확도 검증 (현재 데이터에는 혼합 사진이 없음)
- 수량: 198장

### [필수] D. 왕복 스윕: 이력(히스테리시스), 배율 오차 측정
- Θ: -1.0 → +1.0 → -1.0 (0.1 간격), Y: -2.0 → +2.0 → -2.0 (0.1mm 간격)
- **5회 반복**
- 목적: 가는 방향과 오는 방향의 차이, 반복마다의 차이 측정
- 수량: 약 (41 + 81) × 5 = 610장

### [권장] E. 환경 변화
| 항목 | 방법 | 수량 |
| --- | --- | --- |
| E1 조명 밝기 | 조명 밝기 3단계(평소, -20%, +20%) × C의 49개 자세 중 9개 | 27장 |
| E2 조명 예열, 시간 드리프트 | 장비 전원을 켠 직후부터 60분 동안 1분마다 center 촬영 | 60장 |
| E3 온도 | 촬영 시 장비 주변 온도를 함께 기록 (가능하면 온도가 다른 날 B를 한 번 더) | - |
| E4 진동 | 주변 장비가 동작 중일 때 A(center)를 50장 | 50장 |
| E5 초점 | 초점을 의도적으로 약간 어긋나게 한 상태에서 C의 9개 자세 | 9장 |

### [권장] F. 다른 위치, 다른 장비
- 다른 ADDRESS(다른 QR 내용, 다른 라벨)의 브래킷에서 C의 9개 자세
- 가능하면 다른 장비 1대에서도 동일하게
- 목적: 브래킷, 배경, QR 내용이 바뀌어도 동작하는지 확인
- 수량: 9 ~ 18장

### [최종 검증] G. 폐루프 보정 시험
- 임의 자세에서 시작 → 우리 알고리즘으로 보정값 계산 → 로봇 이동 → 다시 촬영 → 남은 오차 기록
- **100회** 반복 (우리 프로그램을 현장 PC에서 실행해야 함)
- 목적: 실제 사용 방식 그대로의 최종 정확도 (명세서의 최종 목표)
- 수량: 100회 × 2~3장

## 2. 사진마다 함께 필요한 정보 (메타데이터)

현재는 파일 이름이 유일한 정보라서 원인 분석이 어렵습니다. 사진마다 아래 정보를 CSV로 함께 주시면 됩니다.

| 칼럼 | 내용 | 필요한 이유 |
| --- | --- | --- |
| `file` | 파일 이름 | 연결용 |
| `set`, `trial` | 세트(A~G), 반복 번호 | 반복 통계 |
| `cmd_theta`, `cmd_y` | 로봇에 내린 명령값 | 정답값 |
| `enc_theta`, `enc_y` | 엔코더로 읽은 실제 위치 (가능하면) | 명령값과 실제 위치의 차이 분리 |
| `approach_dir` | 마지막 이동 방향 (+/-) | 백래시 분석 |
| `timestamp` | 촬영 시각 (ms 단위) | 드리프트 분석 |
| `exposure`, `gain` | 카메라 노출, 게인 | 밝기 변화 원인 분석 |
| `light_level` | 조명 설정값 | 조명 영향 분석 |
| `temperature` | 주변 온도 (가능하면) | 온도 영향 분석 |
| `station_id`, `machine_id` | 위치(ADDRESS), 장비 번호 | 일반화 검증 |

## 3. 함께 필요한 사양 정보

| 항목 | 필요한 이유 |
| --- | --- |
| Θ 단위 (도°인지) | 결과 해석 |
| 허용 오차 (Θ, Y 각각) | 성공 기준 |
| 로봇 스테이지 사양: 분해능, 반복 정밀도, 백래시 | 우리가 도달할 수 있는 오차 바닥 판단 |
| 카메라 캘리브레이션: 초점거리, 화면 중심, 렌즈 왜곡 | 물리 공식 기반 방법(PnP 등) 적용 |
| QR 실제 크기, QR 간 간격, 판까지의 거리 | 위와 같음 |
| 카메라가 로봇에 달린 구조인지, QR 판이 고정인지 | 원리 확인 |
| QR 밖 영역(브래킷, 배경)을 써도 되는지 | 방법 선택 |
| (가능하면) 외부 기준 측정 장비 값 (레이저 변위계, 다이얼 게이지 등) | 정답값 자체의 오차를 독립적으로 확인 |

## 4. 파일 형식 요청

- **8bit 흑백(1채널)** BMP 또는 PNG로 저장 요청 (현재 24bit 3채널이지만 R=G=B라서 용량만 3배)
  - 현재 한 장 24.9MB → 흑백 BMP 8.3MB, PNG(무손실) 약 3~5MB
- 손실 압축(JPG)은 사용하지 않음 (서브픽셀 측정 정밀도가 떨어짐)
- 예상 총량: 필수 A~D 약 1,200장 (흑백 BMP 기준 약 10GB), 전체 약 1,600장

| 로봇 반복 정밀도, 백래시 | B, D | 정답값 오차 바닥 |

| 환경 강인성 | E | 조건별 오차 변화 |

| 신뢰구간 | 전체 | 모든 수치에 95% 신뢰구간 표기 |
