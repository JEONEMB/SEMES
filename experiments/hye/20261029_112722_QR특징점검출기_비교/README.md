# QR 판 특징점 검출기 비교

QR 구조점(채택 control 측정기)과 일반 특징점 검출기를 같은 자료, 같은 이동장 요약, 같은 판정기로 비교한 C++ 실험이다. 보고서 v6의 선행연구 표(검출기 문헌 비교)에 대응하는 실측이 없어 추가했다. 채택 모듈(`00000_final_Y_T control`)은 바꾸지 않는다. 공통 기준은 [ALGORITHM_RULES.md](../../../ALGORITHM_RULES.md)를 따른다.

## 비교 조건

| 방법 | 점 | 대응 방식 |
|---|---|---|
| QR구조점536+GN(채택측정기) | `points.json`의 내부 536점 | 채택 `Tracker::measure()` (NCC → LK15 정·역방향 → 17×17 스플라인 GN 12회), center 측정 변위 차감 |
| QR구조점536+LK | 같은 536점 | QR별 NCC 정수 이동을 초기값으로 OpenCV LK(21×21, 피라미드 2단) 정·역방향, 역방향 오차 0.5 px 이하만 유효 |
| Shi-Tomasi(GFTT)+LK, Harris+LK, FAST+LK | center의 QR 3개 상자 안에서 검출한 최대 800점 | 위와 같은 LK |
| ORB, BRISK, AKAZE, KAZE + 기술자 짝짓기 | center와 현재 영상에서 각각 검출 (현재 영상은 QR 상자를 가로 ±110, 세로 ±22 px 넓힌 영역) | 전수 탐색 knn(2) + 비율 검사 0.8 |

SIFT, SURF는 사용하는 OpenCV 3.4.15 opencv_world 빌드(contrib 없음)에 없어 제외했다.

모든 방법에서 같은 후처리를 쓴다.

- 오매칭: 영상마다 변위의 중앙값에서 가로나 세로로 2 px 넘게 벗어난 짝. QR 모듈 한 칸이 약 7 px이므로 이웃 모듈로 잘못 짝지은 경우를 잡는다.
- 이동장 요약: 오매칭을 뺀 점으로 dx, dy를 2차 다항식(P12)으로 최소제곱 적합한다. 좌표 정규화는 채택 control과 같다 (u = (x − 1906)/486, v = (y − 1070)/122). 같은 방법으로 center 영상을 측정한 P12를 뺀다.
- 점 잡음: P12 적합 잔차의 RMS (px). 판의 실제 이동장은 매끄러우므로 측정 잡음의 지표로 쓴다.
- 판 이동 직선성: P12 상수항(가로)을 명령값에 1차식으로 맞춘 잔차 RMS.
- 판정기: 고정 4-fold(축마다 값 순 정렬 순번 % 4, 학습 210장, 시험 70장). 학습 자료에서 축마다 P12 각 값을 명령값의 2차식으로 맞추고, 두 축의 잔차 공분산(대각 방향 축소 0.01)으로 백색화한 거리가 가장 작은 축과 값을 고른다. 두 축 오차가 모두 0.09 이하이면 통과다.

판정기는 채택 control의 영점 후보 6개와 부호 게이트를 넣지 않은 단순형이다. 그래서 채택 측정기도 여기서는 273/280이며, 채택 모델의 고정 4-fold 280/280과 직접 비교하지 않는다. 방법 사이의 상대 비교용이다.

## 해석

- 기술자 짝짓기는 QR의 반복 무늬 때문에 짝의 9~16 %가 이웃 모듈로 잘못 짝지어졌고, 남은 짝의 점 잡음도 0.23~0.51 px로 LK 추적의 8~18배였다. 통과는 233~274/280이다.
- 판 전체 이동(직선성 0.20~0.21 px)은 모든 방법이 비슷하다. 차이는 Y와 T를 가르는 미세한 2차 변형 성분에서 난다.
- LK로 고정 점을 추적하면 어떤 검출기로 점을 골라도 오매칭은 없었다. QR별 NCC 초기값이 반복 무늬 문제를 막는다. 다만 일반 코너(GFTT, Harris, FAST)는 Y 최대오차가 0.65로, 구조점(0.28~0.30)의 2배를 넘었다.
- 이 단순 판정기에서는 채택 GN 측정기(273)가 같은 점의 OpenCV LK(276)보다 나쁘지 않다고 말할 근거가 없고, 시간은 7배다. 1~3장 차이는 분할과 판정기에 따라 바뀌는 크기이므로 우열로 해석하지 않는다. 채택 판정기(영점 후보 6개)에서 LK 측정으로 바꾸어도 280/280이 유지되는지는 확인하지 않았다.

## 빌드와 실행

저장소 루트 PowerShell에서 실행한다. `results/`가 이미 있으면 덮어쓰지 않고 멈춘다.

```powershell
cmake -S "experiments/hye/20261029_112722_QR특징점검출기_비교" -B build-detector-comparison-20261029 -G "Visual Studio 18 2026" -A x64 -T v141 -DCMAKE_GENERATOR_INSTANCE="C:/Program Files (x86)/Microsoft Visual Studio/18/BuildTools" -DOpenCV_DIR="C:/opencv/build"
cmake --build build-detector-comparison-20261029 --config Release
.\build-detector-comparison-20261029\Release\compare_detectors.exe
```

입력은 `data/clean/clean_20261014`(center + Y 80 + T 200)와 `experiments/hye/00000_final_Y_T control/assets`다.
