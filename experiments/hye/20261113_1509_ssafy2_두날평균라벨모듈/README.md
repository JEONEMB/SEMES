## ssafy 와 무엇이 다른가

| 항목 | 00000_final_Y_T_ssafy | 20261113_1509_ssafy2_두날평균라벨모듈 |
|---|---|---|
| 학습 사진 | 1959장 (rig_1st 280, rig_grid 1679, 11-12) | **3638장** (위 + rig_grid_rev 1679, 11-13 역순) |
| 격자 라벨 | L2: 같은 세트의 이웃 사진으로 만든 보정 | **같은 자세를 반대 순서로 찍은 두 세트의 평균** |
| rig_1st 라벨 | L2 | L2 (역순 짝이 없음) |
| 모델 식별자 | `final00_huber7_qrncc_rig20261112_1959_irls6_r1e-7` (11-13 오후까지 `final00_huber7_rig20261112_1959_irls6_r1e-7`) | `final00_huber7_qrncc_rig2day3638_avglabel_irls6_r1e-7` (11-13 오후까지 `final00_huber7_rig2day3638_avglabel_irls6_r1e-7`) |

라벨 (절대 영점 = 값이 0 인 상태. 세트 영점은 세트 사진 전체 회귀, 보고서 정의와 같다)

- d = 영상 자세 − 명령. 세트 상수 k = d 의 중앙값(세트 사진 전체). 정방향 Y +19.3 µm, T −22.8 mdeg. 역순 Y +286.2 µm, T −55.6 mdeg.
- 격자 사진의 라벨 = 명령 + 자기 세트 상수 + (정방향 d − k 와 역순 d − k 의 같은 자세 평균).
- 반대 순서로 찍었으므로 시간에 따른 직선 흐름이 상쇄된다. 남는 라벨 잡음(라벨 − 그 사진의 영상 자세)은 σT 4.3 mdeg, σY 12.8 µm 다. L2(σT 1.8)보다 크지만, 같은 사진의 값으로 자기 라벨을 만들지 않는다.
- 역순 사진은 바가 8~14 px 밀려 이 모듈의 측정 기준(rig_1st/center.bmp)으로 직접 잴 수 없었다. 역순 센터 기준으로 재고, 센터 계열 18장을 두 기준으로 모두 재서 구한 기준 차이(값 7개, 18장 표준편차 0.005~0.017 px)를 더했다(`evidence/측정기준차이_*.txt`).
- 정방향에서 측정에 실패한 1장(`Y+0.00 T+0.80`)의 역순 짝도 뺐다.

## 성적 (정지 사진, 고정 검증, `evidence/eval/eval.txt`)

통과는 |eY| ≤ 0.045 mm 이고 |eT| ≤ 0.01 도. 같은 자세(정방향·역순)는 한 묶음이라 학습과 평가로 갈리지 않는다.

| 검증 | 결과 |
|---|---|
| 주: 개발 2910장 섞은 80/20 10회 | 탈락 평균 15.3장 (0.5%), rms Y 0.0102 mm, T 0.0037 도 |
| 보조: 계열별 절반 10회 | 탈락 평균 16.0장 |
| 세트 통째로 빼기 (참고) | rig_1st 97.3%, rig_grid 96.4%, rig_grid_rev 92.5% |
| 마지막 확인 728장 | 탈락 7장 (최대 \|eY\| 0.053, \|eT\| 0.0113) |
| 공개 API (`initialize_joint`, `joint`) 정방향 격자 99장 | 99장 측정, 97장 통과, 계수식 계산과 차이 1e-14 |

같은 평균 라벨로 두 모델 비교 (격자 1679장씩)

| 모델 | 11-12 정방향 | 11-13 역순 |
|---|---|---|
| ssafy (11-12 L2 학습, 역순은 처음 봄) | 1675 통과, σY 12.7 µm σT 4.3 mdeg | 1675 통과, σY 14.9 µm σT 4.2 mdeg |
| ssafy_2 (두 세트 학습, 다시 넣은 것) | 1669 통과, σY 9.8 µm σT 3.7 mdeg | 1672 통과, σY 9.8 µm σT 3.8 mdeg |

- 두 모델의 통과 수는 같은 수준이다. 라벨 잡음(σT 4.3 mdeg)이 성적의 바닥을 정한다.
- 세트 통째로 빼기의 rig_grid_rev 92.5% 는 낮게 나온 값이다. 남은 세트의 라벨에 뺀 세트의 시간 흐름 절반이 자세의 함수로 들어 있어, 한 세트만으로 학습하면 모델이 그 모양을 따라간다(Python 재현 92.5%, 바를 빼도 92.4%).

## 한계

- 라벨은 여전히 영상 값에서 나온다. 독립된 정답과의 비교가 아니다.
- 이틀, 세 세트뿐이다. 실제 복귀 검증은 하지 않았다.
- 측정 기준 자료가 ssafy 와 같으므로, 11-13 처럼 바가 11.5 px 넘게 밀린 날의 사진은 측정에서 거부된다. 그날 센터로 측정 기준을 옮기는 기능은 아직 없다.
- 정방향 L2 보정을 다른 날로 옮기면 나빠진다는 것과, 이 평균 라벨을 고른 근거는 위 실험 결과에 있다.

## QR 값 NCC 포물선으로 바꿈, 기준 다시 잡기, 속도, 리눅스 빌드 (2026-11-13)

QR 값을 536점 추적 평균에서 QR 3개 NCC 포물선 평균으로 바꾸고 계수를 다시 학습했다(`evidence/eval_qrncc/`). 위 성적은 536점 계수(`evidence/eval/`)다. NCC 계수: 주 검증 탈락 16.9장(536점 15.3), rms Y 0.0102 T 0.0037, 마지막 확인 탈락 7/728, 세트 통째로 빼기 rig_grid_rev 91.2%(536점 92.5%). 역순 사진의 QR 값은 원래 기준 자료로 직접 잰 NCC 포물선이다.

**바 기울기도 뺐다(값 5개, 2026-11-13 저녁).** `evidence/eval_qrncc5/`, 모델 `final00_huber7_qrncc5_rig2day3638_avglabel_irls6_r1e-7`: 주 검증 탈락 9.0장(값 7개 16.9), rms Y 0.0119 T 0.0040, 마지막 확인 탈락 2/728(값 7개 7), 세트 통째로 빼기 rig_1st 99.6%, rig_grid 91.4%, rig_grid_rev 91.3%.

**QR 방식 고르기**: 기본 ncc(흐림 σ2, 모델 `final00_huber7_qrnccb2v5_rig2day3638_avglabel_irls6_r1e-7`, 주 검증 탈락 10.5, 마지막 확인 2/728), `initialize_joint_method(assets, "track536")` 로 536점 추적 계수(`final00_huber7_qr536v5_rig2day3638_avglabel_irls6_r1e-7`, 주 검증 탈락 9.5, 마지막 확인 2/728)를 쓸 수 있다. 장단점과 속도는 ssafy README "QR 방식 고르기".

코드는 ssafy 와 같다. 그날 센터 사진으로 측정 기준을 다시 잡는 `set_joint_reference`, 쓰지 않던 QR 호모그래피를 뺀 측정(766 → 54~140 ms, 값은 비트까지 같음), 순수 C++ SHA-256 은 [ssafy README](../00000_final_Y_T_ssafy/README.md) 를 본다. 고친 뒤에도 정방향 격자 99장의 공개 API 결과가 고치기 전과 같다(97장 통과).

## 측정값 일치 점검 (2026-11-14)

ssafy 와 같은 점검이다(설명은 [ssafy README](../00000_final_Y_T_ssafy/README.md) "측정값 일치 점검"). 점검식 `assets/health.tsv`(ncc), `health_track536.tsv` 는 이 모델과 같은 3638장으로 `final00_tool health` 가 만들었다. 기준값 5.42.

- 두 날이 섞인 사진으로 만들어서 ssafy(7.44, 한 날)보다 나사 정상 흔들림이 크다(나사1 0.25 px 대 0.05 px). 즉 덜 예민하다.
- 3638장 공개 API: 경고 0, 3624장 통과(점검 넣기 전과 같은 출력).
- 기본은 경고만 남기고 값은 그대로 낸다. `set_joint_health_check(true)` 면 멈춘다.
