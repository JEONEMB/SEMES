작성: 2026-10-29. 상태: 측정 단계만 GN(채택)·ECC·LK로 바꿔 채택 control 학습식으로 다시 학습하고 비교했다. 채택 모듈은 바꾸지 않았다.
공통 규칙은 [ALGORITHM_RULES.md](../../../ALGORITHM_RULES.md)를 따른다. 1단계: [합성 정답](../20261029_122323_부화소정합_합성정답/README.md), [실측 반복성·기하 일관성](../20261029_124339_부화소정합_실측반복성_기하일관성/README.md).

### 날짜 간 참고: 20261014 전체 학습 → 20261020 60장

| 묶음 | 장수 | GN 통과 | ECC 통과 | LK 통과 |
|---|---|---|---|---|
| 센터 | 3 | 3 | 3 | 3 |
| 혼합 \|T\| ≤ 0.09 | 18 | 15 | 15 | 15 |
| 혼합 0.09 < \|T\| ≤ 1 | 27 | 3 | 3 | 3 |
| 혼합 T+2.00 | 12 | 0 | 0 | 0 |

control은 Y 또는 T 한 축만 움직인 자료로 학습한 Y-or-T 모델이다. 그래서 두 축이 함께 움직인 혼합 자세는 원래 적용 범위 밖이며, 세 측정 모두 같은 수준으로 틀렸다. 실제 2차 운용(T를 먼저 맞춘 뒤 촬영)을 대신하는 평가가 아니다.

### 날짜 간 참고: 20261014 전체 학습 → 20261029 혼합 234장

[results_transfer20261029](results_transfer20261029/)(`src/transfer_1029.cpp`). 234장 모두 Y +0.05에 T 0.04~0.82를 함께 준 자세다. 대부분 같은 명령으로 3장씩 찍었다.

| 묶음 | 장수 | GN 통과 | ECC 통과 | LK 통과 | Y 평균 오차 (GN / ECC / LK) |
|---|---|---|---|---|---|
| \|T\| ≤ 0.09 | 18 | 0 | 0 | 0 | 0.311 / 0.313 / 0.312 |
| 0.09 < \|T\| ≤ 0.3 | 60 | 0 | 0 | 0 | 1.092 / 1.095 / 1.094 |
| \|T\| > 0.3 | 156 | 130 | 106 | 122 | 0.358 / 0.713 / 0.470 |
| 전체 | 234 | **130** | 106 | 122 | |

- GN의 130/234는 [LK 재학습 실험](../20261029_132047_control_LK측정_재학습/README.md)이 채택 측정기로 얻은 130/234와 같다. 그 실험의 LK(21×21, 피라미드 2단)는 127, 여기의 LK(1단)는 122였다.
- **\|T\| ≤ 0.09인 18장은 세 측정 모두 0장 통과다.** 모두 Y 축으로 판정했고 Y를 0.31만큼 크게 읽었다(정답 0.05, 예측 약 0.36). 측정법 차이가 아니라 모델 쪽 현상이다. control은 T≈0 전제의 Y-or-T 모델이라, 1차 허용오차 안(0.04~0.09)의 남은 T를 Y로 흡수한다. 실제 2차 운용에서 1차 뒤에 남는 T가 이 정도라면 control의 Y 추정이 크게 틀릴 수 있다. 이것은 별도 검증이 필요하다(실제 T 정렬 후 재촬영 자료 필요). 이 자료는 T 정렬 후 재촬영한 사진이 아니다.

## 해석

- **채택 GN 측정을 바꿀 근거가 없다.** OOF에서 GN만 280/280·축 100%·부호 100%를 지켰다.
- **1단계에서 잰 점 측정 품질이 Y/T 결과까지 이어진다.** 1단계의 반복성 잡음은 GN 0.015, ECC 0.017, LK 0.019 px였다. 차이가 드러난 곳은 판 변위가 아주 작은 T 0.01~0.05 사진이었다. 이런 사진에서는 점 잡음이 특징을 흔들어 축 판정이 바뀐다.
- **ECC는 1C 기하 일관성 지표에서 가장 좋았지만 Y/T 결과는 가장 나빴다.** 1B·1C에서 걱정한 대로, 창이 커서 매끄러워진 변위장이 기하 일관성 지표에서는 유리하게 보였던 것으로 판단한다. 기하 일관성 지표만으로 측정법을 고르면 안 된다.
- **이전 단순 판정기 비교와 결론이 다르다.** [검출기 비교](../20261029_112722_QR특징점검출기_비교/README.md)의 단순 판정기에서는 OpenCV LK 276 대 GN 273이었다. 채택 6후보 판정기로 다시 학습하면 GN 280, LK 280(축 1장 오류)이다. LK가 GN보다 낫다는 근거는 없다. 다만 그 실험의 LK(21×21, 피라미드 2단, 유효점만)와 여기의 LK(15×15, 1단, NCC 초기값)는 설정이 다르다.

## 한계

- 280장은 이미 개발에 노출된 자료다. 이번 측정 비교도 개발 비교다. 독립 신규 성능이 아니다.
- 비교한 측정은 3개뿐이다. 측정법마다 학습 설정(축소값 등)을 따로 조정하지 않고 채택 설정을 그대로 썼다. GN에 유리한 조건일 수 있다.
- 오류 1~2장 차이라서 분할이 바뀌면 순위가 흔들릴 수 있다. 그래서 fold별 결과([summary.csv](results/summary.csv)의 `oof4_fold*`)와 사진별 오차를 함께 남겼다.

## 빌드와 실행

저장소 루트 PowerShell. `results/`가 있으면 덮어쓰지 않고 멈춘다. 약 4분.

```powershell
cmake -S "experiments/hye/20261029_131112_부화소정합_YT결과영향" -B build-yt-impact-20261029 -G "Visual Studio 18 2026" -A x64 -T v141 -DCMAKE_GENERATOR_INSTANCE="C:/Program Files (x86)/Microsoft Visual Studio/18/BuildTools" -DOpenCV_DIR="C:/opencv/build"
cmake --build build-yt-impact-20261029 --config Release
.\build-yt-impact-20261029\Release\yt_impact.exe
```

1단계 폴더의 `src/methods.cpp`·`src/synth.cpp`와 P12/J204 비교 실험의 `src/models.cpp`를 함께 컴파일한다. 입력은 `data/clean`과 채택 control의 `assets`·`validation`(고정 fold와 원본 fold 모델)이다.
