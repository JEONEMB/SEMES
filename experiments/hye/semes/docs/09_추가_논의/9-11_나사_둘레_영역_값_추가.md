# 9-11. 나사 둘레 영역 값을 Y, T 계산에 더한 근거 (2026-11-16)

2단계에서 나사마다 값을 하나 더 잰다. 지금까지의 머리 테두리 맞춤 값(`dx`)에 더해, 나사 둘레 121×121 영역의 밝기 그대로를 맞춘 값(`area_dx`)을 구한다. 3단계 Y, T 계산에 두 값을 모두 넣는다. 바꾼 이유, 바꾸기 전후 비교, 얻은 것과 잃은 것을 정리한다. 방법 설명은 [5-2 나사](../05_구현_방법/5-2_나사.md) 2-6 에 있다.

## 1. 요약

| 항목 | 전 (테두리 값만) | 후 (테두리 + 둘레 영역) |
|---|---|---|
| 처음 보는 날, 그날 영점 5장 (200번 평균), 702장 합계 | 95.5% | **96.1%** |
| 처음 보는 날, 그날 0 의 차이를 아는 경우 | 98.1% | 98.1% |
| 섞음 (571장 × 10번), 마지막 확인 (131장) | 100%, 100% | 100%, 100% |
| 범위 밖 (안쪽 406장으로 배우고 바깥 296장 시험) | 95.3% (282장) | **95.9% (284장)** |
| 측정 시간 가운데값, 스레드 1개 / 4개 | 18.0 ~ 18.8 / 9.5 ~ 9.8 ms | **26.5 ~ 28.0 / 13.6 ~ 13.8 ms** |
| 측정 시간 95% 지점, 스레드 1개 / 4개 | 21.2 ~ 21.9 / 11.3 ~ 11.9 ms | **47.2 ~ 50.4 / 29.6 ~ 30.0 ms** |
| 환경 변화 33건, 현장 장면 10건 | 기준 | 상태와 알림 코드 모두 같음, 조용한 오류 0건 그대로 |

- **얻는 것**: 처음 보는 날의 통과율이 0.6%p, 범위 밖이 0.6%p 오른다. 영점 사진을 어떻게 골라도 대부분 나아진다(5-3).
- **잃는 것**: 측정 시간이 가운데값으로 약 1.5배, 95% 지점으로 약 2.3배 늘어난다. 범위 밖에서 Y 를 크게 읽는 비율이 0.31% 에서 0.34% 로 조금 커진다.
- 사진 한 장의 흔들림은 거의 그대로다. 줄어드는 것은 촬영 날이 바뀔 때 생기는 어긋남이다(6절).

## 2. 바꾼 이유

- 촬영 날을 통째로 빼고 시험할 때, 영점에 쓴 사진에 따라 결과가 크게 흔들렸다. 판이 명령보다 덜 간 사진이 영점에 쓰이면 그날 모든 사진이 같이 밀린다.
- 그런 사진(20261014 의 명령 Y −0.10, −0.20 사진)에서 오른쪽 나사 2, 4 의 머리 테두리 값이 판이 덜 간 만큼보다 약 0.1 px 덜 움직였다. 지금 계산식은 나사 2 에 가장 큰 무게를 주기 때문에 이 차이가 Y 로 그대로 들어갔다.
- 나사 둘레의 판 표면까지 넓게 맞추면 같은 나사도 조금 다르게 읽혔다. 넓게만 재면 정확도가 떨어졌지만, 두 값을 함께 넣으면 정확도가 올랐다.

| 나사 값 넣는 방식 (실험, 같은 학습 절차) | 처음 보는 날, 영점 200번 평균 | 섞음, 영점 200번 평균 |
|---|---|---|
| 테두리 4개 (전) | 95.0% | 97.9% |
| 둘레 영역 4개만 | 94.3% | 97.1% |
| 대각선 두 쌍(1+4, 2+3) 평균만 | 94.7% | 97.4% |
| 테두리와 둘레 영역의 평균 4개 | 94.8% | 97.6% |
| **테두리 4개 + 둘레 영역 4개 (후)** | **95.7%** | **98.3%** |

(기존 702장 중 범위 안 652장, 받은 명령값으로 채점. 학습 라벨, 분할, 영점 후보는 모든 줄이 같다.)

## 3. 바꾼 내용

| 항목 | 내용 | 코드 |
|---|---|---|
| 둘레 영역 맞춤 | 테두리 맞춤 위치(반올림)에서 출발해, 기준 사진의 나사 둘레 121×121 을 현재 사진 145×145 안에서 OpenCV `findTransformECC` (이동만) 로 맞춘다 | `src/steps/02_find_screws.cpp` `refine_by_area` |
| 실패 처리 | 맞춤 실패면 그 나사를 못 찾은 것으로 뺀다. 테두리 값과 0.5 px 넘게 다르면 일부 가림 의심으로 뺀다 (`W_SCREW_PARTIAL`) | `find_one` |
| 값 개수 | 9개: QR, 나사 1~4 테두리, 나사 1~4 둘레 영역 (`kValueCount`). 값 일치 점검과 회차 영점 추정은 앞의 5개만 쓴다 (`kCheckedValueCount`) | `src/steps/03_compute_yt.hpp` |
| 결과 | `Result::screw_area_shift_px[4]` 추가 | `include/alignment.hpp` |
| 계수와 점검식 | 같은 사진 715장을 `prepare_dataset`, `fit_coefficients` 로 다시 학습. 계수 파일에 `screw1_area` ~ `screw4_area` 줄 추가 | `data/model/` |
| 학습 표 | `features.tsv` 에 `screw1_area` ~ `screw4_area` 열 추가 | `tools/train/prepare_dataset.cpp` |
| 예제 기대값 | 예제 5장 최종 값 갱신 (Y 차이 최대 0.0012 mm) | `data/sample/expected.tsv`, `expected_steps.tsv` |

QR 단계, 나사 대략 찾기, 밝기 맞춤, 테두리 맞춤, 일부 가림의 다른 점검은 바꾸지 않았다. 회차 영점(학습 정답)은 앞의 5개 값으로만 구하므로 바꾸기 전과 같다(20261014 Y 0.036579 mm 등).

**OpenCV `findTransformECC` 를 그대로 쓴 이유**: 테두리 맞춤은 1/32 px 끊김을 피하려고 ECC 를 직접 계산한다([5-2](../05_구현_방법/5-2_나사.md) 2-2). 둘레 영역에도 같은 직접 계산을 먼저 넣었더니 측정 시간 가운데값이 스레드 1개 20.3 → 42.8 ms 로 두 배가 넘었다. 정확도는 두 방법이 같은 수준이었다(처음 보는 날 영점 200번 평균 95.7%, 95.7%). 그래서 빠른 쪽을 골랐다.

## 4. 비교 조건

- 사진: 받은 사진 715장. 센터 사진 4장은 5-3 에서만 썼다.
- 전후 코드를 따로 빌드했다. 전은 바꾸기 직전 커밋(eacb7a14)이다. 전후 모두 같은 도구로 715장을 다시 재고 학습했다.
- 정확도: `evaluate_accuracy` (섞음, 마지막 확인, 처음 보는 날, 범위 밖). 오차 크기와 영점 사진에 따른 흔들림은 저장소 밖 실험 폴더(`experiments/20261116_0307_나사좁게넓게_패키지평가`)에서 패키지 학습 계산(`fit_coefficient_set` 과 같은 절차)으로 계산했다. 학습 라벨, 분할, 영점 후보는 `experiments/20261115_corrected_training_raw_eval` 의 것을 그대로 썼다.
- 속도: `measure_speed` (스레드 1개, 4개). 전, 후, 전, 후 순서로 두 번씩 쟀다. 측정 중에 같은 컴퓨터에서 다른 작업이 돌고 있었다.
- 안정성: `check_qr_blocking`, `make_environment_images`, `make_site_images`.
- 통과 기준: |Y| ≤ 0.045 mm 그리고 |T| ≤ 0.01도.

## 6. 왜 나아지는가

| 확인 | 결과 |
|---|---|
| 테두리 값과 둘레 영역 값의 상관 (회차 안 잔차) | 0.986 ~ 0.9995. 거의 같은 값이다 |
| 두 값의 차이가 사진마다 흔들리는 크기 | 0.012 ~ 0.023 px |
| 두 값의 차이가 Y 1 mm 에 변하는 양 | 나사 1 −0.020, 나사 3 +0.013 ~ +0.016, 나사 4 +0.012 ~ +0.018 px (회차가 달라도 방향이 같음) |
| 사진 한 장의 출력 흔들림 (회차 안 잔차로 계산) | 20261014 Y 0.0118 → 0.0116 mm. 거의 같다 |
| 판이 덜 간 사진(20261014 Y −0.10)의 Y 출력 변화 | 0.0485 → 0.0467 mm |

- 계산식은 테두리 값에 거의 전과 같은 무게를 주고, 두 값의 작은 차이를 보정 값처럼 쓴다. 나사 머리와 둘레 판 표면의 높이가 달라 생기는 작은 시차로 보이지만 확인하지 않았다.
- 사진 한 장의 흔들림은 줄지 않는다. 촬영 날이 바뀔 때 생기는 어긋남이 약 0.002 mm 줄어, 허용오차 근처의 사진 몇 장이 안으로 들어온다.

## 7. 한계와 확인하지 못한 것

- 새로 찍은 사진, 학습 범위(Y ±2 mm, T ±1도)보다 먼 자세, 정렬 반복, 포팅한 환경에서는 확인하지 못했다.
- 판이 크게 움직여 둘레 121×121 영역이 다른 물체에 걸리거나 사진 밖으로 나가는 경우는 시험하지 않았다. 이때는 그 나사를 빼고 계산한다.
- 밝기를 15% 올렸을 때 출력 변화가 조금 커졌다(실험, 사진 72장: Y 최대 0.006 → 0.009 mm).
- 데이터가 더 많을 때 효과가 커지는지 줄어드는지는 시험하지 않았다.
- 개선 폭이 652장 중 수 장이다. 받은 사진 4회차로 얻은 결과다.
