# 10. 패키지 검증

2026-11-16에 패키지 소스로 전체 Release 빌드와 아래 실행 절차를 검증했다. 환경은 Windows x64, MSVC 19.51, OpenCV 3.4.15다. 원본 ZIP과 수정한 작업 폴더는 서로 다른 시점의 자료이므로 수정 문서를 전달하려면 수정본 ZIP을 사용한다.

## 1. 실행 전 확인

1. [02 사용법](02_사용법.md)의 OpenCV 라이브러리 경로와 DLL PATH를 설정한다.
2. 모든 명령은 패키지 루트에서 실행한다. 모델은 `data/model` 같은 영문 상대 경로를 사용한다.
3. 기본 ZIP에는 예제 5장이 있고 전체 학습 사진은 별도 준비해야 한다. 원본 715장은 회차별 폴더에 배치한다. 예제 5장만으로 전체 학습 성능을 검증할 수 없다.
4. 기존 표가 있더라도 전처리 규칙 이력이 없으면 새 표 폴더에 다시 만든다. 표의 사진 경로는 실행 작업 디렉터리 기준이므로 실행 중 사진을 이동하지 않는다.
5. 이 프로젝트에는 CTest에 등록한 테스트가 없다. 아래 도구의 출력과 결과 파일을 확인해야 한다. 종료 코드 0만으로 정확도 통과를 판단하지 않는다.

## 2. 예제와 초기화 확인

```powershell
New-Item -ItemType Directory -Force data/results/package_check
build/Release/check_photos data/model data/sample/list.tsv data/results/package_check/sample.tsv data/sample/expected.tsv
build/Release/measure_one data/model data/sample/sample_1.png
build/Release/measure_one data/model data/sample/sample_1.png data/sample/sample_1.png
build/Release/show_steps data/model data/sample/sample_3.png
build/Release/check_setup data/model data/sample/list.tsv
```

예제 5장은 정상 3장, `W_OUT_OF_RANGE` 경고 2장, 실패 0장이다. 기대값 비교 장수가 반드시 5이며 Y, T 최대 차이는 출력 정밀도에서 0이다. 경고 2장을 빌드 실패로 해석하지 않는다.

`check_setup`은 진단 도구다. 영점 적용 차이 0, 기준 재등록 성공, 나사 2 가림 후 사용 조합 `134`를 확인한다. 이번 실행에서 기준 재등록 후 최대 차이는 Y 0.00106 mm, T 0.00020도였다. 나사 2 가림 전후 차이는 Y 0.01047 mm, T 0.00092도였다. 이 차이는 로봇 명령 기준 정확도가 아니라 원본 사진 측정값과의 차이다.

별도 공개 API 검증에서는 초기화 전 호출, 모델과 설정 누락, 빈 사진, 잘못된 크기와 깊이와 채널, QR 없는 사진, BGR/BGRA 입력, 영점 설정과 복원, 실패 후 기존 상태 보존 등 23개 검사가 통과했다. 한글 모델 경로는 한국어 Windows ANSI 인자로 확인했으며 UTF-8 한글 모델 경로까지 보장하지 않는다.

## 3. 학습, 평가, 속도

각 출력 경로는 새 경로 또는 빈 폴더를 사용한다.

```powershell
build/Release/prepare_dataset data/new_photos --output data/results/package_check/tables
build/Release/fit_coefficients data/results/package_check/tables data/results/package_check/model
build/Release/evaluate_accuracy data/results/package_check/tables data/results/package_check/accuracy
build/Release/measure_speed data/model data/results/package_check/tables data/results/package_check/speed
build/Release/compare_far_pose_methods data/results/package_check/tables data/results/package_check/far
build/Release/score_photos data/new_photos/20261014 data/results/package_check/score_20261014
```

`score_photos`는 회차별로 실행한다. 받은 사진에는 명령 (0, 0) 사진이 없어 자동 영점 없이 채점되며, 이 점수는 근접 명령 사진으로 영점을 추정하는 `evaluate_accuracy`와 다르다. 운영 평가에는 같은 날 명령 (0, 0) 사진만 모은 폴더를 `--zero`로 넘긴다. `--answers`를 쓸 때는 파일 이름, Y, T 순서의 탭 표를 제공한다.

이번 검증 결과는 다음과 같다.

| 항목 | 결과 |
|---|---|
| 원본 측정 | 명령 사진 715장, 측정 실패 0장, 모든 나사 검출 |
| 학습 제외 | 범위 밖 12장, 확인 규칙에 따른 제외 1장 |
| 재학습 | 702장 사용, 모델 파일 30개가 배포 모델과 바이트 단위 일치 |
| 내부 교차검증 | 개발 563장, 5묶음 10회, 5630/5630 통과 |
| 내부 마지막 확인 | 139/139 통과 |
| 범위 밖 내부 진단 | 284/296 통과 (95.9%) |
| 속도, 1스레드 | 측정만 중앙값 26.4 ms, 95% 47.5 ms, 최대 93.6 ms |
| 속도, 4스레드 | 측정만 중앙값 18.9 ms, 95% 44.5 ms, 최대 67.9 ms |

내부 정확도는 보정된 학습 라벨 기준이다. 전체 자료에서 만든 회차 영점 라벨을 분할 간 공유하므로 전처리까지 분리한 독립 검증으로 해석하지 않는다. 분할 수가 이전 문서의 571/131과 다른 이유를 판단할 때는 `std::shuffle` 구현과 보존한 `splits.tsv`를 확인한다. 고정 씨앗만으로 도구 체인 간 동일 분할을 보장하지 않는다. 속도는 PC 부하와 파일 캐시의 영향을 받으며 이전 기록을 보장하는 성능 사양으로 쓰지 않는다.

대화형 경로도 별도로 실행한다.

이번 실행에서 `score_photos`와 `train`의 대화형 경로가 모두 종료 코드 0으로 완료됐다. 회차 4개의 명령줄 평가도 완료했고, 별도 정답표와 자동 영점, 명시적 `--zero`, 허용오차 옵션은 예제에서 각각 확인했다. 이 옵션 검사는 예제 기대값으로 만든 표를 이용한 기능 검증이며 독립 정확도 시험은 아니다.

```powershell
build/Release/score_photos
build/Release/train
```

## 4. 환경 변화와 문서 그림

```powershell
build/Release/make_environment_images data/model data/results/package_check/environment
build/Release/make_site_images data/model data/results/package_check/site
build/Release/check_new_installation data/model data/sample/list.tsv data/sample/expected.tsv data/results/package_check/installation_work data/results/package_check/installation
build/Release/check_qr_blocking data/model data/results/package_check/tables data/results/package_check/qr_blocking
build/Release/make_figures data/model data/new_photos data/results/package_check/figures
```

교란 시험에서는 경고와 실패 발생이 정상적인 시험 결과일 수 있다. 각 TSV의 수치 오차, 상태, `silent_error`를 함께 확인한다. 새 설치 시험도 모든 사례의 허용오차 통과를 뜻하지 않는다. 예를 들어 거리 비율이 1.02인 사례는 기준 재등록 후에도 5장 중 3장만 통과할 수 있어 계수 재학습이 필요하다.

이번 환경 합성 33건과 현장 합성 10건에서 정상 상태로 허용오차를 초과한 사례는 0건이었다. QR 가림과 반사 시험은 사진 59장에 31개 교란을 적용한 1,829건이며, 값을 반환한 354건은 원본 측정값과의 허용오차 안이었다. 나머지 1,475건은 실패로 처리했다. 새 설치 27개 조건과 문서 그림 생성도 실행 완료했다.

`make_figures`는 Windows 전용 빌드 대상이며 예제 그림 외에 지정된 실촬영 사진도 필요하다. 사진이 없으면 실패한다. 출력 폴더를 지정하면 동봉 문서 이미지를 덮어쓰지 않고 확인할 수 있다.

## 5. 검증 범위

실제 카메라 획득, 로봇 이동 후 복귀, 다른 PC와 OpenCV 버전, 장기 반복 운전은 이 시험에 포함되지 않는다. 일반 명령줄 도구는 잘못된 입력에 대한 자동 시험 프레임워크가 아니므로 사진 존재 여부, 출력 장수, 실패 수를 직접 확인한다. 실행 중 파일이 사라졌을 때 출력된 빈 측정이나 속도 0은 유효한 성능 결과가 아니다.

결과보고서와 부록의 과거 그림은 작성 당시 기록이다. 현재 코드 계약과 재현 절차는 수정된 사용법, 구현 방법, 평가 방법, 포팅 안내서와 이 문서를 우선한다.
