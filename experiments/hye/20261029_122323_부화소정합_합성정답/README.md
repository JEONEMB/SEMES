# 부화소 정합 방법 1단계: 합성 정답 실험

작성: 2026-10-29. 상태: 합성 영상에서 점 측정 정확도·실패·시간만 측정했다. 실측 반복성·기하 일관성(1B·1C), Y/T 결과 영향(2단계), 정식 속도 측정(3단계)은 아직 하지 않았다.
공통 규칙은 [ALGORITHM_RULES.md](../../../ALGORITHM_RULES.md)를 따른다. 넓은 재실험 설계는 [특징점 추적 재실험 방법론](../20261029_121819_특징점_추적_재실험방법론/PROTOCOL.md)에 있다. 이 실험은 그 설계에서 "합성 영상은 보조 자료"로 둔 부분이다.

## 무엇을 쟀나

실측 사진에는 점마다 정답 좌표가 없다. 그래서 `center.bmp`에 **알려진 변형**을 넣은 영상을 만들고, 채택 control의 고정 630점(`points.json`) 각각의 변위 정답을 계산했다. 같은 영상과 같은 점에 정합 방법 9개를 돌려 `추정 − 정답`을 비교했다.

이 결과는 점 위치 측정의 비교다. Y/T 추정 성능이나 실제 촬영 성능이 아니다. 보간으로 만든 영상의 성적을 실측 정밀도로 대체하지 않는다.

## 합성 조건 (72장)

모든 조건은 `kCrop`(1340,800,1130,530) 영역만 변형해 원본 크기 영상에 다시 넣는다. 합성 영상은 8비트로 양자화한다.

| 묶음 | 장수 | 변형 | 영상 생성 |
|---|---|---|---|
| 평행이동_x | 21 | tx = 3 + 0~1 (0.05 간격), ty = −1.65 | FFT 위상 이동 (대역 제한 정확 이동), 잡음 없음 |
| 평행이동_y | 21 | tx = 3.35, ty = −2 + 0~1 (0.05 간격) | 위와 같음 |
| 평행이동+잡음 | 11 | tx = 3 + 0~1 (0.1 간격), ty = −1.65, 잡음 σ̂ | FFT 이동 + 정규 잡음 |
| 회전·배율 | 8 | t = (3.4, −1.7), 판 중심(1906,1070) 기준 회전 ±0.02/0.05/0.1°, 배율 0.999/1.001, 잡음 σ̂ | Lanczos4 아핀 |
| 밝기·흐림·잡음 | 7 | t = (3.4, −1.7), 잡음 σ̂ 위에 gain 0.7·offset +20 / gain 1.3·offset −20 / offset +30 / 흐림 σ 0.7·1.2 / 잡음 2σ̂·4σ̂ | FFT 이동 |
| 가림 | 4 | t = (3.4, −1.7), 잡음 σ̂, QR마다 21×21 회색(128) 사각형 3개 (seed 401~404) | FFT 이동 |

- σ̂ = 1.048 (회색값). 20261020 기준 위치 center1~3 세 쌍의 평탄부 차이로 MAD를 구해 추정했다. 차이가 정수라서 MAD가 양자화되어, 세 쌍 모두 정확히 1.4826/√2가 나왔다. 대략적인 값이고, 2σ̂·4σ̂ 조건으로 위쪽 범위를 따로 확인했다.
- 회전·배율 크기는 실제 T 이동이 만드는 변형을 측정해서 정한 값이 아니다. 가정한 범위다.
- Lanczos4 아핀 영상은 생성기 자체의 보간 오차를 포함한다. 그래서 회전·배율 묶음의 작은 오차(0.01 px 수준)는 정답 쪽 오차와 섞여 있을 수 있다.

## 방법 (9개)

| 방법 | 초기값 | 정밀화 |
|---|---|---|
| NCC(정수) | 채택과 같은 QR 단위 NCC → 점마다 17×17 템플릿 정수 NCC (±3 px) | 없음 |
| NCC+포물선 | 위와 같음 | NCC 점수 3점에 가로·세로 각각 2차식 |
| NCC+위상상관 | 위와 같음 | OpenCV `phaseCorrelate`, 32×32, Hann |
| QR단위NCC+위상상관64 | QR 단위 NCC만 | `phaseCorrelate` 64×64가 정수·부화소를 함께 찾음 |
| NCC+cornerSubPix | 점 단위 NCC | `cornerSubPix` 창 11×11. center에서도 같은 방식으로 다듬은 위치를 빼서 변위를 냄 |
| NCC+LK(1단) | 점 단위 NCC | OpenCV LK 15×15, 피라미드 0단, σ 0.8 흐림, 정·역방향 추적 |
| 피라미드LK(3단·NCC없음) | 초기값 없음 | OpenCV LK 21×21, 피라미드 3단 |
| NCC+LK15+GN스플라인(채택측정기) | 채택 `Tracker::measure()` 그대로 (QR NCC → LK15 정·역방향 → 17×17 3차 B-스플라인 GN, gain/offset 포함) | |
| NCC+ECC | 점 단위 NCC | `findTransformECC` 이동 모델, 템플릿 31×31 |

구현에서 정한 사항:

- **ECC:** 처음에는 21×21 창을 따로 넣고 ECC 내부 흐림(기본 5×5)을 썼다. 이때 오차가 부화소 위치와 무관하게 0.18 px로 고정됐다. 작은 템플릿과 입력 창을 따로 흐리면 경계 처리가 달라 점마다 편향이 생기기 때문으로 보인다. 그래서 영역 전체를 σ 0.8로 한 번 흐리고 내부 흐림을 껐다(`gaussFiltSize=1`). 창은 31×31로 키웠다. 이 결과는 빠른 확인 실행에서 보고 바꾼 설정이다.
- **위상 상관:** OpenCV 3.4.15 `phaseCorrelate`를 그대로 썼다. 부화소는 이 함수의 기본 가중 중심 계산이다. 64×64 변형으로 정수 부분은 맞는 것(부호 정상)을 확인했다. 피크 정밀 적합(sinc 맞춤 등)은 구현하지 않았다. 그래서 아래 결과는 **이 구현의 결과**이고 위상 상관 원리 자체의 한계로 일반화하지 않는다.
- **cornerSubPix:** 630점은 검정·흰 경계 위의 점이라 대부분 직각 코너가 아니다. 모서리 방향으로 미끄러질 수 있다. 시작점에서 3 px 넘게 움직이면 실패로 기록했다.
- **정·역방향 오차(FB):** 방법이 아니라 검사이므로 따로 평가했다. LK(1단)과 채택 측정기 내부 LK의 FB 오차를 사용한다.

## 지표

- 오차 = ‖추정 변위 − 정답 변위‖ (px). 수치 결과가 나온 점만으로 계산한다.
- `실패`: 수치 결과를 내지 못한 점의 수. 분모는 72장 × 630점 = 45,360이다.
- `실패 또는 >0.5`: 실패이거나 오차가 0.5 px를 넘은 점의 비율. 분모는 전체 점이다.
- 시간: 영상 한 장의 측정만 잰 것이다(영상 생성 제외). 1스레드, warm-up 없이 각 조건 1회 실행했다. 3단계 정식 속도 측정을 대신하지 않는다.

## 해석 (합성 영상 범위 안에서)

- **정밀도 순서:** 잡음 없는 평행이동에서 채택 GN 측정기의 p95는 0.005 px로 가장 작았다. 그다음이 ECC·LK(0.03~0.04 px), 포물선(0.17 px), 위상 상관(0.44~0.48 px), 정수 NCC(0.61 px) 순이다. 편향 곡선도 같은 순서다. 정수 쪽으로 끌리는 현상은 포물선에서 최대 0.04 px, ECC에서 0.016 px, GN에서 0.0003 px였다.
- **밝기 변화:** gain 0.7·offset +20에서 LK(1단)는 점의 43%가 0.5 px를 넘었다. 같은 조건에서 GN(gain/offset 추정)은 0.3%, ECC(정규화 상관)는 0%였다. LK의 밝기 불변 가정이 깨질 때의 차이다. LK가 밝기 때문에 생긴 오차는 FB 재현율이 낮았다(0.29). 정방향과 역방향이 같은 쪽으로 틀리면 FB로 잡기 어렵다.
- **큰 실패:** gain 0.7 조건에서 점 120, 121은 LK가 수십 px 엉뚱한 곳으로 갔다. GN은 LK 결과에서 출발하므로 같이 틀렸다(최대 57 px). FB 오차가 66~102 px라서 채택 측정기의 유효성 검사로 걸러진다. 유효성 검사를 빼고 쓰면 안 된다는 뜻이다.
- **흐림과 가림:** 이 조건에서는 GN의 우위가 줄었다. 흐림 σ 1.2에서 p95는 LK 0.22, GN 0.25, ECC 0.13, 피라미드 LK 0.10 px였다. 가림에서는 피라미드 LK(0.13 px)와 ECC(0.15 px)의 p95가 가장 작았다.
- **cornerSubPix:** 실패가 1,053점으로 가장 많았다. 대부분 코너가 아닌 경계 점에서 모서리를 따라 미끄러진 경우로 보인다. 이 점 집합에는 맞지 않는다.
- **위상 상관:** 이 구현에서는 부화소 부분을 거의 복원하지 못했다. 편향 곡선이 정수 NCC와 거의 같다.
- **시간(참고):** 피라미드 LK·NCC·포물선이 약 10 ms, LK(1단) 16 ms, 위상 상관 20~32 ms, GN 38 ms, ECC 179 ms였다. 1회 실행이라 정식 측정이 아니다.

## 한계

- 합성 영상은 실제 렌즈·센서·조명·비평면 변형을 다 반영하지 않는다. 이 순위가 실측에서도 같다고 주장하지 않는다.
- 평행이동은 FFT로 만들었다. GN의 B-스플라인과 다른 보간이므로 생성기와 측정기가 같은 보간을 쓰는 문제(inverse crime)는 피했다. 그래도 대역 제한 영상이라는 점에서 실제 영상보다 보간에 유리할 수 있다.
- ECC는 빠른 확인 실행 결과를 보고 설정을 고쳤다. 다른 방법은 기본값 또는 채택 설정을 썼다. 방법별 조정 예산이 같지 않다.
- 회전·배율 크기와 밝기·흐림 범위는 가정이다. 잡음 σ̂는 양자화된 추정이다.

## 빌드와 실행

저장소 루트 PowerShell에서 실행한다. `results/`가 이미 있으면 덮어쓰지 않고 멈춘다.

```powershell
cmake -S "experiments/hye/20261029_122323_부화소정합_합성정답" -B build-subpixel-synthetic-20261029 -G "Visual Studio 18 2026" -A x64 -T v141 -DCMAKE_GENERATOR_INSTANCE="C:/Program Files (x86)/Microsoft Visual Studio/18/BuildTools" -DOpenCV_DIR="C:/opencv/build"
cmake --build build-subpixel-synthetic-20261029 --config Release
.\build-subpixel-synthetic-20261029\Release\subpixel_synthetic.exe
```

인자로 `<결과 폴더> quick`을 주면 다른 폴더에 조건 10개 중 1개만 돌린다(빌드 확인용). 입력은 `data/clean/clean_20261014/center.bmp`(해시 확인), `data/clean/clean_20261020/기준 위치/center1~3.bmp`(잡음 추정), `experiments/hye/00000_final_Y_T control/assets`(630점, 채택 측정기)다.
