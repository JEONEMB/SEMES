# 결과: 방법론별 증강 자료와 고정 검증 (11-12)

## 문제

11-12 실험들은 검증 방식(분할, 반복 수, 라벨, 사진 수)이 서로 달라 숫자를 직접 비교할 수 없었다. 좋았던 방법(절대 영점, QR 표현, 나사 측정, 바 구성, 날 차이 증강)을 하나씩만 확인했고 합쳐서 비교하지 않았다. 앞서 만든 증강 자료도 예전 구성(00004 의 66개 값) 위에 만든 것이었다.

## 방법

- 사진 702장(ID 702 제외, T=+2.00 12장 제외), 절대 영점 라벨(`20261112_1731_.../결과/절대영점_라벨_702장.tsv`), 00004 Huber 학습식. 통과는 |eY| ≤ 0.045 이고 |eT| ≤ 0.01.
- 방법론 48가지 = QR 6(ECC54, ECC24, ECC6, 536점 평균 2, 536점 P12, 536점 3차식 20) × 나사 측정 2(old 밝기 조각, grad 기울기 영상) × 바 4(both, up, lo, none). 나사는 4개 고정.
- 방법론마다 날 차이 증강 자료(원본 702 + 복사본 8 × 702 = 6318행, 배율 2, seed 20261112)를 만들어 `data/augmented/20261112_1835_.../결과/증강자료/<방법론>/` 에 두었다. 48 폴더, 74 MB.
- 조합 96가지 = 방법론 48 × 증강 유무 2. 검증 안에서는 학습 조각만으로 날 차이 벡터를 다시 구해 증강했다.
- 분할(`결과/splits.json`, 자세 묶음 단위): 마지막 확인 142장(20%)을 먼저 떼고 개발 560장에서만 골랐다.
  - 주 검증: 개발 자료 섞은 80/20, 10회
  - 보조: 세션별 절반 50/50, 10회
  - 참고: 세션 통째로 빼기
- 강건성: 주 검증 앞 3회의 모델에 시험 사진의 원시 측정값을 흔들어 넣었을 때 통과율. QR 하나 가로 +0.3 px, QR마다 잡음 0.1 px, 나사 하나 가로 +0.3 px, 나사마다 잡음 0.1 px, 바 하나 +0.3 px. "강건 최소"는 이 중 가장 낮은 값.
- 고르는 규칙(실행 전에 정함): 주 검증 탈락이 최소에서 0.5장 이내인 조합 중 강건 최소가 큰 순, 다음 50/50 탈락, 다음 값 수. 상위 5개와 base 를 마지막 확인 자료로 한 번 확인.
- 실행: 저장소 루트에서 `python "<이 폴더>/실험/combo.py"`. 전체 표는 `결과/결과.tsv`(96행), 출력은 `결과/출력.txt`.

## 해석

- 나사를 기울기 영상으로 재는 것이 가장 확실한 개선이다. 개발 탈락이 평균 3.3 → 1.0장으로 준다. 주 검증 상위 14개가 모두 grad 다.
- QR 값이 많을수록 같은 날 정확도는 조금 좋고 교란에는 약하다. 536점 3차식은 10회 모두 탈락 0장이지만 강건 최소가 50% 다. 536점 평균 2개는 탈락 0.8장이지만 강건 최소가 89% 다.
- 위쪽 바가 가장 약한 고리다. 위쪽 바 값에 0.3 px 를 더하면 "위만" 구성은 통과가 0%, "둘 다" 구성은 50% 다. 아래쪽 바는 85~97% 를 유지한다. 바를 빼면 같은 날 탈락은 평균 0.9장 늘고 강건성과 처음 보는 날 성적이 오른다.
- 날 차이 증강은 처음 보는 날 성적을 평균 59.8 → 89.0% 로 올리고 같은 날 탈락을 평균 0.9장 늘린다. 값이 적은 구성(536점 평균 2 + 나사 grad + 바 없음)에서는 4차까지 94% 로 올라, 앞 실험에서 못 올리던 4차가 처음으로 올랐다.
- 규칙대로 고르면 1위는 "QR ECC6 + 나사 grad + 바 없음, 증강 없음"(값 14개)이다. base 보다 탈락이 적고(1.3 → 0.4장) 강건 최소가 높다(50 → 77%). 마지막 확인 142장에서 탈락 0장이다.
- 마지막 확인 자료에서는 상위 5개와 base 모두 탈락 0장이라 이 자료로는 순위를 가릴 수 없다.

## 한계

- 96가지 중에서 같은 개발 자료로 골랐다. 탈락 0~1장 차이는 분할에 따른 흔들림 범위 안이다.
- 강건성은 측정값에 숫자를 더한 것이다. 사진을 바꿔(밝기, 흐림, 가려짐) 다시 잰 것이 아니다. 교란 크기(0.3 px, 0.1 px)는 임의로 정했다.
- 세션을 통째로 뺀 시험은 날 효과와 안 배운 위치 효과가 섞여 있고 세션이 4개뿐이다.
- 절대 영점 라벨은 00004 의 66개 값으로 정의했다. 다른 구성에도 같은 라벨을 썼다.
- 나사 grad 측정과 536점 표현은 Python 분석값이다(536점 측정만 C++). 채택하려면 C++17, OpenCV 3.4.15 로 옮겨 다시 검증해야 한다.
- ECC 말고 다른 영역 기반 방법, 나사 원 테두리 맞춤은 넣지 못했다.

## 추가: 세로 방향 값을 뺀 구성 (11-12)

값이 달라지는 원인을 나누면 바 세로 이동은 90% 가, 나사 − QR 세로 시차는 75% 가 날 차이이고, 가로 이동·가로 시차·바 기울기는 99.9~100% 가 Y, T 움직임이다. 그래서 세로 값을 빼고 가로 값과 바 기울기만 쓰는 구성을 같은 사진, 같은 라벨, 같은 분할, 같은 교란으로 채점했다. 실행: `실험/horizontal.py` → `결과/가로만_결과.tsv`, `결과/가로만_출력.txt`. base 와 앞 표의 두 구성을 함께 돌려 숫자가 앞 표와 같음을 확인했다.

- 세로 값을 빼면 증강 없이 처음 보는 날이 61~64% 에서 98~99% 로 오른다. 4차도 7% 에서 93~95% 로 오른다. 같은 날 탈락은 늘지 않고 오히려 준다(0.4 → 0.0~0.1장).
- 나사의 세로 값 하나만 다시 넣어도 4차가 93% 에서 62% 로 떨어진다. 날 차이는 세로 값에 들어 있다.
- 이 구성에서는 날 차이 증강이 필요 없고, 넣으면 같은 날 탈락이 2~3장 는다.
- 나사 측정은 여전히 grad 가 필요하다. old 로 바꾸면 탈락이 5.0장이다.
- 가장 적은 구성은 값 5개(QR 가로 평균 1 + 나사 4개의 가로 이동)다.

한계
- 세로 값을 버리면 세로 방향 정보를 쓰는 다른 이상(세로로 밀림, 다른 축의 변화)을 모델이 알아채지 못한다. 품질 판정에는 세로 값을 따로 써야 한다.
- 구성을 같은 개발 자료에서 골랐고, 세로 값을 빼자는 판단도 같은 702장을 보고 내렸다. 마지막 확인 142장은 모든 상위 구성이 0장이라 순위를 가르지 못한다.
- 세션이 4개이고 날 차이의 종류는 사실상 2가지다. 가로 값에 영향을 주는 새로운 종류의 날 차이가 오면 다시 봐야 한다.
- 나사 grad 측정은 Python 이다. C++17, OpenCV 3.4.15 로 옮겨 검증해야 한다.

## 결정 (11-12, 사용자 확인)

새 기준 구성을 아래로 한다. 이후 비교는 이 구성에서 한 가지씩 바꿔 본다.

| 항목 | 기준 |
|---|---|
| 센터 | 절대 영점 라벨 |
| QR | 536점 이동의 가로 평균 (값 1) |
| 나사 | 4개, 기울기 영상 맞춤, 가로 이동만 (값 4) |
| 바 | 위·아래 바의 기울기만 (값 2). 세로 이동은 쓰지 않는다 |
| 증강 | 쓰지 않는다 |
| 합계 | 값 7개. `horizontal.py` 의 "QR P536_2 x / 나사 grad x / 바 tilt" |

- 이 구성의 성적: 개발 탈락 0.1장, 50/50 탈락 0.2장, 강건 최소 88%, 처음 보는 날 99%, 마지막 확인 142장 탈락 0장.
- QR 은 내가 536점 평균으로 골랐다(강건 최소 88% 대 ECC 평균 77%, 정확도는 같음). ECC 평균으로 바꿔도 되는 대안이다.
- 배포 모델(00004)은 바꾸지 않았다. 나사 기울기 영상 측정을 C++17, OpenCV 3.4.15 로 옮겨 검증한 뒤에 바꾼다.
- 세로 값은 Y, T 계산에서 빼고 품질 판정에 따로 쓴다(아직 만들지 않았다).
