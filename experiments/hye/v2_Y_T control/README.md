# 2차 control C++ 모듈 v2

공통 목표, 관측 제약, 평가는 [ALGORITHM_RULES.md](../../../ALGORITHM_RULES.md)를 따른다. 2차 control의 판정 기준은 한 장 `|eY| ≤ 0.045`이다. 보조로 같은 자세 반복의 Y 전폭 ≤ 0.045를 함께 본다.
v1 [00000_final_Y_T control](../00000_final_Y_T%20control/README.md)의 QR 536점 측정기를 그대로 쓰고, **위·아래 바 기울기로 남은 T를 재서 Y에서 빼는 단계**를 더했다. 공개 함수와 CMake 대상 이름(`semes_control`)은 같다. 빌드에 쓰려면 [selected_modules.cmake](../../selected_modules.cmake)의 `SEMES_CONTROL_DIR`를 이 폴더로 바꾼다(이 작업에서는 바꾸지 않았다).

## 무엇을 바꿨나, 왜

control은 1차 joint가 T를 맞춘 뒤 Y를 맞추는 단계다. v1은 T≈0을 전제로 만들어져, **남은 T가 조금만 있어도 Y가 크게 틀린다**(T 1단위가 Y 약 5.6 mm와 같은 화면 이동을 만든다). 1차 기준(|eT| ≤ 0.01)을 지켜도 남은 T 0.01은 Y 약 0.056에 해당해 2차 기준 0.045를 넘을 수 있다.

| | v1 | v2 |
|---|---|---|
| QR 측정 | NCC → LK15 → 17×17 스플라인 GN, 고정 536점, center 자기 측정 차감 | **같음** |
| 바 측정 | 없음 | joint와 같은 바 48블록 정합 → d = 위 바 기울기 − 아래 바 기울기 ([A21](../20261104_094732_A21_바측정_강건화비교/결과/보고서.md)) |
| 모델 | P12 + 6절편 후보 곡선 역산, Y 또는 T 중 하나만 출력 | 아래 식 |
| 출력 | `(Y, 0)` 또는 `(0, T)` | `(y, t)`: y = Y 추정, t = 남은 T 추정 |

```
s  = 536점 중 유효점의 가로 이동 평균 (px)
t^ = c0 + c1·s + c2·d                      남은 T 추정
y  = a0 + a1·s − k·soft(t^, θ)             soft(v, θ) = |v| ≤ θ 이면 0, 아니면 v − sign(v)·θ
```

- **학습 자료는 1차(20261014) 사진만 쓴다.** 2차(20261020), 3차(20261029)는 학습에 쓰지 않고 평가에만 쓴다.
- a0, a1: 20261014의 T = 0 사진 81장으로 맞춘 s → Y 직선. T가 0이면 이것만 쓴다.
- c0~c2: 20261014의 \|T\| ≤ 1 사진 281장으로 맞춘 남은 T 추정. 바 기울기 차 d는 카메라 세로 이동에 영향을 받지 않는다.
- k = 5.618: Y 직선 잔차를 T로 회귀한 기울기. 감도비 이론값 5.617과 맞는다.
- **θ = 0.01 (T 1틱)**: 남은 T 추정이 1틱 안이면 보정하지 않는다. 바 기울기 잡음이 Y로 번지는 것을 막는다. 0.0075~0.015를 비교해 골랐다([A22](../20261104_103107_A22_control_v2_후보비교/결과/보고서.md), [A23](../20261104_103651_A23_control_v1v2_교란강건성/결과/보고서.md)).

## 함수 계약

```cpp
void initialize_control(const std::string& control_assets, double maximum_control_t = 0.09); // 두 번째 인자는 호환용, 쓰지 않음
Alignment_t control(cv::Mat& src);
AlignmentDiagnostics alignment_diagnostics();
```

- **출력이 v1과 다르다.** v1은 Y와 T 중 하나만 내고 나머지를 0으로 두었다. v2는 항상 `y`(Y 추정)와 `t`(남은 T 추정)를 같이 낸다. 호출 측이 v1처럼 "t가 0이면 Y 축"으로 해석했다면 고쳐야 한다.
- `control_precondition_met`: \|t\| ≤ 0.01이면 참이다. 2차의 T≈0 전제를 이 사진에서 확인한 결과다. 거짓이면 호출 측이 1차로 돌아가 T를 다시 맞추는 판단에 쓸 수 있다.
- `outside_training_range`: s나 d가 학습 자료 범위 밖이면 참. 값은 자르지 않는다.
- `selected_axis`는 항상 `"Y"`, `selected_branch`는 `"v2"`다. `model_cost`, `other_axis_cost`, `normalized_cost_margin`은 쓰지 않는다(NaN).
- 측정 실패(QR 추적, 바 블록 정합 실패)는 예외로 알린다. `(0, 0)`으로 숨기지 않는다.
- 초기화 때 모델 파일의 바 블록 중심과 `line_protocol.json`이 다르면 예외를 낸다.

## 검증 결과

이 맥(macOS, Apple clang, Homebrew OpenCV 5.0.0)에서 [tool/standalone](tool/standalone/CMakeLists.txt)으로 빌드해 돌렸다. 결과: [results/v2_validation_20261104](results/v2_validation_20261104/).

**정확도 (\|eY\| ≤ 0.045)**

| 평가 | v1 | v2 |
|---|---|---|
| 20261014 Y 단독 80장 (T = 0) | 80/80 (4-fold OOF, 최대 0.037) | **80/80** (4-fold OOF, 최대 0.029) |
| 20261014만 학습 → 다른 날, 남은 \|T\| ≤ 0.01 (12장) | 12/12, 최대 0.022 | 12/12, 최대 0.028 |
| 20261014만 학습 → 다른 날, 남은 \|T\| ≤ 0.03 (18장) | 12/18, 최대 0.117 | **18/18, 최대 0.037** |
| 20261014만 학습 → 다른 날, 남은 \|T\| ≤ 0.1 (48장) | 12/48, 최대 0.537 | **44/48, 최대 0.143** |
| 날짜 층화 5-fold 10분할, \|T\| ≤ 0.1 | (v1은 20261014만 학습) | 88.5~89.2% |
| 남은 T가 Y로 새는 기울기 dY/dT (20261029) | −1.76 | **−0.015** |

v1과 v2 모두 20261014만으로 학습했다. 20261020과 20261029는 두 버전 모두 학습에 쓰지 않은 날짜다. 배포 모델(`assets/control_v2_model.json`)의 출력은 위 표 "20261014만 학습" 행과 같다(575장 차이 최대 4e-8). 날짜 층화 5-fold 행은 모든 날짜를 섞어 학습했을 때의 참고값이다.

**같은 자세 반복의 흩어짐 (보조 기준, 20261014만 학습, \|T\| ≤ 0.1 묶음 16개)**

| | 전폭 중앙 | 전폭 최대 | 전폭 ≤ 0.045 |
|---|---|---|---|
| v1 | 0.012 | 0.042 | 16/16 |
| v2 | 0.021 | 0.128 | 13/16 |

v1은 흩어짐이 작지만 남은 T 때문에 크게 치우친다(예: 정답 Y 0.05, T 0.10 자세를 Y 0.56으로 읽음). v2는 치우침이 없지만 바 기울기 잡음이 더해져 흩어짐이 조금 크다. 운용 영역(남은 \|T\| ≤ 0.03) 묶음 6개는 v2도 모두 0.045 이하(최대 0.035)다. 0.045를 넘은 3묶음은 모두 T = 0.10 자세다.

**교란 강건성 ([A23](../20261104_103651_A23_control_v1v2_교란강건성/결과/보고서.md), 운용 영역 사진 39장, 같은 사진의 교란 전후 \|ΔY\| 최대)**

| 교란 | v1 | v2 |
|---|---|---|
| 카메라 세로 +0.5 px | 0.018 | **0.0065** |
| 밝기 ×0.8 | **1.85 (축 판정이 뒤집힘)** | 0.0057 |
| 흐림 σ1.2 | 0.25 | 0.0066 |
| 잡음 σ2 (실제의 약 2배) | 0.0003 | **0.044** |
| 잡음 σ4 | 0.0006 | 0.063 |
| 조명 기울기 ±10% | 0.0001 | 0.011 |

가로 이동(+0.25, +0.5 px)은 판이 실제로 움직인 것과 같아서, 두 버전 모두 Y가 그만큼(0.017, 0.035) 바뀌는 것이 정상이다.

v2는 밝기, 흐림, 카메라 이동에 훨씬 강하다. 대신 영상 잡음과 조명 기울기에는 v1보다 약하다. 바 기울기 측정이 잡음에 흔들려 남은 T 추정이 문턱을 넘나들기 때문이다.

**공개 API 확인**: 575장에서 `control()` 출력과 도구 계산 차이 최대 8.7e-10. 측정 실패 0. 처리 시간 중앙 21 ms, p95 24 ms, 최대 58 ms (이 맥, 1스레드).

## 학습과 재현

```bash
cmake -S tool/standalone -B build_v2 -DCMAKE_BUILD_TYPE=Release
cmake --build build_v2 -j
T=build_v2/control/control_v2_tool
$T measure  assets ../../../data/clean assets/training_list.csv results/v2_validation_20261104/features.csv
awk -F, 'NR==1 || $1 ~ /20261014/' results/v2_validation_20261104/features.csv > results/v2_validation_20261104/features_1014.csv
$T fit      assets results/v2_validation_20261104/features_1014.csv assets/control_v2_model.json 0.01
$T evaluate results/v2_validation_20261104/features.csv results/v2_validation_20261104 0.01 results/v2_validation_20261104/v1_control_outputs.csv
$T check    assets ../../../data/clean results/v2_validation_20261104/features.csv results/v2_validation_20261104/check_public_api.csv
```

`v1_control_outputs.csv`는 v1 전달 모델을 575장에 돌린 기존 기록(A10)에서 Y 출력만 옮긴 것이다. 팀 기준(Windows, MSVC v141, OpenCV 3.4.15) 빌드는 확인하지 못했다. 맥 빌드를 위해 SHA-256만 분기했다(Windows bcrypt, 그 밖 CommonCrypto).

## 한계
