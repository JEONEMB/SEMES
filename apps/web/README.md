# 웹 화면 (apps/web)

세메스 Y·T 비전 얼라인먼트의 웹 화면이다. 캔버스의 "서비스"와 "알고리즘 개발 및 평가"를 탭으로 나눈다.

## 탭 계획

| 탭 | 내용 | 상태 |
|---|---|---|
| 서비스 | 입력 사진 → 1차 joint → T 이동 → 2차 control → Y 이동 → 도착을 단계별로 보여 준다 | **구현 중** (시나리오 재생) |
| 디지털 트윈 | 장비와 로봇의 현재 자세를 가상 모델로 보여 준다 | 나중에 |
| 평가 | 후보 알고리즘을 같은 사진으로 채점하고 비교한다 | **구현** (결과 폴더 열기) |
| 보고서 | 실험 보고서를 주제별 블록으로 모아 본다 | **구현** (데이터 증강 연결, 알고리즘과 EDA는 준비 중) |

**서비스 + 디지털 트윈 한 화면 보기**를 고려한다. 서비스 탭의 사진 뷰어 옆(또는 아래)에 디지털 트윈 뷰를 함께 띄우고, 같은 단계 선택을 공유해 사진의 판단과 장비의 움직임을 동시에 본다. 화면 배치는 디지털 트윈 탭 설계 때 정한다.

## 서비스 탭 구성

| 영역 | 내용 |
|---|---|
| 상단 | 탭 4개, 입력 상태 |
| 모델 줄 | 사용 중인 1차·2차 모델과 채택 표시. 모델 변경은 준비 중 |
| 현재 사진 | QR 확대 / 전체 보기. QR 상자는 추정값이 두 축 모두 0.09 이내면 초록, 아니면 빨강. 왼쪽 위 추정값, 아래 이동 계획 |
| 추정값, Y-T 평면, 결론 | 현재 단계 숫자, 시뮬레이션 자세와 추정의 궤적, 진행·도착·중단 |
| 특징점 이동 성분 | control이 쓰는 QR 내부 고정 536점이 기준 사진에서 얼마나 움직였는지를 평행이동 X·Y(px), 회전(mrad), 크기 변화(ppm)로 나눈다. 굵은 화살표는 평행이동 방향, 파란 화살표는 회전과 크기 성분만 확대한 패턴. LK 추적 근사값(control의 GN 정밀화 생략)이며 잔차를 함께 표시 |
| 입력 | 카메라(미연결), 시나리오(6개), 시뮬레이션(증강 후) |
| 단계 | 단계별 추정·판단·이동. 누르면 그 단계로 이동 |

## 평가 탭

1. 채점: 저장소 루트에서 [tool/03_benchmark.cpp](../../tool/03_benchmark.cpp)로 만든 `benchmark.exe`를 실행한다. 평가 탭의 "새 평가 실행"에 사진 폴더 경로를 넣으면 이 명령을 만들어 준다

   ```powershell
   .\build\Release\benchmark.exe "data\clean\clean_20261020" "evals\20261028_1805_clean_20261020"
   ```

   - 사진 폴더 아래의 BMP/PNG를 모두 찾아 1차 joint와 2차 control로 추정한다 (`joint` 또는 `control`을 붙이면 하나만)
   - 정답: 가장 가까운 `_metadata/manifest.csv`의 파일명 명령값, 없으면 파일 이름의 `Y+0.10`, `T-0.20`, `center`
   - 모델: 기본은 selected_modules.cmake의 채택 모델. `--joint-assets`, `--control-assets`로 후보 지정
   - 결과 폴더는 새로 만들고 덮어쓰지 않는다: `predictions.csv`(사진별), `summary.json`(통과 수, 오차 평균·최대·p95, 시간 중앙값, 조건별 통과)
2. 보기: 평가 탭의 "결과 폴더 열기"로 결과 폴더(또는 `evals` 폴더 전체)를 고른다. 여러 개를 열면 첫 번째를 기준으로 비교한다

화면: 통과 수와 오차 요약, 결과 비교, 조건별 통과(기준 위치, Y만, T만, Y와 T 함께), 명령값과 추정값 산점도, 오차가 큰 사진 15장.

2026-10-28 `data/clean` 341장 결과: 1차 joint 341/341 (Y 오차 평균 0.0170, 최대 0.0744), 2차 control 302/341 (Y와 T 함께 18/57). 모두 개발에 쓴 사진이라 재대입 성적이다.

## 데이터

지금 화면은 `static/demo/data.js`를 읽는다. 이 파일은 [tools/make_demo.py](tools/make_demo.py)가 만든다.

- `data/scenarios/*/scenario.yml`의 사진에 `build/Release/main.exe`(joint / control)를 **실제로 실행한 결과**다
- 2단계 규칙: 1차에서 |T| > 0.09면 T만 이동, 이내면 2차로. 2차에서 두 축 0.09 이내면 도착, 아니면 Y만 이동. 최대 20회
- 첫 사진은 시나리오의 시작 사진. 이동 후 사진은 `data/clean` 전체에서 계산된 자세와 가장 가까운 사진(허용 Y 0.025, T 0.005, 사진 간격의 절반). 없으면 중단. `clean_20261014/center.bmp`는 모듈의 기준 사진(assets/center.bmp)과 같은 파일이라 후보에서 뺀다. 도착 장면은 다시 찍은 `clean_20261020/기준 위치/center1.bmp`
- QR 상자 위치는 joint와 같은 NCC 탐색으로 사진마다 찾는다
- 특징점 이동 성분: 사진마다 536점을 QR별 NCC 이동 + LK 15×15(σ 0.8 흐림)로 추적하고, 평행이동·회전·크기 4개 값으로 최소제곱 분해한다. Y와 T 모두 이미지에서는 주로 가로 평행이동으로 나타난다 (예: Y +0.20 → X +2.33px, T +0.20 → X +15.2px)
- 사진은 `static/demo/img/`의 축소 JPEG (전체 1600×900, QR 확대 영역 x1120 y620 1600×900)

다시 만들기 (저장소 루트, 빌드 후):

```powershell
python apps/web/tools/make_demo.py .
```

`make_demo.py`는 C++ 서비스 API가 생기기 전까지 쓰는 **임시 데모 생성기**다(Python + OpenCV). 서비스 흐름(include/pipeline.hpp)과 웹 서버가 생기면 화면은 같은 형태의 데이터를 API에서 받고, 이 스크립트와 `static/demo/`는 지운다.
