# ALIGN — Y·T 보정 시연 웹

Raspberry Pi에서 실행하는 로컬 웹이다. STM32가 모터를 제어하고 웹 서버는 카메라 영상,
시나리오 저장, 명령 전송, Trial 및 상태 표시를 담당한다. 개발 브랜치는 `JHC`다.

## 현재 구현

- 시연 화면 `/`: 실제 영상 영역 중앙 십자선, Trial 0~20, 현재 보정 명령값, Random/자동보정/정지.
- 관리자 `/admin`: 로그인, 중앙 기준 설정, 시나리오 생성·수정·복제·삭제, 재생 순서, JSON 백업.
- 관리자 시험: 시작 위치 이동 → 한 단계/전체 보정 → 결과 확인 → 검증 등록 → 시연 활성화.
- 서버 실행기: ACK 시 카운트·명령값 갱신, DONE 이후 다음 단계, 최대 20회, 중복 명령 방지.
- 보정 시점마다 중앙 좌표를 검사하고 조기 완료할 수 있다. 완료 후 마지막 명령값을 유지한다.
- 시나리오/중앙 기준 버전을 실행 시작 시 고정한다. 수정본은 새 실행에만 적용한다.
- SQLite 실행 기록, 재접속 상태 복원, 서버 재시작 시 실행 중단. 자동 재개하지 않는다.
- 모의 통신, USB 직접 연결(`/dev/ttyACM0`), 기존 `/dev/robot_stage` ioctl 어댑터. **실물 T축은 비활성**이다.
- 관리자에서 모드/연결 방식 선택, Y 원점 복귀, ±수동 이동, 정지, 보고 좌표/원점/리밋 조회.
- Picamera2 → 기본 4056×3040 5fps MJPEG. 저장된 캘리브레이션으로 렌즈 왜곡 보정(기본 켜짐).
- 관리자에서 해상도·왜곡 보정 켜기/끄기 선택 가능. 영상 파일은 저장하지 않는다.
- 한글 글꼴 포함. 실행 중 CDN/외부 인터넷 연결을 요구하지 않는다.

실제 중앙 정렬은 사전에 카메라로 확인한 좌표를 기준으로 한다. 이번 구현은 저장된 단계 재생이며
실시간 영상에서 보정량을 계산하는 알고리즘은 포함하지 않는다. STM32의 스텝 기반 보고 좌표가
허용 오차 내에 있는지 검사하므로, 기구 미끄러짐까지 영상으로 자동 검증하는 기능은 아니다.

## 설치와 실행

저장소 루트에서 실행한다. 이 파이에는 이미 가상환경과 의존성을 설치했다.
다른 파이에서 설치하려면 아래 명령을 사용한다. 시스템에 설치된 Picamera2를 사용하기 위해
`--system-site-packages`를 지정한다.

```bash
cd /home/pi/S15P31A507
python3 -m venv --system-site-packages demo_web/.venv
demo_web/.venv/bin/pip install -r demo_web/requirements.txt
```

최초 관리자 비밀번호를 터미널에서 설정한다. 10자 이상이며 입력 내용은 표시되지 않는다.
비밀번호 평문은 저장하지 않는다. 서버 실행 중에는 비밀번호 설정을 막는다.

```bash
demo_web/.venv/bin/python -m demo_web set-password
```

장치 없이 화면과 시나리오 흐름을 확인한다.

```bash
demo_web/.venv/bin/python -m demo_web serve --mode mock --camera off
```

- 시연: `http://127.0.0.1:8080/`
- 관리자: `http://127.0.0.1:8080/admin`
- 기본값은 모의 통신, 파이 내부 접속이다. 카메라는 최초 미사용이며 이후 관리자 저장 설정을 사용한다.
- `--camera off/picamera2`, `--camera-profile full/medium/preview`를 명시하면 해당 실행에서 저장된 카메라 설정보다 우선한다.
- 다른 노트북에서 접속하려면 명령 끝에 `--host 0.0.0.0`을 추가하고 `http://<파이 IP>:8080`으로 접속한다.
- `Ctrl+C`로 종료한다. 서버 종료 시 진행 중인 이동에 정지를 요청한다.
- 서버는 한 프로세스로 실행한다. 실행기를 복제하는 다중 worker 설정은 사용하지 않는다.

기본 DB에는 시나리오나 관리자 기본 비밀번호를 넣지 않는다.
관리자 로그인 후 `모의 예제 초안` → `초안 저장` → `시작 위치로 이동` → `전체 보정` →
결과 확인 체크 → `검증 완료로 등록` → `시연에 활성화` 순서로 시험할 수 있다.
이후 시연 화면에서 Random → 자동보정을 실행한다. 예제 숫자는 실물용 측정값이 아니다.

## 실제 카메라 / Y축 연결

카메라만 실제로 연결하고 모터 명령은 모의 실행할 수 있다.

```bash
demo_web/.venv/bin/python -m demo_web serve --mode mock --camera picamera2
```

관리자에서 Y축을 시험하는 순서:

1. 서버를 실행하고 `/admin`에 로그인한다.
2. **Y축 장치 연결 · 수동 시험**에서 `실물 Y축` → `USB 직접 연결` → `연결 적용`을 누른다.
   연결 적용은 GET_STATUS/GET_CONFIG 조회만 수행하며 장치를 움직이지 않는다.
3. `Y 원점`이 미설정이면 **Y 원점 복귀**를 누르고 완료를 기다린다. HOME은 Y축만 요청하며 최대 125초 기다린다.
4. 이동 거리 기본값은 **0.100 mm**다. `+Y 이동` 또는 `−Y 이동`으로 상대 이동을 시험한다.
   한 번에 0.001~1.000 mm만 허용하며 STM32 보고 리밋을 넘는 목표는 전송하지 않는다.
5. 정지가 필요하면 **■ 정지**를 누른다. ACK와 DONE 결과는 실행 로그에서 확인한다.

**Y 원점 복귀는 시연 화면(운영자 로그인)과 관리자 화면 모두에 있고, 모드와 관계없이 실제 STM32에서 실행한다.**
`sudo ./tools/rsctl home 1`과 같은 HOME(mask=1)이다. 실물 모드면 현재 연결을 쓰고, 모의 모드면
원점 복귀 동안만 `/dev/robot_stage`(커널 드라이버)를 열었다가 닫는다. 시나리오 실행은 모의 그대로다.
원점 복귀 중 정지 버튼은 실제 장치로 STOP을 보낸다. 웹 서버 사용자(pi)가 `/dev/robot_stage`를 열 수 있어야 하며,
기본 권한(root 0600)이면 "접근 권한이 없습니다" 오류가 난다. 기존 소유자·그룹·모드는 그대로 두고
pi 사용자에게만 ACL을 추가한다 (`/etc/udev/rules.d/99-robot-stage-acl.rules`):
`ACTION=="add|change", SUBSYSTEM=="misc", KERNEL=="robot_stage", RUN+="/usr/bin/setfacl -m u:pi:rw /dev/%k"`.
되돌리기는 규칙 파일 삭제 후 `sudo setfacl -x u:pi /dev/robot_stage`.
브라우저 시험(`browser_smoke.py`)은 실제 장치를 움직이지 않도록 원점 복귀 버튼을 누르지 않는다.

관리자의 **STM32 명령 · rsctl과 동일** 패널은 `rsctl`의 ping / status / config / home 1 / move-rel / move-abs /
speed / stop을 같은 단위(Y µm, T 0.001°, 속도 µm/s)로 실제 STM32에 보낸다(`POST /api/admin/stm32`).
ACK/NAK는 즉시, DONE은 완료 시 출력창에 표시한다. 원점·범위 검사는 rsctl처럼 STM32가 하며, T 값도 그대로 전달한다.
속도는 STM32 리셋 전까지 유지되고 웹 시나리오 실행에도 적용된다.

수동 시험은 카메라 연결 없이 가능하고 Trial을 증가시키지 않는다. 수동 실행 기록으로 시나리오를 검증할 수 없다.
실물 T 명령은 항상 0이며, 원점 복귀도 Y만 대상으로 한다. 원점 미설정 상태의 수동 이동은 막는다.
시나리오 준비/실행 중에는 수동 이동과 장치·카메라 설정 변경이 차단된다.
모드 선택은 서버 재시작 후 유지하지 않는다. 기본 모의 모드에서 다시 실물 연결을 선택한다.
처음부터 실물 통신으로 시작하려면 다음과 같이 실행한다. 이 명령도 자동 HOME/이동은 하지 않는다.

```bash
demo_web/.venv/bin/python -m demo_web serve --mode hardware --transport serial --camera picamera2
```

실물 자동 시연의 추가 조건:

- 실제 영상 수신 중이며 STM32가 Y 원점 설정 후 IDLE 상태여야 한다.
- 시작 T, 중앙 T, 모든 보정 T 명령과 STM32 보고 T 좌표는 0이어야 한다.
- 실물 모드에서 관리자 시험 및 영상 확인 후 검증·활성화해야 한다. 모의 검증으로는 실물 시연이 안 된다.

카메라 해상도는 관리자에서 선택하고 **카메라 적용 / 다시 연결**로 반영한다.

| 설정 | 웹 JPEG 해상도 | 목표 fps |
| --- | --- | --- |
| 원본 (기본) | 4056×3040 | 5 |
| 축소 | 2028×1520 | 10 |
| 미리보기 | 960×720 | 10 |

모든 설정은 IMX477 센서를 4056×3040, 12bit로 읽고 웹 영상만 선택 크기로 변환한다.
웹 JPEG는 RAW 12bit 파일이 아니다. **렌즈 왜곡 보정은 기본 켜짐**이다.
관리자의 `렌즈 왜곡 보정`에서 켜짐/꺼짐을 선택하고 `카메라 적용 / 다시 연결`로 원본과 비교할 수 있다.

- 데이터: `calibration/camera_calib.yml`. 팀의 2026-11-03 IMX477 + 6mm CS 렌즈 측정값이다.
- `카메라 프레임 → 왜곡 보정 → JPEG 압축 → 브라우저 공유` 순서다. JPEG를 다시 풀어 보정하지 않는다.
- 시작 시/영상 기하 변경 시 변환표를 만들고, 매 프레임 같은 표로 `remap`한다.
- 실제 프레임의 ScalerCrop과 출력 해상도로 내부 행렬을 조정한다. 미리보기의 미세한 크롭도 반영한다.
- 해상도와 출력 카메라 행렬을 유지한다. 광학 중심 재배치, SEMES용 크롭·3840×2160 변환은 하지 않는다.
- 보정 오류 시 미보정 영상을 보정된 것처럼 전송하지 않고 영상 연결 오류로 표시한다.
- RMS 재투영 오차 1.68px인 잠정값이다. 렌즈·초점 설정이 달라졌다면 다시 캘리브레이션해야 한다.

해상도 또는 왜곡 보정 설정 변경은 중앙 기준 버전을 올리고 모든 시나리오의 검증·활성화를 해제한다.
보정 파일 내용이 바뀌거나 이전 미보정 버전에서 업그레이드한 경우에도 시작 시 한 번 검증을 해제한다.
저장된 시작 위치와 보정 단계는 보존되며, 영상 중앙 기준을 확인한 뒤 다시 시험·검증·활성화한다.
카메라 사용 여부, 해상도, 보정 여부는 DB에 저장된다. 다른 카메라 프로그램과 동시에 실행하지 않는다.

2026-11-09 장치 확인: IMX477의 세 해상도에서 JPEG 크기와 프레임 수신을 확인했다.
왜곡 보정 적용 후 짧은 로컬 수신 시험에서는 원본 약 4.3fps, 축소/미리보기 약 10fps를 확인했다.
표의 FPS는 목표값이며 처리 부하·네트워크·브라우저 환경에 따라 실제 속도가 달라진다.

**영상 지연 (2026-11-09 측정):** 원본 JPEG는 장당 약 1.3MB라 파이 Wi-Fi 업로드(약 10~25Mbit/s)로는 장당 약 1초가 걸린다.
예전에는 waitress가 연결당 16MB까지 쌓아 두어 10초 넘게 밀렸다. 이제 송신 버퍼를 256KB(`--stream-buffer-kb`)로 줄여
밀린 프레임은 버리고 최신 프레임만 보낸다. 카메라 버퍼는 3개(6개에서 줄임)다. 10Mbit/s 환경 측정 결과는 다음과 같다.
원본은 촬영→JPEG 0.42초에 도착 지연 약 1.5초, **축소 2028×1520은 촬영→JPEG 0.17초에 도착 지연 0~0.4초**다.
발표 화면에는 축소 해상도를 권장한다. 각 프레임 파트에 `X-Frame-Time`(인코딩 완료 시각) 헤더가 있다.
USB 직접 통신으로 실제 STM32의 STATUS/CONFIG 응답을 확인했다. 당시 IDLE, Y 원점 미설정이었다.
**실제 HOME/모터 이동은 실행하지 않았으므로 관리자 버튼을 통한 기구 동작 확인은 남아 있다.**

기존 커널 드라이버를 사용하는 경우 관리자에서 `커널 드라이버`를 선택하거나 CLI에 `--transport driver`를 지정한다.
이 방식에는 `/dev/robot_stage`와 접근 권한이 필요하다. 직접 USB 방식에는 이 드라이버가 필요 없다.
현재 pi 사용자는 USB 장치에 접근 가능하다. USB 포트에 드라이버 line discipline이 연결되어 있으면 직접 방식은 거부한다.
드라이버 소스는 기존 `feat/lye/robot-stage-driver` 브랜치에 있으며, ioctl 구조체는 해당 브랜치의
`hardware/driver/include/uapi/robot_stage_ioctl.h`를 따른다. 드라이버·STM32 펌웨어·기존 빌드 산출물은 변경하지 않았다.

직접 연결 어댑터는 `STM32/robot_stage_protocol.md`의 CRC16/SEQ 규약을 따른다.
ACK 응답이 없으면 같은 SEQ로 최대 3회 재전송한다. 드라이버 방식에서는 커널이 이 처리를 담당한다.
ACK 재전송 중 조회가 섞이지 않도록 직렬화하고, DONE 대기 중에도 STOP은 별도로 전송할 수 있다.
DONE 시간 초과 시 상태 조회만 수행하며 이동 명령을 재전송하지 않는다.
직접 연결에서는 BOOT 이벤트를 받으면 오류로 중단하고 명시적으로 재연결해야 한다.
기존 드라이버의 EVENT 전달 기능은 미구현이므로 상태 조회 및 이동 전후 검사로 확인한다.
두 방식 모두 같은 사용자 장치 잠금을 사용한다. 웹 외의 제어 도구로 동시에 이동 명령을 보내면 안 된다.

## 데이터와 운영

- `demo_web/instance/demo.sqlite3`: 시나리오, 중앙 기준, 실행 기록, 비밀번호 해시, 세션 서명 키.
- `instance/`와 가상환경은 Git 제외. 데이터 폴더는 기본적으로 해당 사용자만 접근하도록 생성한다.
- `--data-dir <경로>`로 데이터 폴더를 분리할 수 있다.
- 기본 접속 대상은 파이 내부다. 운영자 로그인 세션을 가진 브라우저만 장치 조작이 가능하다.
- 관리자 세션은 서버에서 관리하며 로그아웃/재시작 후 무효화한다. 최대 8시간 유지한다.
- 공개 상태 API에는 현재 Trial과 보정 명령값만 반환한다. 시작 좌표·다음 명령·전체 시나리오는 관리자 API에만 있다.
- 로그인 및 변경 요청은 CSRF 토큰을 요구한다. HTML은 사용자 텍스트를 코드로 실행하지 않는다.
- 영상이 3초 이상 갱신되지 않으면 이전 화면을 숨기고 연결 중단으로 표시한다.
- 각 명령 직전과 안정화 대기 이후에도 카메라·제어기·원점 상태를 재확인한다.
  대기 중 연결이 끊기거나 원점이 사라지면 다음 이동과 성공 판정을 막는다.
- 브라우저를 닫으면 서버 실행은 계속된다. 정지 버튼으로 명시적으로 정지한다.
- 통신이 끊어지면 정지 명령도 전달되지 않을 수 있다. 이 경우 화면에 실제 장치 확인 필요 상태를 표시한다.
- 정지 전송 실패는 실행 기록에 남기며, 후속 취소 처리로 오류 표시를 덮어쓰지 않는다.
- 백업 JSON은 관리자만 내보낼 수 있다. 가져오기는 현재 중앙 기준으로 모든 시나리오를 검증한 뒤 새로운 초안으로 저장한다.
  백업의 중앙 기준과 검증 완료 상태는 자동 적용하지 않는다.
- 중앙 기준 설정 변경 시 전체 시나리오를 비활성화한다. 카메라/배율/원점/기구 배치가 바뀌면 기준을 갱신하고 재검증한다.

## 테스트

서버 및 실행기 테스트는 추가 테스트 패키지가 필요 없다.

```bash
demo_web/.venv/bin/python -m unittest discover -s demo_web/tests -v
```

실제 브라우저 동작 확인은 시스템 Chromium을 이용한다. 브라우저 설치 파일을 별도로 다운로드하지 않는다.

```bash
demo_web/.venv/bin/pip install -r demo_web/requirements-dev.txt
demo_web/.venv/bin/python demo_web/tests/browser_smoke.py
```

브라우저 시험은 임시 DB·임시 비밀번호·모의 장치를 사용하고 서버를 자동 종료한다.
기존 데이터와 실제 장치는 건드리지 않는다. 화면 캡처는 `demo_web/artifacts/`에 저장한다.

2026-11-09 검증 결과: 서버/실행기/카메라 설정/통신 어댑터 테스트 61개 통과.
보정 결과는 저장된 `calib_001_undistort.png`와 픽셀 차이가 0인 것을 확인했다.
추가 점검에서 안정화 중 카메라 단절·원점 유실·정지 전송 실패를 재현하고 수정했다.
Chromium에서 로그인 → 초안 저장 → 시작 이동 → 한 단계 → 전체 보정 → 검증 → 활성화 →
시연 실행 → 새로고침 → 모바일 화면 → 로그아웃 흐름을 통과했다.
1440×900 시연 화면의 세로 넘침과 390px 모바일 화면의 가로 넘침이 없음을 확인했다.
자동 이동 테스트는 모의 장치로 수행했다. 실제 카메라 수신과 STM32 상태 조회 결과는 위의 장치 확인 항목을 참고한다.

## 파일 구조

| 파일 | 역할 |
| --- | --- |
| `app.py` | HTTP API, 관리자 인증, CSRF, SSE, 스트림 라우팅 |
| `controller.py` | 단일 실행기, Trial, ACK/DONE, 정지 및 완료 판정 |
| `stage.py` | 모의 장치와 기존 커널 드라이버 어댑터 |
| `serial_stage.py` | 직접 USB 프로토콜, CRC/SEQ, ACK/DONE 및 STOP |
| `camera.py` | 단일 카메라, 압축 전 보정 및 공유 프레임 |
| `rectification.py`, `calibration/` | 캘리브레이션 데이터, 크롭·해상도 반영 및 보정 변환표 |
| `store.py` | SQLite, 입력 검증, 버전, 시험/시연 이력 |
| `__main__.py` | 비밀번호 설정, 서버 시작, 프로세스 잠금 및 종료 |
| `templates/`, `static/` | 시연/관리자/로그인 화면 |

웹 프레임워크 구성은 [Flask 설치 문서](https://flask.palletsprojects.com/en/stable/installation/)와
[보안 문서](https://flask.palletsprojects.com/en/stable/web-security/)를 참고했다.
포함한 글꼴은 [Pretendard v1.3.9](https://github.com/orioncactus/pretendard/tree/v1.3.9)이며,
배포 라이선스는 `static/fonts/OFL.txt`에 함께 포함했다.
